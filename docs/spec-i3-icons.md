# [UX-I3] Спека: набор иконок Mini App в стилистике Amber Glass

Тикеты: #25 [UX-I3] (Idea), #97 [UX-T10] (Task). Направление: UX.
Макет: `docs/mockups/ux-i3-icons.html`. Источник стиля: `docs/mockups/concept-hybrid.html`,
палитра и компоненты — `web/style.css` (Amber Glass, [DSN-S2]).

---

## 1. Цель и пользовательская проблема

Mini App унаследовал набор иконок от концепта 2 (Amber Drive). В макете-гибриде это
помечено честно: «Иконки временно из концепта 2, переделка — тикет [UX-I3] #25».
Владельцу набор не нравится, и есть объективные причины:

- **Пиктограммы-«человечки»** (28 шт.) изображают упражнение фигуркой человека.
  В реальных размерах UI (18–22 px) голова — точка, конечности сливаются, силуэты
  разных упражнений неразличимы, ориентация у каждого своя. Набор «наскальный».
- Гибрид Amber Glass построен на **геометрии** (круги мышц, залитые CTA, стекло) —
  суетливые фигурки выбиваются из языка.
- Есть **эмодзи-заглушки** там, где иконка нужна по смыслу (🔥 ккал, 🏆 рекорды,
  🕐 длительность) — набор неполный.

Цель: единый набор inline-SVG в духе Amber Glass — геометрические силуэты вместо
фигурок, ровный оптический вес, полнота набора.

## 2. Инвентаризация ICONS (web/catalog.js) и точки использования

Все иконки объявлены в `web/catalog.js` через хелпер `_s(inner)` — обёртка
`<svg viewBox="0 0 24 24" fill="none" stroke="currentColor" stroke-width="1.7"
stroke-linecap="round" stroke-linejoin="round">`. Ключи читаются строковыми
константами в `web/app.js` и в `CATS`/`CATALOG` (тот же файл).

| Группа | Ключи | Где используются |
|---|---|---|
| Док-панель (`.nav .nico`, 20px) | `timer` (История), `chart` (Статистика), `pilates` (Техника), `user` (Профиль) | `navHtml()`; FAB — `plus` (24px, CSS поднимает толщину до 2.2) |
| Топбар (`.tb-user`) | `user` | кнопка профиля справа (`topbarHtml()`) |
| Шапка карточки упражнения (`.exhead .ico`, 32–40px) | любая `c.i` из CATALOG + `custom` (fallback) | строки истории (`expill`), карточки каталога/техники (`excard`), шапка карточки в модалке |
| Чипы категорий (`.chip` + `.ico`) | иконки `CATS.muscle/type/block/coll` | пикер упражнения, фильтры каталога и техники |
| Круги мышц (`.mgc`, 38–42px, фон `--c-*`) | `chest, row, lateral, curl, squat, glute, core` (+ `custom`) | статистика/профиль: `MG_STYLE` + `ICONS[g.icon]` |
| Действия карточки (`.barebtn`, 18px) | `repeat, save, timer, trash` | «Повторить», «В шаблоны», «Время», «Удалить» |
| Кнопки тренировки (`.btn .icbtn`) | `plus, cross, check, trash` | «Упражнение», «Отменить», «Завершить», «Удалить тренировку» |
| Резерв (не используются в UI) | `pencil, cup, tag` | вызовов в app.js нет; ключи сохраняем |

Эмодзи-заглушки вне ICONS (кандидаты на новые ключи): `🔥` ккал (wpill, restbar,
`mgc-fire`), `🏆` рекорды (prtag, статистика, тосты PR), `🕐` длительность (wpill),
`⏱` таймер отдыха — по смыслу совпадает с `timer`.

## 3. Диагноз текущего набора (по группам)

1. **«Человечки» (28 шт.)** — голова-точка r≈1.7 при штрихе 1.7 сливается в глазок;
   `curl` ≈ `triceps` ≈ `legext` неразличимы; ориентация и плотность у каждого свои;
   в круге `.mgc` силуэт не читается. Главная причина недовольства.
2. **Инвентарь** (`smith, cable, machine`) — тяжёлые прямоугольные рамки разной
   плотности; `barbell` — несимметричные блины; `pullbar` дублирует мотив `pullup`.
3. **UI-набор** — ближе к норме, но: `chart` с перекошенными колоннами, `cup` без
   ножки, `timer` без штока (плохо читается в 20px), `warmup` — «солнце»
   (семантически мимо: разогрев ≠ солнце).
4. **Навигация**: вкладка «История» использует секундомер (`timer`) — конфликтует
   с таймером отдыха. Имя ключа менять нельзя → добавлен ключ `history` (§7).

## 4. Правила нового набора (дизайн-система иконок)

- Сетка 24×24, активное поле ~20×20 (отступ ≥2 от края). `fill="none"`,
  `stroke="currentColor"`, `stroke-width="1.7"`, round caps/joins — как в `_s()`.
- **Мета-язык вместо человечков**: мышцы — геометрические силуэты (грудь =
  двуарочная клетка, спина = клин, пресс = капсула с полосами); упражнения-механика —
  вектор движения или снаряд в разрезе; кардио — траектория; инвентарь — снаряд «в лоб».
- Максимум ~4–5 элементов на иконку; окружности r ≥ 2; симметрия, центр масс ≈ (12,12).
- Читаемость силуэтом обязательна в 22px (`.mgc`) и в 18px (`.barebtn`) —
  проверено размерной линейкой в макете.
- Двойная кодировка допустима (ключ = мышца + тип), форма выбирается по более
  частому использованию (`row` = спина, не «тяга в наклоне»).

## 8. Edge cases и совместимость

- **Имена ключей не менялись** — все `ICONS[...]`/`ico(...)` в app.js и ссылки
  `c.i`/`icon:` в catalog.js работают без правок; дифф — только значения объекта.
- **Fallback**: `ICONS[key] || ICONS.custom` и `ico()` — ключ `custom` сохранён;
  неизвестные ключи по-прежнему дают «круг с плюсом».
- **Толщина FAB**: CSS `.nav .nfab svg { stroke-width: 2.2 }` остаётся — геометрия
  `plus` симметричная, утолщение не ломает форму.
- **Светлая тема**: цвет — `currentColor`, работает на обоих темах без правок CSS.
- **Читаемость 18px** (`.barebtn`): самые мелкие детали набора — `cup`-ручки,
  `timer`-корона — проверены на размерной линейке в макете; при сомнениях coder
  не должен «упрощать» path'ы самостоятельно.
- **Данные**: набор иконок в данные пользователей не пишется (только имена
  ключей в `CATS`/`CATALOG`), контрактный тест не затрагивается.

## 9. Что НЕ делаем и почему

- **Не меняем имена ключей** — сломало бы `c.i` в CATALOG (60+ записей) и `CATS`.
- **Не рисуем «человечков» заново** — это и есть исходная проблема; в 18–22px
  анатомия не читается в принципе.
- **Не переходим на filled-иконки** — стиль Amber Glass линейный (stroke 1.7,
  currentColor); заливка конфликтует с цветными кругами мышц.
- **Не меняем `_s()`/CSS** (`stroke-width`, размеры) — сетка 24×24 и толщина 1.7
  подтверждены; правки коснутся только path'ов.
- **Не заменяем эмодзи в текстах** (toasts, заголовки «Пока пусто 💪») — это
  тон беседы/характер, а не системные элементы; замена — отдельное решение.
- **Не трогаем `web/catalog.js` из этой задачи** — воплощение делает coder по §6.
