## 1. Цель и пользовательская проблема

Продукт сегодня — **строго приватный** дневник тренировок: данные одного пользователя лежат
в его `chat_<id>.json`, сервер их никому не показывает, социального слоя нет вообще.

Проблемы владельца (#111, #52–54):

1. **Пользователь-новичок** не знает, как выполнять технику безопасно. Инфо-кнопка в «Технике»
   (#52) честно говорит «носит рекомендательный характер» — но не даёт следующего шага:
   *где найти того, кто покажет?* Особенно при ограничениях здоровья (грыжа, больные колени),
   где самодеятельность опасна.
2. **Тренер** (в том числе из числа пользователей продукта) не имеет инструмента: рассказать,
   что он умеет (реабилитация, похудение, масса), где принимает, когда доступен — и вести
   подопечных.
3. **Связка «тренер—подопечный»** (#54): тренеру нужно видеть цели и прогресс подопечного,
   чтобы вести его осмысленно, а не вслепую. При этом подопечный остаётся хозяином своих
   данных: дневник приватный по природе продукта, и выдача данных тренеру — только по явному,
   гранулярному согласию.
4. **Единомышленники** (#111): людям нужен чат/сообщество для мотивации — но внутренний чат
   в продукте несоразмерно дорог (модерация, хранение, антиспам).

**Решение** — вертикаль «Тренер»: опциональный социальный слой поверх приватного дневника.
Подопечный ищет тренера по месту и специализации, отправляет заявку (или вводит код
приглашения), тренер одобряет. После связки тренер видит ровно то, что подопечный разрешил
переключателями-грантами. Сообщество — Telegram-группа, не внутренний чат.

## 2. Контекст и рамка

| Факт | Следствие для дизайна |
|---|---|
| Пользователей ~6, все «свои» | Премодерация вручную владельцем реальна; никакой автомодерации, рейтингов и антифрода на старте |
| Бэкенд — чистая Java 17 без зависимостей, данные в `data/*.json` | Соцданные — тоже JSON-файл, без БД. SQLite и миграции — отдельная тема (направление SQL в бэклоге) |
| Данные сейчас строго «один файл = один чат» | Публичные карточки и связи **не могут** жить в `chat_*.json` (см. §4) — нужен отдельный серверный файл |
| Продукт приватный по ДНК | Соцслой — **опционален и по умолчанию выключен**; ничего публичного, пока пользователь сам не включил |
| Владелец — единственный администратор | Верификация тренеров, жалобы, разблокировки — вручную владельцем (интерфейс: админ-команды бота) |
| WebServer проверяет `initData` (HMAC) | Все соц-API доступны только авторизованному пользователю приложения; анонимного «публичного каталога» нет |
| Уже есть скрытый таб «Тренер» (плейсхолдер «🧑‍🏫 Персональный тренер»: программы/разборы/советы) | **Конфликт имён**: это контент-фича, а не соцсеть. Предлагается переименовать плейсхолдер в «Советы и программы» (вопрос владельцу №14), а слово «Тренер» отдать соцвертикали |

**Ключевой поворот**: это первый выход продукта за пределы «данные одного человека».
Каждое решение ниже пронизано этим: что публично, что по согласию, что вообще не делаем.

## 3. Роли и глоссарий

- **Подопечный** — пользователь с дневником; может искать тренера и отправлять заявки.
- **Тренер** — пользователь, включивший режим «Я тренер» и подтверждённый владельцем.
  Один пользователь может быть и тренером, и подопечным одновременно (тренер тренера —
  допустимо, ограничений не вводим).
- **Карточка тренера** — публичный профиль тренера (виден в поиске после верификации).
- **Связка** — установленное отношение «тренер ↔ подопечный» (одобренная заявка или код).
- **Грант** — переключатель согласия подопечного: какой раздел его данных видит тренер.
- **Карточка подопечного** — представление подопечного в приложении тренера (видно только
  тренеру, и только то, что разрешено грантами).
- **Код приглашения** — 6-символьный код тренера для оффлайн-привязки без заявки.

## 4. Архитектура данных (записка для кодера — в этой задаче код не пишется)

### 4.1 Новое хранилище: `data/social.json` (единый файл)

Соцданные **нельзя** класть в `chat_<id>.json`:

- файл одного пользователя не должен содержать чужие данные (публичные карточки, связи) —
  это и утечка, и поломка модели «бэкап/восстановление одного чата»;
- `GymData`/`GymContractTest` — контракт приватных данных, его не трогаем.

Предлагаемая структура (черновик, финализирует кодер):

```json
{
  "rev": 1,
  "trainers": {
    "<userId>": {
      "displayName": "Игорь Соколов",
      "bio": "...", "specs": ["rehab","mass"], "city": "Минск",
      "gyms": "«Атлет», «Олимп»", "years": 6,
      "achievements": ["..."], "education": ["..."],
      "schedule": ["Пн–Пт 07:00–21:00"], "useTgAvatar": true,
      "status": "verified", "statusNote": "",
      "cap": 5, "updatedAt": "2026-11-13T10:00:00"
    }
  },
  "links": [
    { "trainer": "<userId>", "student": "<userId>", "since": "2026-11-13",
      "grants": { "progress": true, "goals": false, "body": false, "health": false },
      "source": "apply|invite" }
  ],
  "invites": [ { "trainer": "<userId>", "code": "K7RM2X", "usesLeft": 1 } ],
  "healthNotes": { "<userId>": { "text": "грыжа L5, осторожно с наклонами", "updated": "..." } },
  "reports": [ { "by": "<userId>", "about": "<userId>", "at": "...", "text": "..." } ]
}
```

Правила:

- **Ключ участника — Telegram user id** (`from.id`), не `chat_id` (личный чат с ботом
  совпадает с user id, но семантически правильнее id пользователя).
- **Бэкапы**: ротация `Storage` (20 версий) распространить на `social.json` — то же правило
  «бэкап ПЕРЕД перезаписью» (см. TODO.md «Восстановление тренировки»).
- **Право на забвение**: при удалении данных пользователем (`/deletedata`) — удалить его
  карточку тренера, все связи с его участием, гранты, заметку о здоровье; у контрагентов
  связка исчезает без следов. Это обязательно (152-ФЗ, см. §13).
- **Аватар** — только ссылка `photo_url` из Telegram (initData), файлы на сервер не
  загружаются (WebServer приёма файлов не имеет; загрузка = отдельная задача с модерацией).

### 4.2 API Mini App (черновик)

Все эндпоинты — с проверкой `initData`, как существующие `/api/*`:

| Эндпоинт | Метод | Назначение |
|---|---|---|
| `/api/social/me` | GET | моя тренер-карточка, мои связи (как тренер/как подопечный), гранты |
| `/api/social/card` | POST | сохранить/обновить карточку (→ статус «на проверке»), вкл/выкл режим |
| `/api/social/search` | GET | `?city=&specs=` — только `verified`-карточки, только для авторизованных |
| `/api/social/apply` | POST | заявка в подопечные (+ комментарий) |
| `/api/social/link` | POST | одобрить/отклонить заявку, разорвать связь |
| `/api/social/invite` | POST/GET | сгенерировать/отозвать код; применить код со стороны подопечного |
| `/api/social/grants` | POST | изменить гранты связки |
| `/api/social/health` | POST | сохранить приватную заметку «Здоровье и ограничения» |
| `/api/social/report` | POST | жалоба (дублируется владельцу через существующий feedback-канал) |

Уведомления бот шлёт по уже существующему `TelegramApi` (см. §14). Push-канала «в приложение»
нет и не нужен: приложение тянет `/api/social/me` при открытии.

### 4.3 Чего не проектируем архитектурно

БД/SQLite, полнотекстовый поиск, кеши, очередь уведомлений, вебхуки, real-time.
При 6 пользователях `social.json` в оперативной памяти процесса + атомарная перезапись
(как сейчас `Storage`) — достаточно.

## 5. Режим «Я тренер»

### 5.1 Включение

- **Место**: вкладка «Профиль» → новая карточка «🧑‍🏫 Тренер» (после «⭐ Любимые упражнения»).
  Содержимое карточки зависит от состояния:
  - **Выключен**: тогл «Я тренер» (компонент `.switch` [UX-S4]) в OFF + подпись «Включите,
    чтобы создать публичную карточку тренера» + строки «Найти тренера», «Сообщество».
  - **Включён**: вместо тогла — компактный статус карточки (⏳ На проверке / ✔ Подтверждён /
    ✖ Отклонена + причина) + кнопки «Карточка тренера», «Мои подопечные».
- Тогл OFF→ON раскрывает форму карточки прямо в карточке «Тренер» (аккордеон, без отдельного
  экрана — форма и так длинная, отдельный подэкран со «←» тоже допустим; рекомендация:
  разворачивать инлайн, как «Дата рождения» в Профиле).
- **Тонкий момент**: включение тогла = согласие на публикацию данных карточки (см. §13).
  Под формой — строка: «Карточка видна в поиске только после подтверждения владельцем».

### 5.2 Форма карточки тренера

| Поле | Тип | Лимит | Примечание |
|---|---|---|---|
| Отображаемое имя | текст | 2–40 | дефолт — имя из Telegram; можно псевдоним |
| О себе | textarea | до 300 | чем занимаетесь, подход к работе |
| Специализации | мультивыбор-чипы | до 3 из фиксированного набора | набор ниже — поиск и модерация проще |
| Город | текст | до 40 | одна строка; геокодинга нет |
| Зал(ы) | текст | до 80 | «„Атлет“, „Олимп“» |
| Стаж, лет | число | 0–60 | |
| Достижения | список строк | до 5 × 80 | «КМС по пауэрлифтингу, 2019» |
| Образование и курсы | список строк | до 5 × 80 | «РГУФК, 2015»; переподготовка, курсы |
| Расписание | список строк | до 3 × 60 | «Пн–Пт 07:00–21:00» — текстом, НЕ слоты (слоты = фаза 2) |
| Лимит подопечных | чипы | 3 / 5 / 10 / 20 | по умолчанию 5; при наборе — «Набор закрыт» (§6.4) |
| Аватар Telegram | чекбокс | — | «Показывать мой аватар Telegram» (по умолчанию ВКЛ; OFF → кружок с инициалами) |

**Фиксированный набор специализаций** (идентификаторы стабильные, названия — UI):

| id | Название чипа | Покрывает пожелания владельца |
|---|---|---|
| `rehab` | Реабилитация | грыжа, операции, больные колени |
| `loss` | Похудение | «хочу похудеть» |
| `mass` | Набор массы | «набрать массу» |
| `comp` | Соревнования | «к Мистер Олимпия» |
| `power` | Сила | пауэрлифтинг, рекорды |
| `begin` | Новички и база | первые шаги в зале |
| `mobility` | Растяжка и мобильность | гибкость, осанка |
| `group` | Групповые тренировки | будущие групповые занятия |

Кнопки формы: **«💾 Сохранить»** (сохраняет черновик) и **«📤 Отправить на проверку»**
(переводит в `pending`, уведомляет владельца — см. §14.5). Существует и черновик:
сохранить можно без публикации.

### 5.3 Верификация (предложение)

- **Кто подтверждает**: владелец, **вручную**, на старте — единственный оператор и модератор.
  Документы НЕ проверяем (см. §18); проверка = владелец смотрит карточку и решает.
- **Статусы**: `draft` → `pending` → `verified` / `rejected` (с причиной, видимой тренеру).
- **Публикация в поиске** — только `verified`. «На проверке» и «Отклонена» в поиске не видны.
- **Правки карточки**: любое изменение содержимого возвращает статус в `pending`
  (повторная проверка). При 6 пользователях это ок; позже можно ослабить (расписание/лимит —
  без ревью). Дисциплинирует и защищает от подмены содержимого после подтверждения.
- **Интерфейс владельца** — админ-команды бота (§14.5): `/trainer_pending`,
  `/trainer_ok <userId>`, `/trainer_no <userId> причина`.
- Позже (не в MVP): самозанятые/сертификаты — только как поля «Образование», без документной
  верификации.

### 5.4 Выключение режима

Тогл ON→OFF (или «Скрыть карточку»): карточка исчезает из поиска немедленно. Связи с
подопечными **сохраняются** (подопечные не выбрасываются молча), но новые заявки невозможны.
Полное завершение работы тренера — через разрыв каждой связи (§7.5).

## 6. Поиск тренера

### 6.1 Точки входа

1. **Техника** (#52): инфо-плашка «Техника выполнения носит рекомендательный характер…»
   получает кнопку-действие **«🧑‍🏫 Найти тренера»** — прямой сценарий «посмотрел технику →
   понял, что нужен тренер».
2. **Профиль → карточка «🧑‍🏫 Тренер»** → строка «Найти тренера».
3. **Бот**: команда `/trainer` (текст-статус + webapp-кнопка «📱 Открыть раздел „Тренер“»).

### 6.2 Экран поиска

- Поле **«Город или зал»** (один input — ищем вхождением в `city` или `gyms`, регистр
  не важен; никаких гео-карт).
- Чипы-фильтры **специализаций** (те же 8; выбранная — совпадение по любой, OR).
- Результаты — карточки-превью: аватар (или инициалы), имя, до 3 чипов специализаций,
  «Город · Зал», «Стаж N лет». Тап → детальная карточка.
- **В результатах только `verified`-карточки** — отдельного чекбокса «только подтверждённые»
  не нужно.
- Сортировка: по дате подтверждения (свежие сверху). Никакого «рейтинга» (§18).

### 6.3 Карточка тренера (детально)

- Шапка: аватар, имя + бейдж «✔ Подтверждён», город.
- Био, чипы специализаций, зал(ы), расписание, стаж, достижения, образование.
- **Контакта Telegram в публичной карточке НЕТ** — раскрытие контакта только после связки
  (вопрос владельцу №5).
- Кнопка **«🤝 Стать подопечным»** (prime) → модалка заявки: textarea «Комментарий»
  (до 200) с плейсхолдером «Расскажите о себе: цель, опыт, ограничения здоровья…»
  («предложить дату и время» в MVP — текстом в этом комментарии; структурный пикер — фаза 2,
  см. §10.4). Кнопка модалки «📤 Отправить заявку».
- Состояния кнопки: «Заявка отправлена ⏳» (disabled, ждём тренера) / «Набор закрыт»
  (disabled, лимит связок) / обычная.
- Тонкая строка-действие «⚠️ Пожаловаться» → deep-link обратной связи (§13.4).

### 6.4 Эдж-кейсы поиска

| Случай | Поведение |
|---|---|
| Ничего не найдено | «Ничего не нашлось. Попробуйте другой город или снимите фильтры» + кнопка «Сбросить» |
| Нет подтверждённых тренеров вовсе (пустой каталог) | Пустое состояние с пояснением «Пока нет подтверждённых тренеров» — важно для первых дней |
| Ошибка сети/сервера | Существующий тост `.toast.err`, результаты не рендерятся |
| Свою же карточку в поиске | Видно с бейджем «Это Вы» — кнопка заявки заменена на «Редактировать карточку» |
| Тренер уже связан с пользователем | В карточке — «Уже Ваш тренер ✓» вместо кнопки заявки |

## 7. Связка тренер ↔ подопечный

### 7.1 Заявка (онлайн-механика)

1. Подопечный: «Стать подопечным» → комментарий → «Отправить заявку».
2. Тренеру: push-сообщение от бота (§14.1) с кнопками «✅ Принять» / «✖️ Отклонить»
   (callback) и «📱 Открыть приложение». Заявки также видны в приложении тренера (§9.1).
3. Тренер принимает → связка создана (гранты все OFF — ноль данных не согласилось),
   подопечному пуш «заявка принята» (§14.1). Отклоняет → подопечному мягкий пуш без причины,
   заявка исчезает. Причина отклонения тренеру не требуется (избегаем конфликтов).
4. Дубли: одна активная заявка на пару пользователей; повторный тап невозможен (§6.3).
5. Заявка «висит» 14 дней, затем сама исчезает (уведомление никому не шлём — тихо).

### 7.2 Код приглашения (оффлайн-механика)

- Тренер (в приложении, раздел «Мои подопечные»): «Код приглашения» → показ кода
  (**6 символов**, алфавит без похожих `ABCDEFGHJKLMNPRTUVWXY23456789`, одноразовый)
  + кнопка «Новый код» (старый гасится).
- Подопечный: Профиль → «Тренер» → **«У меня есть код»** → input → «Применить».
- Код = выраженное тренером согласие заранее: **связка создаётся сразу**, без стадии заявки;
  оба получают уведомления (§14.1). Гранты — все OFF.
- Код не имеет срока, но одноразовый и заменяемый — риск перехвата минимален и
  регулируется отзывом.

### 7.3 Что видит тренер после связки

Только данные, разрешённые грантами подопечного (§8) — по умолчанию: **имя и аватар
Telegram и всё** (никакого прогресса/целей/здоровья). Карточка подопечного без грантов
выглядит «закрытой» с понятными замками (§9.3) — это мотивирует подопечного открыться,
но не принуждает.

### 7.4 Несколько подопечных

Тренер ведёт сколько подопечных, влезает в лимит карточки (§5.2). Список — §9.1.
Подопечный может иметь **одного активного тренера** в MVP (проще модель и UI; вопрос
владельцу №3 — «второй тренер» явно не запрошен).

### 7.5 Разрыв связи

- Подопечный: «Разорвать связь» (с подтверждением-модалкой) — гранты сбрасываются,
  тренер теряет доступ немедленно; уведомление тренеру не шлём (мягко), в списке подопечный
  просто исчезает.
- Тренер: «Убрать подопечного» (подтверждение) — то же зеркально.
- Разрыв не блокирует повторную связку позже (новая заявка/код).

## 8. Согласие подопечного: гранулярные гранты

### 8.1 Экран «Что видит тренер» (в Профиле подопечного)

Блок «Мой тренер» в карточке «🧑‍🏫 Тренер» (Профиль) → связка установлена → раскрывается:

| Грант | Что открывает тренеру | Источник данных | Дефолт |
|---|---|---|---|
| **Прогресс тренировок** | Активность: тренировки за 30 дней, суммарный объём, последний рекорд | существующая статистика GymData | **ВКЛ** (рекомендация: это суть связки; см. вопрос №4) |
| **Цели** | Цели подопечного ([GOA-I1]): название, срок, % прогресса | Goals (появятся с GOA-I1; до него — пустой блок) | OFF |
| **Вес и рост** | Текущие значения профиля (вес, рост) | `profile` | OFF |
| **Здоровье и ограничения** | Приватная заметка подопечного свободным текстом (до 300) | `healthNotes` (новое поле) | OFF |

Каждая строка — тогл `.switch` + подпись «что именно увидит тренер» (не абстрактное
«данные», а конкретика: «Тренировки за 30 дней и последний рекорд»).

Дополнительно в этом блоке:

- строка-инфо «Изменения применяются сразу — тренер видит актуальное состояние»;
- **«Здоровье и ограничения»** OFF→ON впервые — предлагает поле ввода заметки
  («Грыжа, больные колени, что учитывать при нагрузках»). Заметка приватна вдвойне:
  хранится отдельно и показывается только тренеру с грантом.
- кнопка «Разорвать связь» (danger-текст, sec).

### 8.2 Правила грантов

- Изменение гранта вступает немедленно; уведомлений тренеру НЕ шлём (спам-риск; тренер и так
  видит актуальное состояние карточки).
- Гранты живут в связке (`links[].grants`) и умирают с ней.
- «Открыть всё» / «Закрыть всё» — двумя ссылками над тоглами (быстрое действие).

### 8.3 Чего гранты НЕ открывают (границы — явно)

- Сам текст тренировок (упражнения/подходы) — тренер видит **агрегаты**, не журнал.
  Журнал — слишком глубокая приватность; агрегатов достаточно для ведения (вопрос №4).
- Питание (🥤) — никогда.
- Калории/BMR — никогда (вычислимы из веса — грант «Вес и рост» уже отдает основу;
  считаем эту комбинацию приемлемой, отмечаем в политике).
- История веса тела — в MVP нет данных (вес тела хранится одним значением; Δ-динамика —
  фаза 2 вместе с историей веса, см. §16).

## 9. Карточка подопечного у тренера

### 9.1 Раздел «Мои подопечные» (режим тренера)

Вход: Профиль → «Тренер» → «Мои подопечные» (или скрытый таб «Тренер», переименованный
в соц-хаб — вопрос №14). Состав экрана:

- **Заявки (N)**: карточки заявок: аватар, имя, комментарий, дата; кнопки «✅ Принять» /
  «✖️ Отклонить». Пусто → «Новых заявок нет».
- **Подопечные (M / лимит)**: строки: аватар, имя, чипы видимости «Прогресс · Цели»
  (только включённые гранты; ни одного — «Данные закрыты»), «→» к карточке.
- Кнопка «Код приглашения» (показ/генерация, §7.2).

### 9.2 Карточка подопечного (детально)

Верх: аватар, имя, «в подопечных с 13.11», строка грантов-чипов, действие «Убрать
подопечного» (§7.5). Ниже — блоки по грантам:

| Блок | При гранте ON | При гранте OFF |
|---|---|---|
| 🎯 Цели | список целей с прогресс-барами (стиль `.rec-bar`) | 🔒 «Скрыто: подопечный не открыл цели» |
| 📈 Активность | «4 тренировки за 30 дней · объём 21 т · последний рекорд: жим 82.5 кг (08.11)» | 🔒 «Скрыто: нет доступа к прогрессу» |
| ⚖️ Вес и рост | «85 кг · 180 см» | 🔒 «Скрыто» |
| 🩺 Здоровье и ограничения | текст заметки (жёлтая рамка `.hint` — «важно учитывать») | 🔒 «Скрыто» |

Каждый закрытый блок — кнопка-строка «Попросить открыть» → шлёт подопечному мягкое
сообщение от бота: «Тренер Игорь С. просит доступ к „Здоровье и ограничения“. Решение
за Вами: Профиль → Тренер → Что видит тренер». Не чаще 1 раза в 7 дней на грант
(антиспам), грант всё равно решает подопечный.

### 9.3 Ограничения MVP

- Карточка **read-only** для тренера: ставить цели, оставлять комментарии, назначать
  программы (#54 в полном объёме) — фаза 2 (см. §16). В MVP тренер «смотрит и общается
  вживую/в Telegram».
- Экспорт/скачивание данных подопечного не предусмотрены UI. Технически скриншот никто
  не отменял — честно пишем в политике (§13).

## 10. Групповые занятия (MVP-набросок, вне итерации S1)

Концепт для полноты картины (#111); в первую итерацию НЕ берём (§16) — приоритет связке.

### 10.1 Сущность

`Class { id, trainerId, title, place, start (ISO), durMin, cap, participants[] }` —
в `social.json` (§4.1). Занятие принадлежит `verified`-тренеру.

### 10.2 Создание (тренер)

Раздел «Мои подопечные» → «Групповые занятия» → «＋ Создать»: название (до 60), место
(до 80), дата и время (нативный `datetime-local`), длительность чипами (45/60/90 мин),
лимит мест (5–30), описание (до 300). Занятие публикуется сразу (тренер уже верифицирован).

### 10.3 Запись участников

- В карточке тренера — секция «🗓 Групповые занятия»: карточка занятия: название, дата-время,
  место, чип «N / лимит мест», кнопка «Записаться» / «Вы записаны ✓ (Отменить)».
- Лимит исчерпан → «Мест нет» (disabled) + «⚡ Записаться в лист ожидания» — фаза 2.
- Тренер видит список записавшихся (имена), может отменить занятие → пуш всем записанным
  (§14.3).
- Напоминания о занятии — фаза 2 (пуш за 2 часа; требует планировщика — которого нет).

### 10.4 «Предложить время и дату» (индивидуально)

Отдельная механика от владельца (#111 «предложить время и дату»): в фазе 2 — структурное
поле заявки/сообщения подопечного «дата + время + комментарий», у тренера — очередь
предложений с ответами «Подходит / Предложу другое». В MVP потребность закрывает
комментарий заявки (§6.3) и живое общение в Telegram (§11). Расписание-слоты тренера
(структурированные) — только после этого.

## 11. Чат единомышленников — рекомендация: Telegram-группа

**Сравнение вариантов** (по #111 «чат для поиска единомышленников»):

| Критерий | Telegram-группа (рекомендация) | Внутренний чат |
|---|---|---|
| Разработка | ноль (создать группу) | сервер: сообщения, доставка, история; huge |
| Модерация | средства Telegram + владелец-админ | своя: антиспам, баны, жалобы |
| Привычность | все и так в Telegram | «ещё один чат» в приложении-дневнике |
| ПДн | вне нашего сервера | сообщения пользователей на нашем сервере |
| Риск | низкий | высокий (сроки, злоупотребления) |

**Решение (предложение)**: закрытая Telegram-группа «MyHelper · Сообщество» (владелец —
владелец группы). В приложении — одна точка входа: Профиль → «Тренер» → строка
«💬 Сообщество» + дисклеймер «Чат работает в Telegram; правила — в закрепе». Ссылка —
invite-link (владелец может ротировать). Бот не пишет в группу, продукт ничего в ней не
хранит. Правила (черновик, владелец правит): взаимное уважение; без рекламы и «купи курс»;
здоровье — не диагноз, обсуждение ограничений с тренером лично.

Внутренний чат (DM тренер↔подопечный) — **не делаем** (§18); после связки приложение
показывает подсказку «Общайтесь в Telegram» (контакт раскрывается по вопросу №5).

## 13. ПДн, приватность, модерация (отдельный раздел)

### 13.1 Что публично (карточка тренера)

Публично **только** `verified`-карточка и только поля формы §5.2. Контакты (телефон,
e-mail, ссылки на соцсети) — **отдельных полей нет**, а в свободных текстах их указание
формально не запрещено, но модерация вправе отклонить (владелец смотрит карточку перед
публикацией). Контакт Telegram раскрывается только внутри связки (вопрос №5).
Аватар — по явному чекбоксу (§5.2).

### 13.2 ПДн подопечного

- По умолчанию тренер не видит **ничего**, кроме имени/аватара (§7.3).
- Гранты — гранулярные, немедленно отзываемые, живут в связке (§8).
- Данные здоровья — чувствительная категория: отдельное поле, отдельный грант, показ
  только тренеру; хранится вне карточки, в `healthNotes` (§4.1); в публичность не попадает
  никогда.
- Журнал согласий: факты изменения грантов (кто, когда, что) — в `social.json` с меткой
  времени (мини-лог последних 20 событий на пользователя) — чтобы был след согласия.
- Журнал **просмотров** тренером — НЕ ведём в MVP (параноика против 6 «своих» пользователей
  не строим); вернуться при росте (вопрос №11).

### 13.3 152-ФЗ (маркеры, не юр. заключение)

- Оператор ПДн — владелец продукта. Обновить политику конфиденциальности (резерв строки
  уже есть в Настройках, [ONB-T2]): добавить раздел «Социальные функции»: что публикуется,
  гранты, отзыв, удаление.
- Право на забвение — §4.1 (удаление данных → чистка соцслоя).
- Уведомление регулятора/локализация сервера — юр. вопрос владельца (вопрос №13); в
  дизайне отмечаем: сервер один, VPS, локация известна владельцу.
- Возраст: функция для взрослых; явного возрастного замка в продукте нет — вопрос №12.

### 13.4 Модерация (владелец вручную на старте)

- **Премодерация карточек**: публикация только после `/trainer_ok` (§5.3).
- **Жалобы**: кнопка «⚠️ Пожаловаться» в карточке тренера → deep-link
  `https://t.me/<bot>?start=feedback` (существующий механизм обратной связи, README) —
  владелец получает текст + отправителя. Карточка жалобы пишется и в `social.json`.
- **Реакции владельца**: скрыть карточку (`/trainer_no`), разорвать связь, удалить
  пользователя из соцслоя. Разблокировка — вручную.
- Автомодерации текстов нет и не будет на старте (§18) — объёмы не требуют.

| Команда | Ответ |

```text

  Профиль → Тренер → «Что видит тренер»
    тоглы: Прогресс / Цели / Вес-рост / Здоровье  ──→  «Мои подопечные» → карточка
                                                                 (видит только включённое)

ТРЕНЕР (включение режима):
Профиль → тогл «Я тренер» → форма → «Отправить на проверку»
  ──→ бот владельцу (в очередь /trainer_pending) → /trainer_ok|/trainer_no
        └→ бот тренеру «Подтверждена» / «Отклонена + причина»
```

## 16. MVP-срез vs полная картина

### 16.1 Рекомендация: состав итерации S1

**Входит (по порядку сборки):**

1. Хранилище `social.json` + API (§4) — фундамент.
2. Режим «Я тренер»: форма карточки, черновик/«на проверке», админ-команды верификации (§5, §14.5).
3. Поиск (город/зал + специализации) и детальная карточка; инфо-кнопка в Технике (#52) (§6).
4. Связка: заявка→одобрение + код приглашения; уведомления бота (§7, §14).
5. Гранты + карточка подопечного у тренера (read-only) + заметка «Здоровье» (§8–9).
6. «Сообщество» — ссылка на Telegram-группу (§11). Жалобы через feedback (§13.4).
7. Команда `/trainer` (§14.4) + правки политики конфиденциальности (§13.3).

**НЕ входит (осознанно):** групповые занятия (§10 — концепт готов, берём отдельной
итерацией после стабилизации связок), «предложить время» структурой (только комментарий
заявки), рейтинги/отзывы, загрузка фото, функции ведения тренера (цели/комментарии/программы
— #54 фаза 2, когда GOA-I1 даст данные целей), монетизация (после MON-E1), второй тренер
у подопечного.

### 16.2 Почему именно так

- Связка+гранты — ядро ценности и главный ПДн-риск: лучше отработать на минимуме поверхностей.
- Групповые занятия добавляют новый публичный контент и пуши-логистику — это второй
  «проект» внутри проекта; готовый концепт §10 не теряется.
- Рейтинги без массы пользователей опасны (накрутка на 6 юзерах тривиальна) — отложены.

### 16.3 Декомпозиция (черновик для lead'а)

| Тикет | Суть | Зависимости |
|---|---|---|
| TRN-S1.1 | `SocialStore` + `social.json` + бэкапы + чистка при `/deletedata` | — |
| TRN-S1.2 | Режим «Я тренер»: форма + статусы + админ-команды | 1 |
| TRN-S1.3 | Поиск + карточка + инфо-кнопка в Технике | 1, 2 |
| TRN-S1.4 | Заявка/одобрение/код + уведомления бота | 2, 3 |
| TRN-S1.5 | Гранты + карточка подопечного + «Здоровье» | 4 |
| TRN-S1.6 | Сообщество-ссылка + политика + `/trainer` | 2 (тексты — любые) |

## 18. Что НЕ делаем и почему

| Не делаем | Почему |
|---|---|
| Внутренний чат (DM и общий) | Несоразмерная разработка + модерация; Telegram-группа закрывает потребность (§11) |
| Рейтинг, отзывы, «звёзды» | 6 пользователей = фиктивные числа и накрутка; алгоритмы рейтинга — позже, при массе |
| Верификация документами | Юр. и операционная нагрузка несоразмерна; ручная верификация владельцем достаточна |
| Геолокация, карты, «тренеры рядом» | Гео-разрешения, точность, приватность — без города/зала текстом потребность закрыта |
| Загрузка фото на сервер | WebServer не принимает файлы; аватар Telegram бесплатно закрывает 90% случаев |
| Комиссия с услуг, встроенные платежи за тренировки | Не отследить оффлайн-оплаты; юр. риски; см. §12 |
| Автомодерация текстов (стоп-слова, ML) | Объёмы не требуют; премодерация владельцем точнее |
| Публичный каталог без авторизации | Каталог виден только пользователям приложения (initData); иначе — парсеры и спам |
| Журнал просмотров тренером | Параноика на 6 пользователей не строим; вопрос №11 |
| Структурированные слоты расписания / пуш-напоминания о занятиях | Нет планировщика в продукте; потребность MVP закрывается текстом и Telegram |

## 19. Вопросы владельцу (нужны ответы до кода)

1. **Тон обращений**: продукт сейчас преимущественно на «ты» («У тебя есть незавершённая
   тренировка», «твой вес»). Новые тексты этой спеки написаны на «Вы» — унифицировать ли
   весь продукт на «Вы» или переписать новые тексты на «ты»?
2. **Верификация**: подтверждаете лично Вы, вручную (`/trainer_ok`) — верно? Есть ли
   требования к тому, кто может стать тренером (кроме Вашего решения)?
3. **Привязка**: хватает ли пары «заявка + код приглашения»? Нужен ли поиск «по имени
   тренера» (найти конкретного человека, а не по городу)?
4. **Границы данных**: гранты «Прогресс / Цели / Вес и рост / Здоровье» — правильный набор?
   Дефолт «Прогресс ВКЛ при связке» — согласны (или всё OFF)? Тренеру достаточно агрегатов
   (без журнала упражнений)? Можно ли вообще принимать текст о здоровье (чувствительные
   данные) — или лучше убрать поле?
5. **Контакт тренера**: раскрывать Telegram-контакт тренера подопечному только после
   связки — ок? Или публичная кнопка «Написать в Telegram» прямо в карточке?
6. **География**: один город/зал или сразу страна? Обязателен ли фильтр города в поиске
   MVP (можно и без него — просто список всех подтверждённых)?
7. **Сообщество**: Telegram-группа — согласны? Открытая или по invite-ссылке? Правила
   (§11) — правьте под себя.
8. **MVP-срез**: согласны с составом §16.1 (без групповых занятий, рейтингов, «предложить
   время» структурой)? Групповые — следующей итерацией?
9. **Монетизация**: старт бесплатно, потом «Тренер Pro» за Stars (§12B); комиссию с услуг
   не делаем — согласны?
10. **Фото**: аватар Telegram вместо загрузки файлов — достаточно? (загрузка = отдельная
    задача с хранением и модерацией)
11. **Модерация/жалобы**: канал «Пожаловаться» через существующую обратную связь — ок?
    Нужен ли журнал просмотров тренером (сейчас не ведём)?
12. **Возраст**: ограничивать ли режим тренера и подопечных 18+? (в продукте сейчас
    известна дата рождения — замок реализуем)
13. **Хранение/юр.**: `social.json` на том же VPS — ок? Локация сервера и 152-ФЗ
    (уведомление регулятора) — что решили? Это не блокер кода, но блокер публикации.
14. **Имена в UI**: скрытый таб/раздел «Персональный тренер» (будущие программы/советы —
    это контент, НЕ соцсеть) переименовать в «Советы и программы»? Слово «Тренер» тогда
    целиком принадлежит соцвертикали.

## 20. Риски

| Риск | Мера |
|---|---|
| ПДн-инцидент (утечка данных подопечного) | гранты по умолчанию OFF, агрегаты вместо журналов, заметка о здоровье отдельно, чистка при удалении данных; контракт-тесты на видимость |
| Ручная модерация не масштабируется | осознанно; при росте — самообслуживание + жалобы (решение владельца) |
| Фейковые тренеры подрывают доверие | премодерация + бейдж «✔ Подтверждён»; отзывы позже |
| Бренд «приватного дневника» размывается | соцслой опционален, выключен по умолчанию, копирайтинг подчёркивает контроль данных |
| Объём работы велик для чистой Java | жёсткий MVP-срез §16, декомпозиция §16.3, без БД/чата/файлов |
| Тон текстов разъезжается с продуктом | вопрос №1 — решить до вёрстки текстов |
| Конфликт имён «Тренер» (контент vs соцсеть) | вопрос №14 |
