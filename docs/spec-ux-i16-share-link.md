# [UX-I16] Read-only шейринг тренировки по ссылке

- **Idea**: https://github.com/PolkAlex/gymhelper/issues/267 ([UX-I16], метка `need_design`)
- **Макет**: `docs/mockups/ux-i16-share-link.html` — публичная read-only страница тренировки
  (мобайл 390, Amber Glass, стиль лендинга), страница «Тренировка недоступна», шит выбора
  «Картинка / Телеграм» на карточке завершённой тренировки, тост «Ссылка скопирована»
- **Статус**: In Design. Гейт: **код не пишется до одобрения владельцем** (правило макет-ревью)
- **Связанные**: [UX-I14] (`spec-ux-i14-share-card.md`) — картинка-постер, **другая механика**;
  лендинг gym-helper.com (тёмная Amber Glass — источник стиля страницы); канал @MyHelperGym
- **Затрагивает**: `src/gym/web/WebServer.java` (публичный GET `/w/<shareId>` + API
  `POST /api/share`, заголовки noindex, robots.txt), `src/gym/Workout.java` + `GymData.java`
  (поле `shareId`, обратная совместимость), `web/app.js` (шит выбора, генерация ссылки,
  fallback), `web/style.css` (шит), `src/gym/Stats.java` (ключи-счётчики)
- **НЕ затрагивает**: `src/gym/BotLogic.java` (бот не меняется — шеринг только из Mini App,
  как в UX-I14 §9), формат CSV `/export`, лендинг, канал

> **Редакция 2 [I16-update1 19.11.2026]** — фидбек владельца по шиту выбора: пункт
> «Ссылка» заменён на **«Телеграм»** — тап копирует ссылку в буфер обмена и открывает
> **выбор чата Telegram** через официальный `t.me/share/url?url=…` (Telegram сам
> показывает чаты/каналы с превью страницы по OG-тегам), затем тост
> «🔗 Ссылка скопирована». Порядок и fallback — §7.2; счётчики `linkSend`/`linkCopy` — §7.3.
> Чистое копирование («Ссылка») из шита убрано — его закрывает «Телеграм».

## 0. Резюме решения (TL;DR — короткие ответы на вопросы владельца)

| Вопрос владельца (#267) | Ответ |
|---|---|
| «Он её тапает и открывается приложение? Лендинг?» | **Ни то, ни другое.** Открывается **публичная read-only веб-страница этой тренировки** (`app.gym-helper.com/w/<shareId>`): карточка в стиле продукта, без входа, в любом браузере. В Telegram ссылка открывается во встроенном браузере — тот же вид |
| «Если делюсь с тем, у кого есть приложение — проще?» | Механика **одна для всех**: у пользователя бота страница выглядит так же; его данные не затрагиваются. Из страницы его Diary не видно и чужая тренировка в его дневник не попадает никогда |
| «Посмотрел — а дальше что? Крестик → История?» | **Нет.** Чужая тренировка не попадает в данные друга, поэтому и «История» не при чём. Закрытие страницы/браузера возвращает в **чат, откуда открыл**. У не-юзера страница остаётся с CTA «Попробовать в Telegram». У юзера CTA «Попробовать» открывает его собственный дневник (deep-link) |
| «Приватность ссылки» | Длинный случайный `shareId` (~131 бит, не угадывается), страница с `noindex`, видна **только** по ссылке. Удаление тренировки владельцем → ссылка умирает (404). Отзыв и срок — v2 |

**Одно каноническое решение вместо трёх**: страница покрывает и юзера, и не-юзера,
и Telegram, и любой браузер. Read-only режим внутри Mini App (через `startapp`) —
overengineering: второй «шелл» для того же контента (§10).

## 1. Цель и пользовательская проблема

**Продуктовая** (гэп дистрибуции, `docs/analysis-strategy-2026-11.md`): UX-I14 даёт
виральную **картинку**, но картинка — плакат: цифры без контекста, в личку «жал 120×8»
уходит скрином, который нельзя открыть. Ссылка на конкретную тренировку — вторая
виральная механика: адресат тапает и видит **живую, настоящую** карточку «как в
приложении» — это сильнее плаката для личного диалога («смотри, что я сегодня сделал»).

**Пользовательская**: после тренировки хочется показать её конкретному человеку.
Пересылка скриншота — сухая; давать другу «свой телефон» — нельзя; заводить соцсеть —
избыточно. Нужна ссылка, которую можно отправить в личку другу, — открывается у кого
угодно, показывает только эту тренировку, ничего не требует (без входа и установки).

**Решение**: кнопка «📤 Поделиться» на завершённой тренировке → выбор **«Картинка»**
(постер UX-I14, для сторис/каналов) или **«Телеграм»** (ссылка копируется в буфер и
открывается системный выбор чата Telegram — родная доставка в личку/чат/канал,
редакция 2). Ссылка открывается в любом браузере без входа; видна только по ссылке.

**Тон**: те же правила, что у UX-I14 — факты тренировки, «хочу так же», без рекламы.
Продукт в текстах — от третьего лица.

## 2. Что открывается у друга: разбор кейсов (вопрос 1–2 из #267)

### 2.1 Друг НЕ пользователь (главный кейс владельца)

Тап по ссылке в личке → Telegram открывает **встроенный браузер** (или любой внешний,
если ссылку переслали за пределы TG). Открывается публичная страница:

- **Стиль** — тёмная Amber Glass, как лендинг: та же палитра, те же стеклянные карточки,
  тот же шрифт. Страница выглядит «родной» в тёмном Telegram и как бренд вне его.
  Тема всегда тёмная (как картинка UX-I14 §4): тёмный фон — бренд, светлая тема
  получателя на страницу не влияет.
- **Состав** — см. §6: дата, агрегаты, герой-число, рекорд, все упражнения, серия.
- **CTA** внизу (sticky): **«🏋️ Попробовать в Telegram»** → `t.me/MyHelperGymBot/app`.
  Под кнопкой строка: «Уже пользуетесь? Откроется ваш дневник».
- **После просмотра**: страница никуда не «перекидывает». Закрыл браузер — вернулся
  в чат. Захотелось попробовать — тапнул CTA, попал в бота, онбординг (~60 сек, [ONB]).

### 2.2 Друг — пользователь бота

Техническая реальность: https-ссылка в Telegram **всегда** открывается во встроенном
браузере — Telegram не «прокидывает» произвольные URL внутрь Mini App. Открыть чужую
тренировку внутри Mini App друга можно только отдельным механизмом
(`t.me/MyHelperGymBot/app?startapp=<shareId>` — приложение стартует с параметром и
запрашивает публичный JSON). Это возможно, но **дублирует** страницу: два рендера
(web + Mini App) одной карточки, два пути тестирования, ноль новой ценности —
содержимое одинаковое.

**Решение MVP**: для друга-юзера открывается **та же веб-страница**. Его сценарий
отличается только последним шагом: CTA «Попробовать в Telegram» открывает **его**
чат с ботом и его дневник. Чужая тренировка **не копируется** в его данные —
read-only по определению; «История» друга остаётся его собственной.

Deep-link-режим Mini App (`startapp`) — **отложено в v2** (вопрос владельцу, §11.6):
имеет смысл только если владелец захочет бренд-фидбек «открывается как приложение».

### 2.3 «Дальше что» — ответ на гипотезу «крестик → История» (вопрос 3 из #267)

Гипотеза владельца не работает ни в одном варианте, и это **правильно**:

| Кто открыл | «Дальше что» |
|---|---|
| Не-юзер | Закрыл вкладку → вернулся в чат. Или тапнул CTA → бот → онбординг. Страница одноразовая точка входа, не «экран приложения» |
| Юзер | Закрыл встроенный браузер → вернулся в чат. Его «История» — в его Mini App, чужая тренировка туда не попадает (read-only, §2.2). Если он хочет **свою** историю — открывает дневник как обычно |
| Владелец ссылки | Открыл свою же ссылку → видит ту же страницу (ничего секретного для себя там нет). Ничего не меняется ни в приложении, ни в боте |

Никакого «крестика с перекидыванием» в дизайне нет вообще: страница — обычный веб-документ,
её «крестик» — это системная кнопка браузера/webview, поведение которой мы не контролируем
и не должны: она всегда возвращает туда, откуда открыли.

## 3. Сценарии использования

### Сценарий 1 — «Показать другу в личке» (главный)

1. Пользователь завершает тренировку (рекорд, объём, серия).
2. История → тап по тренировке → карточка → **«📤 Поделиться»** → шит выбора (§7).
3. Тап **«✈️ Телеграм»** → приложение запрашивает у сервера `shareId` (мгновенно, < 300 мс),
   копирует ссылку в буфер обмена и открывает **выбор чата Telegram**
   (`t.me/share/url?url=…`, §7.2).
4. Выбор чата «смотри» → отправка. Telegram прикрепляет ссылку и строит превью страницы
   по OG-тегам («Тренировка · 16 ноября · GymHelper» — без цифр, §5).
5. Вернувшись в приложение, пользователь видит тост «🔗 Ссылка скопирована».
6. Друг тапает ссылку → страница (§2.1). Читает, закрывает. При желании — CTA → бот.

### Сценарий 2 — «Отправить в группу/канал»

Тот же сценарий, но получателей много: каждый открывает свою копию страницы
(рендер живой, §8.4). Виральность: канал с аудиторией → N переходов → CTA.

### Сценарий 3 — «Друг-юзер открыл ссылку»

Как сценарий 1, шаг 5: страница та же; тап CTA → его дневник. Ничего не ломает:
в его данных изменений нет, /history не тронут.

### Сценарий 4 — «Владелец удалил тренировку»

Через день владелец чистит дневник (удаляет тренировку из Истории или `/delete_my_data`).
Чья-то старая ссылка теперь открывает страницу **«Тренировка недоступна»** (§6.3):
вежливый текст + CTA «Попробовать». Данных по ссылке больше нет.

### Сценарий 5 — «Буфер обмена недоступен»

Старый webview без `navigator.clipboard` → выбор чата Telegram всё равно открывается:
URL передаётся параметром `?url=` — Telegram сам прикрепит его к сообщению
(**ПРОВЕРИТЬ** на iOS/Android, §7.2). Тост копирования не показывается — копировать
нечем и незачем. Совсем старый webview без `openTelegramLink` — открытие
`t.me/share/url` через `window.open`; механика не ломается.

## 4. Ссылка и жизненный цикл shareId

### 4.1 Формат

| Параметр | Решение |
|---|---|
| URL | `https://app.gym-helper.com/w/<shareId>` — тот же сервер и домен, что у Mini App; отдельного веб-хостинга нет. Короткий домен `gym-helper.com/w/…` (через прокси) — v2, вопрос владельцу (§11.7) |
| shareId | **22 символа base62** (`[0-9a-zA-Z]`), генерация `SecureRandom` 128 бит → ~131 бит энтропии. Не угадывается, не перебирается, никак не связан с chat id / номером тренировки |
| Пример | `https://app.gym-helper.com/w/9kQz4vTm2wR8pLd1XaBc5e` |

### 4.2 Жизненный цикл

| Событие | Поведение |
|---|---|
| Первый тап «✈️ Телеграм» | `POST /api/share {wid}` → сервер генерирует `shareId`, сохраняет в тренировку (`"shareId"` в JSON), возвращает `{shareId, url}`. `shareId` создаётся **лениво** — только у тренировок, которыми делились |
| Повторный тап | Тот же `shareId` → **та же ссылка**. Стабильность важна: одна тренировка = один адрес (не плодим копии в чатах, Telegram кеширует превью по URL) |
| Правки владельца после шеринга | Страница рендерится **живьём** из данных при каждом открытии: поправил вес — в ссылке актуальный вес. Это фича («честность»), не баг |
| Удаление тренировки владельцем (Mini App или бот) | Ссылка умирает: GET `/w/<shareId>` → 404 «Тренировка недоступна». Данные тренировки удалены — рендерить нечего |
| `/delete_my_data` | Умирают **все** ссылки владельца (файл данных удалён целиком) |
| Коллизия shareId | Вероятность ~0; при генерации проверка по индексу, коллизия → перегенерация |
| **Отзыв ссылки (v2)** | Кнопка «Отозвать ссылку» в шите шеринга: `shareId` удаляется/меняется → старая ссылка 404. В MVP отзыва нет (§11.5) |
| **Срок жизни (v2)** | По умолчанию бессрочно до удаления/отзыва. Авто-истечение — вопрос владельцу (§11.8) |

### 4.3 Приватность ссылки

- Ссылка — «пароль без ввода пароля»: кто получил URL, тот и видит. Это осознанная
  модель («share by obscurity»), стандарт для шеринга (Google Docs «по ссылке»).
- На страницу **нет** индексации: `<meta name="robots" content="noindex, nofollow">`,
  заголовок `X-Robots-Tag: noindex, nofollow`, `robots.txt: Disallow: /w/`
  (ремень + подтяжки: мета-тег не читается, если страницу отдали по уже
  проиндексированной ссылке, заголовок работает всегда).
- 404-страница **одинаковая** для «не существует», «удалена» и «отозвана» —
  не даём оракула «а существует ли такой id».
- Сервер не логирует содержимое запросов `/w/` (только агрегат-счётчик `linkView`).

## 5. Приватность содержимого страницы (ПДн-минимализм)

Правило то же, что у UX-I14 §3: **всё, что не работает на «хочу так же», не показываем.**
Но страница публичнее картинки (живой URL, который ходит по чатам) — порог строже.

### 5.1 Показываем

| Блок | Что именно |
|---|---|
| Дата тренировки | «16 ноября · понедельник»; год добавляется, если дата не текущего года («14 марта 2025») |
| Герой-число | объём кг; при калистенике — сумма повторений (паритет с UX-I14 §3) |
| Агрегаты | длительность («1 ч 14 м»), ккал (если профиль задан), число подходов |
| Рекорд | **реальным весом** («120 кг — вес, который жал», решение владельца 19.11). Расчётный 1ПМ по Эпли на странице **не показываем** — посторонний получатель не знает, что это оценка; честный факт лучше расчёта |
| Упражнения | все (не первые 3, как у картинки — страница не канва): название + подходы «120 кг × 3×8»; подход-рекордсмен с янтарным 🏆 |
| Серия | «🔥 Серия: 12 тренировок подряд» при n ≥ 2, формулировка как в приложении (§6.2) |
| Подпись бренда | «GymHelper · дневник тренировок в Telegram» |

### 5.2 НЕ показываем (осознанно)

| Что | Почему |
|---|---|
| Имя, @username, фото владельца | ПДн. Ссылку пересылают — получатель не должен узнавать человека без его согласия. Вопрос об opt-in имени — §11.1 |
| Кастомное название тренировки | Может содержать личное («Тренировка с Машей») — тот же запрет, что в UX-I14 §3. На странице только дата. Вопрос владельцу — §11.2 |
| Питание («что пил и ел») | Личное, на «хочу так же» не работает |
| Время начала и конца (часы) | Паттерн распорядка дня («всегда в 7:00») — лишние сведения о человеке. Показываем только длительность |
| Вес тела, пол, возраст, рост, дата рождения | ПДн профиля. Ккал нужны, вес тела — нет |
| Прогресс vs прошлая тренировка, ккал по упражнениям, MET-детали | Шум; внутренняя кухня продукта |
| Число просмотров ссылки | Соц-давление и утечка «кто как смотрит»; агрегат живёт только в /stats |

**Нюанс про ккал (осознанно принято)**: ккал считаются по MET от веса тела —
зная ккал и минуты, вес тела можно приблизительно вычислить. Владелец включил ккал
в состав страницы (19.11) — оставляем: цифра «622 ккал» сама по себе ничего не называет,
а точность «вычисления веса» низкая (MET зависит от объёма/мин). Если владелец
передумает — ккал убирается одним блоком (§11.4).

### 5.3 OG-превью (что видит Telegram до тапа)

- `og:title`: **«Тренировка · 16 ноября»**; `og:description`: «Открытая карточка
  тренировки — GymHelper, дневник тренировок в Telegram»; `og:site_name`: GymHelper.
- **Чисел в превью нет** (объём/рекорды — только после тапа): превью пересылают дальше,
  а плакат-цифры в ленте без контекста — это то, от чего ПДн-минимализм уберегает.
  Вариант «добавить герой-число в превью ради вау» — вопрос владельцу (§11.3).
- Telegram кеширует превью по URL — ещё одна причина стабильного `shareId` (§4.2).

## 6. Состав read-only страницы

### 6.1 Блоки (сверху вниз)

| # | Блок | Содержимое |
|---|---|---|
| 1 | Шапка бренда | янтарный тайл 💪 + «GymHelper»; справа пилюля «только просмотр» (приглушённая — честная метка read-only, не технический жаргон) |
| 2 | Карточка тренировки (glass, glow) | дата «16 ноября · понедельник» → **герой-число** (объём «5 340 кг» / повторения) с подписью «объём тренировки» → плашка рекорда при наличии: «🏆 НОВЫЙ РЕКОРД · ЖИМ ШТАНГИ ЛЁЖИ» + «120 кг» + мелко «реальный вес подхода» |
| 3 | Агрегаты | три стеклянные карточки в ряд (решение владельца 19.11 в UX-I14 — полоса-стрип слеплялась): «1:14 / время», «622 / ккал», «9 / подходов». Ккал-карточки нет, если профиль без веса |
| 4 | Упражнения | стеклянная карточка; каждое упражнение — вложенная пилюля: тайл-иконка + название + строки подходов «120 кг × 3×8» (формат `entryLine`); лучший сет-рекордсмен упражнения — янтарный бейдж «🏆 рекорд» справа. Упражнения без весов — «4×8» без «кг» |
| 5 | Серия (если ≥ 2) | вложенная карточка 🔥 «Серия: 12 тренировок подряд» + подстрока дней |
| 6 | Строка приватности | 🔒 «Карточка видна только по этой ссылке — без входа и без имени» (мелко, приглушённо; снимает тревогу и у получателя, и у владельца) |
| 7 | Sticky CTA (низ) | янтарная кнопка «🏋️ Попробовать в Telegram» → `t.me/MyHelperGymBot/app`; под ней «Уже пользуетесь? Откроется ваш дневник»; ниже подпись бренда «GymHelper · дневник тренировок в Telegram» |

### 6.2 Серия — точное определение (для coder)

Считается по завершённым тренировкам владельца, **заканчиваясь датой этой тренировки**
(включая её): череда дней, где каждый следующий день с тренировкой = предыдущий + 1
(алгоритм `monthStreak()` в `app.js`, ограниченный «до даты тренировки», а не «за месяц»).
Формулировка — «Серия: N тренировок подряд» (`trainWord` для склонения), показ при N ≥ 2.
Серия считается **на момент открытия страницы** — если владелец продолжает ходить,
серия у ссылки не «замораживается»; это живой факт, согласуется с живым рендером (§4.2).

### 6.3 Страница «Тренировка недоступна» (404)

Та же шапка бренда; по центру стеклянная карточка: тайл 🔗, заголовок
**«Тренировка недоступна»**, текст: «Ссылка устарела, или владелец удалил тренировку
и закрыл доступ. Попросите свежую карточку — или попробуйте GymHelper сами:
записывать тренировки здесь — за секунды.» Ниже — тот же sticky CTA.
HTTP-статус 404, те же noindex-заголовки. Одинаково для «не найдено» / «удалено» /
«отозвано» (§4.3).

### 6.4 Адаптивность

- Телефон (основной случай): ширина контента до 430px, все блоки в одну колонку.
- Десктоп: контент центрируется колонкой ~430–480px на тёмном фоне — страница
  остаётся «телефонной» карточкой, это норм (ссылка рождается в мессенджерах).
- Без JS: страница целиком сервер-рендер (§8), JavaScript на ней не нужен.

## 7. Кнопка «Поделиться» и выбор «Картинка / Телеграм»

### 7.1 Точка входа — одна

На карточке завершённой тренировки остаётся **одна** кнопка UX-I14 «📤 Поделиться»
(место и правило видимости — UX-I14 §7: тело карточки, `finished && setsTotal > 0`).
Тап открывает **нижний шит выбора** (модалка продукта, Amber Glass sheet):

| Строка шита | Тайл | Подпись |
|---|---|---|
| **Картинка** | 🖼 | «Постер для сторис и каналов» |
| **Телеграм** | ✈️ (иконка Telegram-стиля, фирменный синий тайл) | «Отправить в любой чат — откроется выбор чата, ссылка также скопируется» |
| Футер шита | — | мелко: «Ссылку видят только те, кому вы её отправили» |

Шапка шита — «Поделиться тренировкой» + кнопка «✕» (закрыть; тап по подложке тоже
закрывает). Если UX-I14 уже в проде с прямым рендером канвы — I16 превращает тап
в шит, старый рендер становится действием строки «Картинка» (небольшой рефакторинг
фронтенда, механика канвы не меняется).

### 7.2 Поток «Телеграм» (редакция 2)

1. Тап «✈️ Телеграм» → шит закрывается, кнопка «Поделиться» — «Готовим ссылку…»,
   повторный тап заблокирован.
2. `POST /api/share {wid}` → `{shareId, url}` (норма < 300 мс; id генерируется один
   раз и переиспользуется, §4.2).
3. **Сначала буфер**: `navigator.clipboard.writeText(url)` — ссылка уже у пользователя,
   даже если выбор чата он закроет и уйдёт в другой чат или приложение.
4. **Затем выбор чата**: `tg.openTelegramLink('https://t.me/share/url?url=' +
   encodeURIComponent(url))` — официальный шеринг Telegram: список чатов/каналов
   пользователя с превью страницы (OG-теги, §5.3). t.me-адреса в Mini App открываются
   только через `openTelegramLink` (Telegram WebApp API) — навигация через
   `window.location` в webview ненадёжна.
5. **Тост** **«🔗 Ссылка скопирована»** — показывается в момент копирования;
   пользователь видит его сразу после возврата из выбора чата.
6. Отмена выбора чата — не ошибка: ссылка уже в буфере, тост сказал правду,
   кнопка разблокирована.

**Порядок важен**: буфер → выбор чата. Telegram при отправке через `t.me/share/url`
сам прикрепляет URL к сообщению (вместе с превью по OG-тегам) — буфер нужен не
для вставки, а как гарантия: ссылка останется у пользователя при любом повороте
сценария (закрыл выбор чата, переслал позже, вернулся в другой чат).

**Fallback**: `navigator.clipboard` недоступен → шаг 3 пропускается, открывается
только выбор чата (Telegram передаёт URL параметром `?url=` и прикрепляет его к
сообщению — **ПРОВЕРИТЬ** на iOS/Android: ссылка и её превью доходят до получателя
в fallback-ветке). Совсем старый webview без `openTelegramLink` → `window.open(...)`.
Механика не ломается ни в одной ветке.

Механика «Ссылка» с чистым копированием из шита **убрана** (редакция 2): её закрывает
«Телеграм» — буфер заполняется в том же потоке, а выбор чата — главный путь доставки.
`navigator.share` для ссылки больше не используется: в webview это лишний посредник,
`openTelegramLink` — родной путь Telegram.

### 7.3 Счётчики (воронка механики; ключи в `Stats.KEYS` + белый список WebServer, агрегаты без ПДн)

| Ключ | Событие |
|---|---|
| `linkCreate` | POST `/api/share` вернул url |
| `linkSend` | открыт выбор чата Telegram (`t.me/share/url`) |
| `linkCopy` | ссылка записана в буфер обмена |
| `linkView` | GET `/w/<shareId>` отдал страницу (200) |

Воронка: `linkCreate → linkCopy → linkSend → linkView` — видно, у скольких
пользователей буфер не сработал (разрыв linkCopy → linkSend) и сколько ссылок
реально открыли получатели (linkView на linkSend). Ключи картинки UX-I14
(`shareClick/shareOk/shareDownload`) остаются как были — две механики считаются
отдельно, воронку сравниваем: что лучше «выстреливает», картинка или ссылка.

## 8. Архитектура MVP

### 8.1 Сервер (`src/gym/web/WebServer.java`)

| Элемент | Решение |
|---|---|
| `GET /w/<shareId>` | Публичный маршрут (без initData — до авторизационного слоя `/api/*`). Сервер находит тренировку по `shareId` и **рендерит HTML строкой на Java** (как остальной код — без зависимостей): статичный документ с инлайн-CSS (палитра Amber Glass из `web/style.css`, ~2–3 КБ), без внешних файлов и шрифтов. 404-страница — тем же шаблоном |
| Индекс shareId → файл данных | Ленивый: при первом промахе по памяти сервер сканирует `data/*.json` (их десятки, не тысячи) и строит `Map<shareId, chatId>`; сброс/досрочная инвалидация по mtime файлов. Детали реализации — coder; требование: поиск не деградирует при сотнях файлов и работает после рестарта процесса |
| `POST /api/share {wid}` | Авторизованный маршрут (initData, как остальные API). Создаёт/возвращает `shareId` тренировки. Доступно **только для своей** тренировки и только `finished` (иначе 4xx) |
| Заголовки `/w/*` | `Content-Type: text/html; charset=utf-8`, `X-Robots-Tag: noindex, nofollow`, `Cache-Control: no-store` (живой рендер), опционально базовый `Content-Security-Policy: default-src 'none'; style-src 'unsafe-inline'` — на странице нет ни JS, ни внешних ресурсов |
| `robots.txt` | Новый статический файл: `User-agent: * / Disallow: /w/` |
| Хранение | `Workout` получает поле `shareId` (строка, null у старых тренировок). **Обратная совместимость обязательна**: старые файлы без `shareId` читаются как раньше (эталон — `GymContractTest`, добавить кейс «файл без shareId») |

### 8.2 Безопасность рендера

- **Экранирование HTML обязательно для всех пользовательских строк** — имя упражнения
  и название — пользовательский ввод; `<script>` в имени упражнения не должен исполняться
  (на странице нет JS, но дыру не оставляем). e2e-тест с вредоносным именем — §12.
- Рендер только завершённых тренировок (у незавершённых `shareId` не выдаётся; на всякий
  случай рендер проверяет `finished`).
- Ошибки рендера (битые данные) → та же 404-страница, а не stacktrace.

### 8.3 Фронтенд (`web/`)

- Шит выбора — существующая модалка-шит продукта (`.modal`/`.modal-box`, стиль как
  «Добавить упражнение»); два ряда-кнопки (тайл + заголовок + подпись); тайл «Телеграм» —
  фирменный синий (плоскость `#2AABEE → #229ED9`, бумажный самолётик).
- Генерация ссылки, буфер и открытие выбора чата — расширение `app.js` (или маленький
  `share.js`, решает coder), ванильный JS, без новых зависимостей;
  `tg.openTelegramLink` — Telegram WebApp API уже подключён в `web/`.

### 8.4 Производительность

- Рендер страницы — одна выборка из памяти + строковая сборка: < 5 мс на сервере.
  Ответ лёгкий (~10–15 КБ с инлайн-CSS), gzip-конвейер сервера уже есть ([EXR-T7]).
- Telegram запрашивает OG-превью при каждой отправке ссылки в новый чат — ответ быстрый,
  кешировать не нужно.

## 9. Edge-кейсы

1. **Друг — юзер бота**: страница та же, его данные не затронуты (§2.2) — e2e-сценарий.
2. **Десктоп-браузер**: колонка ~430px по центру, читаемо (§6.4).
3. **Владелец открыл свою ссылку**: обычная страница, никаких особых режимов.
4. **Удаление тренировки** (app или бот) → 404 «Тренировка недоступна».
5. **`/delete_my_data`** → все ссылки владельца 404.
6. **Правки после шеринга** (вес/подходы/переименование/удаление упражнения) →
   живой рендер показывает актуальное состояние (§4.2).
7. **Подделанный/несуществующий shareId** → та же 404 (без оракула, §4.3).
8. **Калистеника** (объём 0): герой = сумма повторений; строки без «кг»;
   рекорд повторений — «🏆 рекорд» без веса (паритет UX-I14 §8.1).
9. **Профиль без веса**: агрегатов две (время/подходы), ккал-карточки нет.
10. **Несколько упражнений с рекордами**: у каждого упражнения свой 🏆 у лучшего сета —
    как `prChipSetIdx` в приложении (чип на лучшую запись каждого упражнения).
11. **Долгое имя упражнения / название набора**: перенос строк, без `overflow` (страница
    не канва — ограничений «3 строки» нет).
12. **10+ упражнений**: показываются **все** (отличие от картинки, §5.1) — страница
    это полная карточка.
13. **Год не текущий**: дата с годом («14 марта 2025 · суббота»).
14. **TG-превью без тапа**: OG только дата и бренд — цифры не утекают в ленту (§5.3).
15. **Буфер обмена недоступен** (старый webview): тап «Телеграм» пропускает копирование,
    открывается только выбор чата; тост не показывается; Telegram сам прикрепляет URL
    из параметра `?url=` — проверить на устройствах (§7.2).
16. **Пользователь отменил выбор чата** — не ошибка: ссылка уже в буфере, тост уже
    показан, кнопка разблокирована.
17. **Серия < 2** — блок серии не рендерится.
18. **Имя упражнения с HTML/скриптом** — экранируется (§8.2, e2e-тест).

## 10. Что НЕ делаем и почему

| Отсечено | Почему |
|---|---|
| Read-only режим внутри Mini App (`startapp=<shareId>`) | Дублирует страницу вторым рендером и вторым путём тестов ради одинакового контента; https-ссылка в TG открывается во встроенном браузере и покрывает юзера и не-юзера одинаково. Пересмотр — v2 при доказанном спросе (§11.6) |
| Лендинг как точка открытия ссылки | Смешивает воронки: лендинг — SEO/статьи, ссылка — конкретная тренировка; промежуточный экран режет конверсию |
| Публичный профиль пользователя / список его тренировок | Соц-механика против ДНК продукта («дневник без соцсети»); ссылка — ровно одна тренировка, не «мини-сайт» |
| Пароль на ссылку / доступ по списку получателей | Убивает шеринг трением; 131-битный id достаточно |
| Отзыв и срок жизни ссылки в v1 | Отзыв без UI-хвостов не полный (пересланные ссылки не отзывается из чужих чатов), MVP — удаление как единственная смерть ссылки; отзыв/срок — v2 после первых метрик |
| Кнопка шеринга в боте | Тот же аргумент, что UX-I14 §9: v1 — только Mini App |
| `navigator.share` для ссылки (поток «Ссылка» редакции 1) | Заменён «Телеграм»: родной `t.me/share/url` даёт выбор чата с превью страницы; navigator.share в webview — лишний посредник (редакция 2, §7.2) |
| Счётчик просмотров на странице («ссылку открыли 5 раз») | Соц-давление + пассивная слежка за получателем; агрегат живёт только в `/stats` |
| Реферальные метки (`?start=ref_…`) на CTA | Отдельная идея distribution-plan №4; аттрибуцию не смешиваем с шерингом |
| Светлая тема страницы | Тёмная — бренд; страница-карточка должна выглядеть родной в тёмном Telegram (как картинка UX-I14 §4) |
| EN-версия страницы | RU-фокус стратегии |

## 11. Вопросы владельцу

1. **Имя владельца на странице** — по умолчанию **нет** (ПДн: ссылку пересылают,
   человек не должен узнаваться без согласия). Если хочется («Антон · 12 тренировок
   подряд») — opt-in-тумблер в Профиле, единый с UX-I14 («Показывать имя на шеринге —
   картинке и ссылках»), по умолчанию выключен. Нужен ли?
2. **Кастомное название тренировки** — показывать на странице, если владелец задал своё?
   Рекомендация: **нет** (может содержать личное, «Тренировка с Машей»); на странице дата.
3. **OG-превью в чате** — только «Тренировка · 16 ноября» (рекомендация) или добавить
   герой-число («5 340 кг») ради вау прямо в превью? Превью расходится шире тапов —
   цифры в нём видят даже те, кто не открывал.
4. **Ккал на странице** — остаются (по списку данных 19.11); нюанс: по ккал+минутам
   теоретически вычислим вес тела. Принимаем как есть? Убрать ккал из публичной
   страницы (оставив на картинке)?
5. **Отзыв ссылки** — подтвердить v2 (MVP: ссылка умирает только с удалением тренировки)?
   Или отзыв нужен сразу (кнопка «Отозвать ссылку» в шите)?
6. **Mini App share-режим** (`startapp`) — подтвердить, что пропускаем (веб-страница
   покрывает всех)?
7. **Домен ссылки** — `app.gym-helper.com/w/…` (рекомендация: без нового хостинга) или
   короткий `gym-helper.com/w/…` (нужен прокси-маршрут на сервер бота)?
8. **Срок жизни** — бессрочно до удаления/отзыва (рекомендация) или авто-истечение
   (например, 90 дней)?

## 12. Критерии приёмки (для coder / tester)

- «📤 Поделиться» открывает шит «Картинка / Телеграм»; у активной и пустой тренировки
  кнопки нет (правила UX-I14 §7 сохранены).
- «✈️ Телеграм»: `POST /api/share` → url; повторный вызов возвращает **тот же** shareId;
  поток §7.2 — сначала буфер (`navigator.clipboard`), затем
  `tg.openTelegramLink('t.me/share/url?url=…')`, тост «🔗 Ссылка скопирована».
- Fallback без `navigator.clipboard`: открывается только выбор чата, тост не показывается.
- **Проверено вручную на iOS и Android**: отправка через выбор чата доносит ссылку и
  превью получателю — включая fallback-ветку без буфера (пункт «ПРОВЕРИТЬ» §7.2).
- `GET /w/<shareId>` рендерит read-only страницу: состав §6, тёмная тема, без JS,
  заголовки `noindex` + `X-Robots-Tag` + `robots.txt` (§4.3).
- **Приватность §5.2**: на тестовых датасетах (с именем владельца в профиле, кастомным
  названием, питанием, временем начала) ни одно из запрещённых полей не попадает в HTML.
- **Рекорд реальным весом** («120 кг»), Эпли на странице отсутствует; серия —
  «N тренировок подряд» при N ≥ 2, считается до даты тренировки (§6.2).
- Удаление тренировки и `/delete_my_data` → 404-страница «Тренировка недоступна»
  (одинаковая для несуществующих id); HTTP 404.
