# [UX-I15] #257 · Пилюля «+ Добавить подход» вместо «+» в шапке упражнения

> Статус: **дизайн** (need_design) — спека + макет `docs/mockups/ux-i15-add-set-pill.html`.
> Код не менялся. Воплощение — задача coder после отмашки владельца.
> Направление: UX · Идея владельца дословно (16.11.2026):
> «Здесь кнопка "+" для добавления подходов не нравится. Давай над плашкой "идёт время"
> добавим тонкую, но на всю ширину пилюлю упражнения, кнопку "+ Добавить подход".
> Новая кнопка не должна выглядеть "ярче", чем "+ Добавить упражнение", чуть тоньше,
> это же просто добавить подход. А тот плюс справа вверху уберем.»

---

## 1. Цель и проблема

В карточке упражнения активной тренировки добавление подхода живёт на **тонком «+»
справа вверху шапки упражнения** (`ex-add`, [UX-T22]). Проблемы:

- «+» визуально сливается с соседней корзиной 🗑 — оба «голые» `barebtn` в одном ряду;
  промахи тапом (рядом чужая опасная кнопка);
- действие «добавить подход» — самое частое в активной тренировке, но его цель (куда
  добавится подход) не читается: плюсик висит на уровне **названия** упражнения, а не
  списка подходов;
- нет явного места «точки ввода» — список подходов заканчивается молча (или плашкой
  «упражнение активно — время идёт»), без приглашения к действию.

**Решение:** убрать «+» из шапки; в каждой плитке упражнения, сразу под списком
подходов и **над плашкой «упражнение активно — время идёт»**, положить **тонкую
пилюлю на всю ширину «+ Добавить подход»**, визуально заметно скромнее кнопки
«➕ Добавить упражнение» (иерархия: подход — второстепенное действие относительно
упражнения).

## 3. Целевое поведение

### 3.1 Схема плитки упражнения (DOM, «после»)

```
.expill
├─ .exhead: [фото/иконка] [Название упражнения] [🗑]        ← «+» УДАЛЕН
├─ .entry   «85 кг, 1 подход по 8 повторений»  [🏆 108]     ← существующие подходы
├─ .entry   «85 кг, 1 подход по 8 повторений»
├─ .entry   «87,5 кг, 1 подход по 6 повторений»
├─ .ex-addset   «+ Добавить подход»                          ← НОВАЯ пилюля (всегда у активной)
└─ .restline    «упражнение активно — время идёт»            ← как было, ПОД пилюлей
```

Пилюля — последний интерактивный элемент плитки: список подходов «замыкается» точкой
ввода. Между пилюлей и `.restline` сохраняется текущий ритм (`.restline` margin-top 4px).

### 3.2 Точная позиция

- **Внутри** плитки упражнения (`.expill`), не на уровне карточки — пилюля принадлежит
  конкретному упражнению.
- **После последнего подхода** (`.entry`), **перед** `.restline`. У упражнения без
  `.restline` (не текущее) — сразу после подходов.
- При **0 подходов** пилюля — первый элемент после `.exhead` (единственная точка входа,
  см. §6.1).

### 3.3 Поведение тапа — БЕЗ изменений

`data-act="openEntryModal" data-a="<wid>" data-b="<exIdx>" data-c="-1"` — та же модалка
«Новая запись», что у старого «+»: вес/подходы/повторения, подстановка веса прошлого
подхода [UX-T12], план упражнения [UX-E5]. Ничего в логике сохранения не меняется.

### 3.4 Видимость

| Состояние тренировки | Пилюля | Было |
|---|---|---|
| Активная, упражнение с подходами | ✅ после подходов | «+» в шапке |
| Активная, упражнение 0 подходов | ✅ единственный элемент под шапкой | «+» в шапке |
| Активная, текущее упражнение (CUR) | ✅ + `.restline` под ней | «+» + restline |
| Завершённая | ❌ (паритет с [UX-B6]) | ❌ |

## 4. Сценарии использования

**С1 · Добавить подход к упражнению с записями**
Активная тренировка → плитка «Жим штанги лёжа» (3 записи) → тап по пилюле под третьей
записью → модалка «Новая запись» (вес 85 подставлен) → «➕ Добавить» → запись появилась
под пилюлей, пилюля уехала ниже списка. 1 тап + 1 тап сохранения (как было).

**С2 · Первый подход в только что добавленном упражнении**
«➕ Добавить упражнение» → пикер → выбрано «Разведение гантелей» → плитка с пустым
списком: шапка (название + 🗑) и сразу пилюля «+ Добавить подход» → тап → модалка →
первая запись. Раньше тот же путь шёл через «+» в шапке — количество тапов не меняется.

**С3 · Карточка с несколькими упражнениями**
3 упражнения → пилюля **у каждой плитки** (под своим списком). Добавление подхода
всегда адресовано конкретному упражнению, контекст виден по положению пилюли.

**С4 · Текущее упражнение (идёт запись)**
У плитки с `CUR`: подходы → пилюля → «упражнение активно — время идёт». Пилюля читается
как «продолжить запись сюда», плашка — как статус. Порядок владелец задал дословно.

**С5 · Завершённая тренировка** — пилюль нет, только просмотр (без изменений).

**С6 · Онбординг, шаг 2 туториала [ONB-T4]**
Подсветка «точка ввода подхода» переезжает с «+» в шапке **на пилюлю** первого
упражнения (`spot.wrap.box` внутри пилюли, механика ред. 5 сохраняется — подсветка
вложена в реальный элемент). Текст шага 2 онбординга («тонкий плюсик в шапке
упражнения») требует синхронной правки текста/макета ONB (см. §8).

## 5. Визуальная спецификация пилюли

Класс-предложение: **`.ex-addset`**. Тёмная тема (значения дизайн-системы Amber Glass,
`web/style.css`); светлая — теми же токенами (все переменные двухтемные).

| Свойство | Пилюля «+ Добавить подход» (новая) | «➕ Добавить упражнение» (эталон) |
|---|---|---|
| Класс | `.ex-addset` | `.btn.sec.wide` |
| Ширина | `100%` внутри плитки | `100%` на карточке |
| Фон | `var(--nested)` — `rgba(0,0,0,.18)`, темнее карточки (инсет) | `var(--btn)` — `rgba(255,255,255,.07)`, светлее карточки |
| Рамка | `1px solid var(--nested-brd)` — `rgba(255,255,255,.05)` | `1px solid var(--btn-brd)` — `rgba(255,255,255,.08)` |
| Радиус | `999px` (стадион — «пилюля») | `14px` |
| Паддинг | `4px 12px` | `9px 14px` |
| **Высота** | **≈26px** (~60% от эталона, −40%) | **≈40px** |
| Шрифт | `12px / 600` | `14px / 600` |
| Цвет текста | `var(--muted)` `#9aa0aa` | `var(--text)` `#f2f3f5` |
| Иконка | `ICONS.plusThin` 14px, `var(--muted)` — тонкий «+» из иконок продукта | эмодзи ➕ |
| Отступ сверху | `margin: 8px 0 0` (после записей) | `.btnrow` `margin-top: 8px` |
| `:active` | фон `var(--btn-pressed)`, цвет `var(--text)`, `scale(.985)` | `brightness(1.05)` / `scale(.97)` |
| Янтарь | **нет** — ни рамка, ни текст, ни фон | нет, но кнопка в 2 «ступени» ярче |

**Ключ иерархии** (заметно скромнее, как просил владелец): темнее фон (инсет vs выпуклое
стекло), тише рамка, приглушённый текст вместо белого, шрифт −2px, высота −40%,
тонкий монохромный «+» вместо цветного эмодзи ➕. При беглом взгляде карточки глаз
читает «Добавить упражнение» как главное действие, пилюли — как второстепенные точки
ввода. Сравнение вживую — секция «Анатомия и иерархия» макета.

**Зона тапа:** видимая высота ~26px < рекомендованных 44px. Компенсация (рекомендовано
coder'у): `.ex-addset { position: relative }` + невидимый хит-слой
`.ex-addset::after { content:''; position:absolute; inset:-8px -6px }` — фактическая
зона ≈42px. `inset` сверху/снизу не превышает межблочные отступы (8px до записей,
4px до restline), кликабельность соседей не съедает (restline некликабельна).

**Название на кнопке:** «+ Добавить подход», где «+» — тонкая SVG-иконка
(`ICONS.plusThin`, уже есть в иконках продукта), не эмодзи ➕: эмодзи цветастый и громкий,
противоречит требованию «не ярче».

## 6. Edge-кейсы

### 6.1 Пустая плитка (0 подходов) — главный проверенный риск из issue

Установлено: упражнение создаётся с `sets: []` (`app.js:408`; шаблоны — `app.js:2760`),
и раньше первый подход добавлялся **только** через «+» в шапке. Значит при удалении «+»
пилюля **обязана рендериться и при 0 подходов** — иначе упражнение станет тупиком.
Пилюля наследует роль «+» 1:1, путь добавления первого подхода не удлиняется.
Подсказки «Подходов пока нет» НЕ вводим (см. §9) — пустой список говорит сам за себя,
обучает онбординг (шаг 2).

### 6.2 Несколько упражнений

Пилюля у **каждой** плитки активной тренировки (паритет с прежним «+», который тоже был
у каждой). Альтернатива «одна общая пилюля на карточку» отклонена: непонятно, к какому
упражнению добавится подход (нужен был бы ещё шаг выбора), для нижних упражнений длиннее
рука, ломается паттерн «точка ввода замыкает список».

### 6.3 Текущее упражнение (CUR)

Пилюля над `.restline`, обе видны одновременно; не взаимозаменяемы (действие vs статус).

### 6.4 Drag&drop плитки

Пилюля — `<button>` внутри `.expill`: существующий guard `app.js:1731` (drag игнорирует
`button`) покрывает её автоматически. Long-press по пилюле не поднимает плитку, тап не
конфликтует. Изменений drag-логики не требуется.

### 6.5 Модалка уже открыта / завершение тренировки

Без изменений: `openEntryModal` сам защищает завершённую тренировку ([UX-B6], тост
«Тренировка завершена — доступен просмотр»); после завершения пилюля исчезает рендером.

### 6.6 Онбординг-подсветка без активной тренировки

Логика пропуска шага 2 (нет активной/упражнений — «Дальше») не меняется; меняется только
элемент-носитель подсветки (см. §8).

## 8. Что НЕ делаем и почему

| Отсечено | Почему |
|---|---|
| Мгновенное добавление подхода тапом (без модалки) | Ломает паттерн ввода (вес/повторения всё равно нужны); риск дублей при случайном тапе; сценарий «повторить прошлый подход» уже закрыт пилюлей плана и подстановкой веса [UX-T12] внутри модалки. Вынесено открытым вопросом владельцу (§10.1) |
| Одна общая пилюля «+ Добавить подход» на карточку | Не адресована упражнению; нужен шаг выбора цели; длиннее путь для нижних упражнений (§6.2) |
| Пилюля с янтарной рамкой/текстом (стиль `.prevpill`) | Владелец: «не ярче, чем Добавить упражнение» — янтарь сделал бы её громче обеих; плюс янтарь зарезервирован под рекорды/подсказки |
| Яркая крупная кнопка в стиле `.btn.sec` на всю ширину | Дублировала бы «Добавить упражнение» — иерархия пропала, карточка раздувается |
| Подсказка-плейсхолдер «Подходов пока нет» в пустой плитке | Лишний шум; пилюля сама приглашение; обучает онбординг (§6.1) |
| Изменения потока бота (кнопки «➕ Добавить запись» и пр.) | Идея владельца — только про экран Mini App; бот не трогаем |
| Убирать 🗑 из шапки / двигать шапку | Вне скоупа; жалоба владельца только про «+» |
