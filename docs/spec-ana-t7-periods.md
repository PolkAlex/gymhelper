## 1. Цель и пользовательская проблема

Вкладка «Статистика» отвечает на вопрос «как мои дела?» — но каждый её блок молча
зафиксирован на своём окне: «Рекорды недели» — только Пн–Вс, «Мышечные группы ·
эта неделя» — неделя, «Серия» — 30 дней, сводка «Тренировки» — всего и «в этом
месяце». Пользователь не может спросить «а как у меня было за квартал / за год /
за всё время?» — и не понимает, к какому окну относится каждая цифра.

**Решение в одном абзаце:** пикер периода вверху вкладки — горизонтальный ряд
пилюль «Неделя · Месяц · 3 месяца · Полгода · Год · Всё время» (лейбл «3 месяца» —
решение владельца 20.11.2026). Период влияет на
**всю вкладку** (решение владельца 19.11.2026), кроме двух осознанных исключений —
«Оценка 1ПМ · Эпли» и блока «Цели» (§5.2: это «рекорды вообще», периоду не
подчиняются). Плюс новая метрика **«среднее время тренировки»** за выбранный
период в карточке «Тренировки».

Не-цели: бэкенд, бот `/stats` и формат данных не трогаем — все периоды считаются
из уже загруженного `G.workouts` на клиенте (данных мало: десятки тренировок,
фильтрация по дате мгновенна). **Нижняя навигация, FAB и топбар — НЕ изменяются**
(решение владельца 20.11.2026: «не трогать вообще»); на макете они не изображаются.

## 2. Пикер периода

### 2.1. Вид и место

**Выбрано: горизонтальный ряд пилюль (`.chip`-стиль, как «Таймер отдыха» и
фильтры каталога) с горизонтальным скроллом**, первой строкой вкладки, над
«Рекордами периода».

| Вариант | Вердикт | Почему |
|---|---|---|
| Пилюли + h-скролл | ✅ | стиль уже в приложении (чипы); каждый период в один тап; 6 значений видно сразу/почти сразу; кода минимум |
| Сегмент-контрол `.seg` | ❌ | 6 сегментов на 320px = по ~50px на кнопку; подписи («Полгода», «Всё время») не влезают без сокращений («Пол-года», «Всё»), а сокращения — новая система обозначений |
| Dropdown (нижний лист, как пикер вида в Календаре `calPickerHtml`) | ❌ | период на Статистике меняется чаще и «прикидкой» (тапнул — посмотрел — тапнул другое); лист = 2 тапа на смену вместо 1; на Календаре лист оправдан редкой сменой вида, здесь — нет |
| Sticky-пикер (прилипает к topbar при скролле) | ❌ (v1) | вкладка длинная и прилипание соблазнительно, но topbar-зона уже источала баг перекрытия ([UX-B10]); отложим до фидбэка — §9 |

Скролл: `overflow-x: auto` без переноса (`flex-wrap: nowrap`), `scrollbar-width:
none` (как в других местах приложения); активная пилюля `.chip.on` (янтарная).
При ширине 320px ряд скроллится — активная пилюля должна быть в пределах видимой
области при каждом рендере (при смене периода — `scrollLeft` к активной; при
открытии вкладки — к «Месяц», она вторая слева и видна без скролла даже на 320px).

### 2.2. Значения и дефолт

| Ключ | Пилюля | Дефолт |
|---|---|---|
| `week` | Неделя | |
| `month` | **Месяц** | ✅ (предложение владельца; компромисс между «неделей»-шумом и «годом»-далёкостью) |
| `quarter` | 3 месяца (лейбл «3 месяца» — решение владельца 20.11.2026; прежний «Квартал») | |
| `half` | Полгода | |
| `year` | Год | |
| `all` | Всё время | |

### 2.3. Хранение выбора

Переменная в памяти сессии (`STATS.period = 'month'`), как состояние подэкранов
(`TECH`, `CAL.panel`). **Не** localStorage и **не** `GymData`:
- выбор статистики — «прикидка на один взгляд», а не настройка; после переоткрытия
  Mini App честный дефолт «Месяц» уместнее прошлого выбора;
- не трогаем бэкенд и формат данных (ограничение задачи).

Смена периода = перерасчёт и рендер вкладки, `save()` НЕ нужен (данные не менялись),
скролл окна сохраняется как есть (пользователь чаще всего стоит вверху).

## 3. Семантика периодов: календарные vs скользящие

**Рекомендация: календарные периоды** (кроме «Полгода» — гибрид, §3.1).

Обоснование:
1. **«Неделя» в приложении уже трактуется как Пн–Вс** — `weekRecords`,
   `weekMuscleGroups`, недельный вид календаря [UX-I17]. Скользящие «последние
   7 дней» разъехались бы с этим значением на той же вкладке.
2. **«Месяц» уже существует в интерфейсе** как «в этом месяце» (сводка «Тренировки»,
   бот `/stats`). Календарный месяц сохраняет совпадение текстов и цифр.
3. Календарные границы («с 1-го числа», «с начала квартала», «с 1 января»)
   объяснимы одним словом, скользящие требуют оговорки «последние 30 дней» — и
   их числа нельзя сверить с календарём или целью («к концу квартала»).
4. Дневник тренировок живёт рядом с целями [GOA] со сроками «до конца квартала» —
   календарный квартал в статистике рифмуется с этим.

### 3.1. Таблица периодов (верхняя граница всегда «сегодня» включительно; только `finished`)

| Ключ | Нижняя граница | Подпись-заголовок (§5) |
|---|---|---|
| `week` | понедельник текущей недели (как `weekRecords`: `date - ((day+6)%7)`) | «эта неделя» / «Рекорды недели» |
| `month` | 1-е число текущего месяца | «этот месяц» / «Рекорды месяца» |
| `quarter` | 1-е число месяца квартала (янв/апр/июл/окт) | «этот квартал» / «Рекорды квартала» |
| `half` | 1-е число, отстоящее на 5 месяцев назад от текущего (19.11.2026 → 1 июня 2026) | «последние 6 месяцев» / «Рекорды за 6 мес.» |
| `year` | 1 января текущего года | «этот год» / «Рекорды года» |
| `all` | без границы (вся история) | «за всё время» / «Рекорды» |

> ✅ **«Полгода» — УТВЕРЖДЕНО владельцем (19.11.2026):** гибрид «последние
> 6 календарных месяцев (с 1-го числа, 5 месяцев назад)». Отсечены: чистое
> календарное полугодие (1 янв / 1 июл — стагнация внутри цикла, декабрьское
> «янв–июнь» наполовину мёртвое) и скользящие 182 дня (рвёт связь с сеткой
> месяцев и остальными периодами).

Сравнение тренировки по дате — по `w.date` (ISO `YYYY-MM-DD`), как во всех
существующих фильтрах (`weekRecords`, `monthStreak`); `durationMin` в среднее
входит по той же дате-принадлежности.

## 4. Новая метрика: «среднее время тренировки»

### 4.1. Формула

```
avgMin = Σ durationMin(w) по тренировкам периода, где durationMin(w) != null
         ÷ число таких тренировок
```

- `durationMin` — существующая функция (`started → ended|now`, мин, округление;
  `null` если `started` не зафиксирован). **Новых источников времени не заводим:**
  тренировки без `started` (ретро-ввод через «⏱ Время» всегда его ставит, но
  legacy-записи могут не иметь) в среднее не попадают и из знаменателя исключены.
- Округление — как в `durationMin` (до минуты), один раз, на итоговой сумме/счёте:
  `Math.round(sumMin / cnt)`.
- Знаменатель = 0 (ни одной тренировки с длительностью за период) → **ячейка не
  показывается** (тот же приём, что `totalMin > 0` у «общего времени» сейчас).

### 4.2. Формат

`durationText(avgMin)` — существующий формат приложения («1 ч 20 м», «45 м»,
«2 ч»), префикс «≈» как у других оценок (Эпли: «≈ 82 кг»). Итог: **«≈ 1 ч 20 м»**.
(В формулировке задачи был «~1 ч 20 мин»; в приложении везде `durationText` с
«м» и «≈» — берём его, чтобы не плодить третий формат времени. Вопрос снят
в пользу консистентности.)

## 5. Поведение каждого блока за период

Порядок блоков НЕ меняется ([GOA-S1]: подсказка цели + виджет «Цели» — сразу
после Эпли; это святое). Меняется только источник данных периодных блоков.

### 5.1. Периодные (пересчитываются от пикера)

| Блок | Было | Стало |
|---|---|---|
| **Рекорды** (×3 карточки) | «Рекорды недели · Жим…» — топ-3 упражнения недели по макс. весу подхода | **Да, переименовать:** «Рекорды · <период>» в заголовке каждой карточки: «Рекорды месяца · Жим лёжа». Топ-3 упражнения периода по макс. весу подхода. Шкала «% от личного рекорда» остаётся **по всей истории** (иначе при «Всё время» всегда 100%, а на коротких периодах проценты теряют смысл); подпись «личный рекорд: X кг» — без изменений |
| **Серия** | `monthStreak` — самая длинная череда дней за последние 30 дней | Стрик ищется **в пределах периода**; подпись динамическая: «самая длинная за месяц» → «за квартал / за 6 месяцев / за год / за всё время». Стрики, пересекающие границу периода, режутся границей (это честно: карточка описывает период). Порог показа `days.length >= 2` — как сейчас |
| **Мышечные группы** | «Мышечные группы · эта неделя» — подходы Пн–Вс | Подходы за период; заголовок «Мышечные группы · <подпись периода из §3.1>» («этот месяц», «этот квартал»…). Сортировка по подходам, топ без лимита — как сейчас |
| **Тренировки (сводка)** | «тренировок всего / в этом месяце / общее время / подходов всего» | 4 ячейки за период: **«N · за <период>»** («за месяц», «за всё время»…), **«≈ X · средняя»** (новая, §4), **«X · общее время»**, **«N · подходов»**. См. §5.3 про судьбу «в этом месяце» |
| **Тренды** | топ-5 упражнений по числу занятий за всю историю, «последний результат» | топ-5 упражнений **периода** (по числу занятий в периоде); «последний результат» = последний подход **в пределах периода** (упражнение без подходов в периоде просто не попадает в список) |
| **Упражнения** | топ-15 за всю историю: «(N раз.)», рекорд веса, последний | топ-15 **периода**: «(N раз.)» = занятий в периоде, «Рекорд веса» = максимум подхода **в периоде**, «Последний: …» = последняя запись **в периоде** (дата рядом — как сейчас, из `lastDate`) |

### 5.2. Вне периода (осознанные исключения — НЕ фильтруются)

| Блок | Почему вне периода |
|---|---|
| **Оценка 1ПМ · Эпли** | e1RM — монотонная оценка **текущей** силы («какой у меня сейчас рабочий максимум»), эталон целей [GOA]. Периодная фильтрация превратила бы её в «оценку на момент внутри периода»: неделя из лёгких подсобок перетасовала бы топ-5 и испугала пользователя падением «≈». Карточка не меняется совсем |
| **Подсказка цели + виджет «Цели»** | Цели считаются от всей истории (`goalMaxE1rm`), прогресс монотонный, % не должен падать от смены пикера; подсказка «💡 Попробуйте цель» — производная того же агрегата. Положение после Эпли закреплено решением 12.11 ([GOA-S1] §7) |

Решение владельца «пикер влияет на ВСЮ вкладку» (19.11) здесь уточняется: влияет
на все **периодные** блоки; два блока-«рекорда вообще» документированно исключены.
Задача поручала дизайнеру решить этот вопрос — решено и обосновано выше; в
интерфейсе признака «вне периода» НЕ добавляем (лишний шум, §9), поведение
проверяется на e2e (§7).

### 5.3. Судьба «в этом месяце» в сводке

Ячейка «в этом месяце» **заменяется** периодной «за <период>»: при пикере «Месяц»
это одно и то же число (дубль убран), при остальных периодах периодная ячейка
полезнее. «Тренировок всего» в чистом виде остаётся доступным — пикер «Всё время».
✅ УТВЕРЖДЕНО владельцем (19.11.2026): сводка = **ровно 4 ячейки** за период;
постоянной ячейки «в этом месяце» нет — она заменяется периодной.

## 6. Пустые состояния

| Ситуация | Что видит пользователь |
|---|---|
| **Истории нет вообще** (0 `finished`) | Как сейчас: hero «Пока пусто 💪» с кнопкой старта. **Пикер не показывается** — выбирать период не из чего |
| **Период пуст, история есть** (например «Неделя» в воскресенье до первой тренировки недели) | Пикер остаётся (это главный орган навигации — им же пользователь уходит из пустоты). Под ним одна карточка-заглушка: «📭 За эту неделю тренировок нет» + muted «Выбери другой период — вся история на месте». Все периодные блоки скрыты (карточки не рендерятся, как сейчас скрыта Эпли без весов); **Эпли и Цели остаются** — они вне периода (§5.2) |
| **Период непустой, но в нём нет тренировок с длительностью** | Ячейка «средняя» скрыта (§4.1); «общее время» — по существующему правилу `totalMin > 0` |
| **Период непустой, но нет подходов с весом** | «Рекорды периода» не рендерятся (как сейчас `weekRecords(3)` может вернуть пусто); Эпли не рендерится — существующее правило `rows.length == 0` |
| **Серия из 1 дня / без данных** | Карточка не показывается (порог `>= 2` — как сейчас) |

## 7. Чек-лист кодера и e2e

- [ ] `STATS = { period: 'month' }` в памяти; ACTIONS `statsPeriod` (валидация ключа
  из §3.1, неизвестный — тихий игнор, остаётся предыдущий)
- [ ] Хелперы границ: `periodRange(p)` → `{ from: Date|null }` (верхняя — «сегодня»,
  фильтр `d <= today` неявно выполнен: будущих дат нет); недельная граница — формула
  `weekRecords` (Пн), «Полгода» — §3.1
- [ ] `weekRecords(limit, range)`, `monthStreak(range)`, `weekMuscleGroups(range)` —
  параметр-граница вместо жёсткой недели/30 дней (дефолт параметра = старое
  поведение, чтобы не сломать прочие вызовы, если есть)
- [ ] `renderStatsTab()`: пикер-разметка; ветка пустого периода (§6); сводка с
  «средней»; динамические заголовки «Рекорды · …», «Мышечные группы · …», подпись
  серии; `byEx` строится один раз по периодному фильтру (им питаются Тренды и
  Упражнения)
- [ ] Эпли, `goalHintCardHtml`, `goalsWidgetHtml` — вызовы без изменений (§5.2)
- [ ] Пилюли: активная в видимой области (§2.1); aria-label пикера «Период статистики»
- [ ] `node --check web/app.js`; e2e:
  1. Открыть Статистику с историей в двух месяцах → дефолт «Месяц»: сводка = числам
     текущего месяца, «≈ …» присутствует, Эпли = по всей истории
  2. Тап «3 месяца» → заголовки рекордов/мышц сменились, цифры пересчитались, Эпли
     и Цели не изменились
  3. «Всё время» → сводка совпадает со старой логикой «всего» (+ средняя)
  4. Период без тренировок → заглушка, периодные карточки скрыты, Цели на месте
  5. Все тренировки без `started` в периоде → ячейка «средняя» отсутствует
  6. 320px: пикер скроллится, активная пилюля видна

## 9. Что НЕ делаем и почему

| Отсечено | Почему |
|---|---|
