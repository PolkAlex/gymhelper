## 1. Цель и пользовательская проблема

В профиле возраст хранится статическим числом (`profile.age`). Через год после ввода он
врёт на единицу, через пять — на пять; никто не возвращается в настройки обновлять цифру.
При этом возраст входит в BMR (Mifflin-St Jeor), который показывается в Профиле и в боте.

**Решение**: хранить **год и месяц рождения** — возраст вычисляется динамически и
сам обновляется в расчётах. День рождения **не собираем** (приватность: год+месяц
достаточны для расчётов, точный день нужен только для поздравления — см. §5).

Дополнительно (из идеи): мягкий бейдж «день рождения в этом месяце» — без пушей и
навязчивости.

## 2. Модель данных и миграция (ядро решения)

### 2.1 Формат ProfileData

```json
{"sex":"м","age":36,"height":178,"weight":78.5,"birthYear":1990,"birthMonth":11}
```

| Поле | Тип | Значение | Правило |
|---|---|---|---|
| `sex` | строка | `м`/`ж` | без изменений |
| `age` | int | **зеркало** | совместимость: пишется всегда; при валидной дате = вычисленный возраст, при её отсутствии — как раньше |
| `height`, `weight` | как было | — | без изменений |
| `birthYear` | int | 1990 | **0 = не указан**; ключ в JSON пишется только когда оба birth-поля валидны |
| `birthMonth` | int | 1–12 | 0 = не указан; парное к `birthYear` |

Правило «оба-или-ничего»: `birthYear>0` и `birthMonth` 1–12 существуют **только вместе**.
Читатель, встретив одно без другого (или мусор), считает дату не указанной.

### 2.2 Семантика «единого источника»

- Если `birthYear` валиден (1900–2100 при чтении) → **возраст ВСЕГДА вычисляется**
  из даты; поле `age` читателями с поддержкой даты игнорируется.
- `age`-зеркало нужно только старым читателям (старый jar на VPS в окно деплоя,
  старый кэш JS у пользователя) — они продолжают показывать числом, как сейчас.
- Зеркало может «протухнуть» (прошёл год, никто не сохранял) — поэтому **bmr обязан
  использовать вычисленный возраст**, а не `p.age`, если дата задана (см. §3).

### 2.3 Вычисление возраста

Возраст наступает **1-го числа месяца рождения** (день не хранится):

```
age = текущийГод − birthYear − (текущийМесяц < birthMonth ? 1 : 0)
```

Веб и бот считают по одному правилу → значения совпадают. Пример: 1990-11 в
ноябре 2026 → 36 лет.

### 2.4 Чтение (`GymData.fromJson`, блок profile)

```java
p.birthYear  = (int) Json.lng(pm.get("birthYear"));
p.birthMonth = (int) Json.lng(pm.get("birthMonth"));
/* мусор → «не указано»; границы чтения толерантнее границ ввода (§2.6) */
if (p.birthYear < 1900 || p.birthYear > 2100) p.birthYear = 0;
if (p.birthMonth < 1 || p.birthMonth > 12) p.birthMonth = 0;
if (p.birthYear == 0 || p.birthMonth == 0) { p.birthYear = 0; p.birthMonth = 0; }
```

Старый файл без ключей → 0/0 → «не указано», читается как сейчас (паттерн restSec/templates).

### 2.5 Запись (`GymData.toJson`, блок profile)

```java
pm.put("sex", ...); pm.put("age", ...); pm.put("height", ...); pm.put("weight", ...);
/* ключи в конце карты — старые файлы без даты остаются байт-в-байт прежними */
if (profile.birthYear > 0 && profile.birthMonth >= 1 && profile.birthMonth <= 12) {
    pm.put("birthYear", profile.birthYear);
    pm.put("birthMonth", profile.birthMonth);
}
```

**Кто пишет age-зеркало**: тот, кто сохраняет профиль (web `saveProfile`, бот
`handleProfileInput`), ставит `age = вычисленный`, если дата валидна. Сервер
(`/api/save`) — не редактор: зеркала не пересчитывает, что пришло, то пишет.

### 2.6 Границы ввода (писатель)

| Поле | Допустимо при вводе | Ошибка |
|---|---|---|
| Год рождения | вычисленный возраст ∈ **5–100** → для 2026: 1930…2021; жёсткий пол ввода: **1930** (реалистично) | в UI невозможна (select содержит только допустимые годы); защита на сервере и в боте: «Проверь год рождения» |
| Месяц | 1–12 (select — невалидный невозможен) | — |
| Возраст (бот, legacy-режим) | **5–100** [I8-update 09.11: было 10–100 — минимум снижен владельцем] | «Проверь значения: возраст 5–100…» |

Диапазон года — **динамический**: верх = текущий год − **5**, низ = max(1930, текущий − 100)
(например в 2026: max(1930, 1926) = 1930, верх 2021; в 2031 низ поднимется до 1931).
Список годов в select — ровно этот диапазон по убыванию. Сообщение об ошибке бота
показывает диапазон текстом. **[I8-update 09.11]**: минимальный возраст **5 лет** (было 10).

### 2.7 Миграция старых профилей — НЕ молча

Тикет прямо требует: «миграцию старых age не делать молча — попросить дату рождения
при следующем редактировании профиля». Правила:

- Профиль с одним `age` **читается и работает как сейчас** — возраст из `age`, никаких
  автоподстановок «примерного года».
- В Mini App карточка «Дата рождения» у такого пользователя пустая, с заметной
  подсказкой-плашкой: «Укажи год и месяц — возраст станет обновляться сам» (§4.4).
- Сохранение **не блокируется**: пользователь может обновить вес, не указывая дату
  («попросить», а не «заставить»). Подсказка остаётся до заполнения.
- Исключение — **новый профиль** (у новичка нет прежнего `age`): дата рождения
  обязательна, иначе BMR невозможен (§4.6).
- Бот в age-режиме работает как раньше (§6) — пользователи бота без Mini App не
  принуждаются.

### 2.8 Матрица совместимости (читатель × файл)

| Файл \ Читатель | Старый jar / кэш JS (до фичи) | Новый jar / новый JS |
|---|---|---|
| без profile | ок | ок («Нужен для расчёта калорий 🔥») |
| `profile` только age | ок (как сейчас) | ок: возраст = age + подсказка миграции в форме |
| `profile` + birthYear/birthMonth | ок: показывает age-зеркало числом | ок: возраст = вычисленный |

### 2.9 Серверный merge — защита от старого кэша JS

`WebServer` заменяет профиль целиком: `if (data.profile != null) current.profile = data.profile;`
Старый клиент строит profile без birth-ключей → **дата потерялась бы** при любом его
сохранении. Добавить перенос (аналог существующего паттерна «старый кэш JS — не трогаем»
для `templates`):

```java
if (data.profile != null) {
    /* [UX-I8] клиент без поддержки даты (старый кэш JS) не теряет birthYear/birthMonth */
    if (data.profile.birthYear == 0 && current.profile != null && current.profile.birthYear > 0) {
        data.profile.birthYear = current.profile.birthYear;
        data.profile.birthMonth = current.profile.birthMonth;
    }
    current.profile = data.profile;
}
```

Бот читает/пишет полную модель GymData — потерь нет при одном условии: `handleProfileInput`
должен **переносить birth-поля из загруженной модели**, а не строить `new ProfileData()`
с нуля (см. чек-лист §10).

### 2.10 GymContractTest — контракт не ломается

Существующие ассерты остаются (фикстура `age:31` без birth-ключей — читается как сейчас).
Добавить кейсы:
- legacy-файл без birth-ключей: читается; `toJson` **не пишет** ключи `birth*` (байт-в-байт);
- файл с датой: читается (`birthYear`/`birthMonth`); round-trip без потерь;
- мусор: `birthMonth:13`, `birthYear:1800`, `birthYear` строкой → «не указано»;
- полуфабрикат: `birthYear:1990` без `birthMonth` → оба 0;
- age-зеркало: профиль с датой сохраняется сервером от старого клиента (save без birth-ключей
  при существующей дате) → дата переживает merge (§2.9, через реальный WebServer как в
  resurrect-тесте).

## 3. Возраст в расчётах

- **BMR** (Mifflin-St Jeor) — единственное место, где возраст участвует в формулах
  (web `bmr()` стр. ~225, `BotLogic.bmr()`). Обе функции заменить `p.age` → `ageOf(p)`,
  где `ageOf` = вычисленный при валидной дате, иначе `p.age`. Иначе 1 января у всех
  носителей даты BMR врал бы до следующего сохранения.
- **Ккал за тренировку** (`calcWorkoutKcal`, MET-модель) возраст **не использует** — только
  вес. Фича на неё не влияет (проверено по коду).
- **Склонения**: сейчас саммари пишет «31 лет» — всегда «лет». Ввести `ageWord(n)`:
  год (1, 21, 31…), года (2–4, 22–24…), лет (5–20, 11–14, 26–30…). В боте уже есть
  `BotLogic.plural` — использовать `plural(n, "год", "года", "лет")`.

## 4. Mini App: экран «Профиль»

### 4.1 Карточка «Дата рождения» (новая, между «Пол» и карточкой рост/вес)

```
┌──────────────────────────────────────────┐
│ Дата рождения                            │  ← .flabel (11px, как у prow-полей)
│ ┌Год рождения┐┌Месяц рождения────────┐  │
│ │ [ 1990 ▼ ] ││ [ Ноябрь       ▼ ]   │  │  ← два <select> в ряд, стиль .prow .pf
│ └────────────┘└──────────────────────┘  │
│ Возраст: 36 лет                          │  ← живая строка (обе даты выбраны)
│ Возраст пересчитается сам · день не нужен│  ← .meta
│ Хранится с дневником; политика — в ⚙️    │  ← .meta, ссылка на Настройки (§7)
└──────────────────────────────────────────┘
```

**[I8-update 09.11]** — решение владельца: макет v1 (текстовый год + чипы месяцев) НЕ
одобрен. Ввод года и месяца — **два нативных `<select>` в один ряд**, в точности в
стилистике полей «Рост, см / Вес, кг» (`.prow .pf`): лейбл 11px над полем, тёмная заливка
`--field`, рамка `--fieldbrd`, скругление 12px, **та же высота, что у prow-полей**
(40px в проде; референс-скрин владельца: «Рост, см» и «Вес, кг» бок о бок). Тап по
select открывает системный пикер — быстро и знакомо на мобиле.

- **Год рождения** (`#pfBirthYear`): опции генерируются динамически — от `текущий − 5`
  вниз до 1930, **по убыванию (свежие годы сверху)**; в 2026 это 2021…1930 = 92 опции.
  Плейсхолдер-опция **«—»** (value="") = состояние «не указано».
- **Месяц рождения** (`#pfBirthMonth`): полные имена **«Январь … Декабрь»** (в системном
  пикере полные имена читаются лучше сокращений). Плейсхолдер-опция **«Выбрать…»** (value="").
- Стиль select: `appearance: none` + шеврон-стрелка (SVG в фоне справа, цвет `--muted`);
  выравнивание текста — по центру, как у prow-полей (если webview не поддерживает
  `text-align` у select — допустимо влево, не критично). Плейсхолдерное состояние —
  текст цвета `--muted` (класс `.ph`); подсветка ошибки частичного ввода — `.err`
  (рамка `--danger`).
- Живая строка возраста: при выбранных годе+месяце — «Возраст: 36 лет» (склонения §3),
  обновляется на событии `change` любого select, **до сохранения** (сразу видно
  следствие). Неполная пара → строка скрыта.
- Разметка: `.brow` — flex-ряд из двух `.bf`, каждый `flex: 1` (равная ширина, как два
  поля prow); на 320px поля сжимаются, лейблы `nowrap` (эталон: prow).

### 4.2 Карточка рост/вес (существующая `.prow`) — БЕЗ поля «Возраст»

```
Рост, см  [ 178 ]   Вес, кг  [ 78,5 ]   [ 💾 Сохранить ]
```

Поле «Возраст» **удаляется** (замена, не дублирование: два редактируемых источника
возраста = конфликт). На 390px ряд влезает свободнее, чем сейчас (было 3 поля).

### 4.3 Саммари-карточка «Профиль»

- Дата указана: `М · 36 лет · 178 см · 78,5 кг` (возраст вычисленный, склонения §3),
  `BMR ≈ 1723 ккал/сут (Mifflin-St Jeor)`.
- Только age: `М · 31 год · 190 см · 95 кг` — как сейчас, но со склонениями.
- Бейдж дня рождения — см. §5.

### 4.4 Состояние «не указано» (legacy age-only)

- Карточка даты: оба select в плейсхолдерном состоянии («—» / «Выбрать…»), живой возраст скрыт.
- Плашка-подсказка внутри карточки ( `.hint`, янтарный тинт `--glow`, иконка 🎂 или ℹ️):
  «Укажи год и месяц рождения — возраст станет обновляться сам». Пропадает после
  заполнения (рендер по факту валидной пары).
- Сохранение без даты разрешено: профиль пишется с прежним `age`, birth-ключи не пишутся.
- Для **нового профиля** (G.profile пуст) дата обязательна: тост
  «Укажи год и месяц рождения — они нужны для расчёта калорий», сохранение отменено (§4.6).

### 4.5 Валидация при сохранении (порядок проверок)

1. Пол — как сейчас (`profileSex || 'м'`).
2. Дата: если оба select на плейсхолдере («—»/«Выбрать…») → пропуск шага (legacy-режим,
   см. §4.4); если выбрано только одно из двух → тост «Укажи и год, и месяц — или выбери
   „—“ в обоих полях», оба select подсвечены `.err`; если пара выбрана — нарушение
   диапазона невозможно (select содержит только допустимые годы, §2.6); защитная проверка
   возраста **5–100** остаётся в боте и на сервере (тост «Проверь год рождения:
   1930–2021», диапазон динамический: `${max(1930, текущий−100)}–${текущий−5}`).
3. Рост/вес — как сейчас (тост «Проверь значения: рост 100–250, вес 30–300» — слово
   «возраст 10–100» из старого тоста убирается).
4. Успех: `G.profile` получает birth-поля и `age`-зеркало; тост «✓ Профиль сохранён».

Частичный ввод (год выбран, месяц «—» — или наоборот) блокирует сохранение — это
ошибка формы, а не легитимное «не указано». Вернуться к «не указано» можно только
сбросом **обоих** select на плейсхолдер.

### 4.6 Edge-кейсы Mini App

| Кейс | Поведение |
|---|---|
| Новый пользователь, сохранил без даты | Тост-ошибка, профиль не пишется (§4.4) |
| Год `2021` (возраст 5) | Валидно: первая опция списка — минимум **5 лет** [I8-update 09.11: было 10] |
| Год `1930` (возраст 96) | Валидно: последняя опция списка (пол 1930) |
| Год вне списка (`1850`, `2024`…) | Невозможно в UI (select); мусор из старых данных/бота санитизируется при чтении (§2.4) |
| `29 февраля` | Не проблема — день не хранится |
| 31.12→01.01, смена года | Возраст +1 сам (правило 1-го числа месяца) |
| Старый кэш JS сохраняет профиль | Серверный merge переносит birth-поля (§2.9) |
| Два устройства | Обычная модель rev/save: кто последний сохранил профиль, тот и записал дату |
| 320px | Два select в ряд сжимаются `flex: 1`, лейблы `nowrap`; вертикальный рост карточки — ок (эталон: prow) |
| Пол не выбран у новичка | Дефолт `м` — как сейчас, не менялось |

## 5. День рождения: мягкий бейдж (без пушей)

### 5.1 Проблема требования

Просили «поздравление в день рождения», но день **не хранится** (приватность — главное
решение идеи). Без дня «в день рождения» невозможен.

### 5.2 Решение v1: бейдж месяца рождения (внедряется этой фичей)

- В **месяце рождения** в саммари-карточке Профиля появляется строка-бейдж:
  `🎂 Твой день рождения в этом месяце` (`.bdg`: янтарный тинт `rgba(255,194,32,.12)`,
  рамка `--glow-brd`, текст `--accent`, радиус 999px).
- Показывается **только**: дата указана + текущий месяц = birthMonth + вкладка «Профиль».
- Не показывается: у legacy (нет даты), вне месяца, в других вкладках.
- Никаких пушей, тостов, сообщений бота — пользователь видит бейдж, когда сам открыл
  Профиль. «Не навязчиво» = максимальная мягкость.
- Бейдж живёт весь месяц (мы не знаем день) — формулировка «в этом месяце», не «сегодня».

### 5.3 Вариант B (отсечён из v1, вынесен владельцу — §13)

Опциональное поле «День» (по желанию, подпись «нужно только для поздравления»):
тогда поздравление точно в день + тост в день открытия приложения. Отложено: добавляет
третье поле в форму ради косметической функции.

## 6. Бот (BotLogic)

Бот — вторичный интерфейс профиля; Mini App остаётся основным. Изменения минимальные,
но данные не теряем.

### 6.1 Ввод: два режима одной строки

Формат остаётся «пол X рост вес», где X распознаётся однозначно:
- **X 5–100** → возраст (legacy-режим; [I8-update 09.11] минимум снижен с 10 до 5);
- **X 1930–текущий год** → год рождения (диапазоны не пересекаются: 100 < 1930); год
  новее «текущий − 5» (возраст < 5) распознаётся как год, но даёт ошибку диапазона;
- вне обоих → ошибка.

Текст-подсказка `/profile` дополняется вторым примером:
```
Введи одной строкой: пол возраст рост вес
Например: м 30 180 82
Можно вместо возраста указать год рождения: м 1990 180 82
```

### 6.2 Диалог год-режима: выбор месяца кнопками

Клавиатура месяцев (3×4 + меню), callback `bm:1`…`bm:12`:

```
Пользователь: м 1990 178 78,5
Бот: 🎂 Год рождения: 1990
     Выбери месяц рождения:
     ┌Янв┐┌Фев┐┌Мар┐┌Апр┐
     ┌Май┐┌Июн┐┌Июл┐┌Авг┐
     ┌Сен┐┌Окт┐┌Ноя┐┌Дек┐
     ┌───🏠 Меню───┘
Пользователь: [Ноя]
Бот: ✅ Профиль сохранён

     Пол: М · Возраст: 36 лет · Рост: 178 см · Вес: 78,5 кг
     BMR ≈ 1723 ккал/сут (Mifflin-St Jeor)

     🎂 Возраст теперь считается по дате рождения и обновляется сам
```

- Между вводом строки и выбором месяца значения (sex, X, height, weight) держатся в
  `UserState` (добавить поля pending-профиля) — `storage.save` только после месяца.
- «🏠 Меню» отменяет выбор (state сбрасывается), профиль не меняется.
- Кнопки месяцев — сокращения «Янв…Дек» (единый словарь с ботом; в Mini App select —
  полные имена месяцев, сокращения остаются только в кнопках бота ради их ширины)
  [I8-update 09.11].

### 6.3 Age-режим при существующей дате (защита данных)

Пользователь с датой посылает «м 30 178 78,5» — введённый возраст **не применяется**
(иначе затёр бы вычисление датой backwards):

- сохраняются sex/height/weight; birthYear/birthMonth **переносятся** из загруженной
  модели; `age`-зеркало = вычисленный;
- ответ:
```
✅ Профиль сохранён

Пол: М · Возраст: 36 лет · Рост: 178 см · Вес: 78,5 кг
BMR ≈ 1723 ккал/сут (Mifflin-St Jeor)

ℹ️ Дата рождения не изменилась — возраст считается по ней (введённый возраст не применён)
```

### 6.4 Ошибки

- X вне 5–100 и вне допустимых годов: «Проверь значения: возраст 5–100 или год рождения
  1930–2021, рост 100–250 см, вес 30–300 кг» (границы годов динамические: низ
  max(1930, текущий−100), верх текущий−5) [I8-update 09.11].
- «Не понял числа» — как сейчас.

### 6.5 profileSummary

`Возраст: N {год/года/лет}` — N из `ageOf` (§3). Дата указана → вычисленный;
нет → прежний `age`. Строка BMR без изменений.

Бот **не показывает** бейдж месяца рождения (вне скоупа; поздравление — только Mini App §5).

## 9. Что НЕ делаем и почему

| Отсечено | Почему |
|---|---|
| Точный день рождения в v1 | Приватность (главная идея тикета); поздравление реализуется бейджем месяца (§5). Точный день — вариант B, опционально и только по явному желанию владельца |
| Пуш/сообщение от бота в день рождения | Навязчиво; требует cron на сервере и отдельной инфраструктуры; против «мягко» |
| Чипы месяцев + текстовый ввод года (макет v1) | Владелец посмотрел макет v1 и НЕ одобрил [I8-update 09.11]: решено — два нативных `<select>` в стиле полей Рост/Вес; системный пикер быстрее чипов, не даёт опечаток и не требует цифровой клавиатуры |
| Колёсный датапикер (wheel) | Кастомный компонент вне дизайн-системы; нативный select закрывает ту же потребность |
| Хранение даты в localStorage | Профиль — серверные данные (BMR считается и в боте); расщепление хранилища сломает консистентность |
| Автомиграция age → birthYear («примерный год = текущий − age») | Прямо запрещено тикетом («не делать молча»); подстановка неверного месяца исказила бы данные |
| Возраст и дата как два одновременно редактируемых поля | Два источника истины = вечный конфликт; замена, не дублирование |
| Клавиатура годов в боте (кнопка на каждый год) | ~97 кнопок — неюзабельно; ввод года текстом + 12 кнопок месяца решают задачу |
| Кнопка «удалить дату рождения» | Не нужна: дату можно отредактировать; удаление вернуло бы мёртвый age-режим |
| Изменение формата одной строки ввода бота (два поля в строке) | Ломает привычку существующих пользователей; X-распознавание (§6.1) даёт год без смены формата |

## 11. E2E-кейсы (дополнение к `tests/e2e.spec.js`)

Существующие тесты, которые **обновляются** (tester): сцена профиля
(`#pfAge.fill('31'/'30'/'34')`, замеры rect `#pfAge` на 320px) — поле возраста заменено
карточкой даты с двумя select; seed-фикстуры дополнить профилем с датой и без.
Нативный системный пикер e2e не тестируется — ассерты только по DOM select'ов
(значения, опции, классы).

Новые сценарии:
1. **Новый профиль**: select на плейсхолдерах → сохранить → тост «Укажи год и месяц
   рождения…», профиль не записан; выбрать год+месяц → тост «✓ Профиль сохранён»,
   саммари показывает вычисленный возраст со склонением.
2. **Списки select**: опции года по убыванию — первая `текущий−5` (возраст ровно 5 лет),
   последняя 1930; у месяца ровно 13 опций: «Выбрать…» + Январь…Декабрь.
3. **Живой возраст**: выбрать год `1990` при месяце «—» → строки нет; выбрать
   «Ноябрь» → «Возраст: 36 лет» до сохранения; смена года обновляет строку сразу.
4. **Частичный ввод**: год без месяца → сохранить → тост «Укажи и год, и месяц…»,
   оба select с `.err`; сброс года на «—» → сохранение проходит в legacy-режиме
   (для нового профиля — тост обязательности даты).
5. **Границы возраста**: год `текущий−5` (5 лет) и год `1930` сохраняются без ошибок
   [I8-update 09.11: минимум 5 лет вместо 10].
6. **Legacy**: seed-профиль только с `age` → саммари с прежним возрастом, плашка-подсказка
   видна; обновить вес и сохранить → `age` не изменился, birth-ключи не появились;
   после указания даты — возраст пересчитался.
7. **BMR живой**: смена года на 5 лет → BMR-строка саммари изменилась на ~25 ккал.
8. **Бейдж**: seed с `birthMonth` = текущий месяц → бейдж «🎂 Твой день рождения в этом
   месяце» в саммари; seed с другим месяцем → бейджа нет (мок времени: `page.clock`).
9. **Серверные данные**: после сохранения `/api/init` возвращает `birthYear/birthMonth`
   и `age`-зеркало = вычисленному.
10. **Регресс 320px**: два select в ряд + prow без горизонтального переполнения.
