## 0. Резюме для владельца (TL;DR)

1. **Telegram Stars — самый дешёвый по интеграции способ принимать оплату**: без
   эквайринга, карт и внешних платёжных форм — счёт открывается прямо в Telegram,
   пользователь платит изнутра мессенджера. Минус: Stars ≠ деньги на счёте — вывод
   через Fragment (комиссия ~30%), см. §2.3.
2. **Принцип: бесплатное ядро не трогаем никогда.** То, что работает сегодня
   (ввод, история, статистика, экспорт CSV, 20 шаблонов), остаётся бесплатным.
   Платным становится только НОВОЕ и над-лимиты (§3). Это наш главный
   дифференциатор (исследование §6: недоверие к пейволлам — боль рынка).
3. **Рекомендуемый состав «⭐ Премиум» v1** (§3.7): продвинутая аналитика +
   до 100 шаблонов + акцентные темы. Один флаг `premium` в данных, всё
   обратимо, downgrade без потери данных (§5.2).
4. **Модель оплаты — периоды, не «навсегда»**: 1/3/12 месяцев, разовый счёт
   Stars за каждый период (нативная подписка Stars — как опция, §4.2).
   Пожизненных покупок не делаем (§9).
5. **При 6 пользователях продажи запускать рано** — предложение: реализовать
   инфраструктуру (флаг, экраны, invoice-механику) и НЕ включать точки продаж
   до набора аудитории (§10, вопрос 5). **Подтверждено решением 12.11: продажи
   НЕ запускать** («Нет» на запуск сейчас); фаза 0 (инфраструктура без продаж)
   утверждена к будущей реализации; вывод Stars через Fragment (~30% комиссия) —
   принято к сведению.
6. **Данных почти не добавляем**: один опциональный ключ `premium` в
   `data/chat_<id>.json` (§5.1), совместимость со старыми файлами — по паттерну
   `restSec`/`birthYear`; ПДн не собираем (платит Telegram).

## 1. Цель и пользовательская проблема

**Проблема владельца**: продукт живёт на голом энтузиазме (VPS, домен, время).
При 6 пользователях классические способы монетизации (реклама — #113, продажа
тренер-услуг — [TRN-I4]) ещё недоступны или преждевременны. Нужен канал
поддержки проекта, который:

- не ломает доверие существующих пользователей (ядро — бесплатно);
- стоит копейки во внедрении (нет платежных шлюзов, документов юрлица и т.п.);
- технически готов задолго до того, как пользователей станет достаточно
  для выручки.

**Цель фичи**: заложить в продукт опциональный слой «⭐ Премиум» на Telegram
Stars — инфраструктура приёма оплат, экран продажи, флаг в профиле — и каталог
премиум-удобств, которые можно включать/расширять по мере роста.

**Чего НЕ является целью**: вырезать из бесплатной версии что-либо работающее;
быстрый заработок на текущих 6 пользователях; монетизация данными (никогда).

## 2. Механика Telegram Stars

### 2.1 Что такое Stars

Telegram Stars (внутренняя валюта `XTR`) — валюта Telegram для оплаты цифровых
товаров и услуг в ботах и Mini App. Пользователь пополняет баланс Stars прямо
в Telegram (in-app покупки в клиентах / Fragment), затем платит звёздами за
счёт бота — карты, реквизиты и внешние формы не нужны. Оплата происходит
внутри мессенджера за 2–3 тапа, включая случай «звёзд не хватает — докупить».

### 2.2 Bot API (проверить актуальные сигнатуры на момент реализации)

| Метод/событие | Назначение | Примечание для нас |
|---|---|---|
| `sendInvoice` | Отправить счёт в чат | `currency="XTR"`, `provider_token` — **пустая строка**; цены — **целые** Stars; для XTR счёт содержит ровно один элемент `prices` |
| `createInvoiceLink` | Получить ссылку вида `https://t.me/$…` на тот же счёт | нужна для открытия счёта поверх Mini App (`WebApp.openInvoice`) |
| `Message.successful_payment` | Событие оплаты (приходит боту как сообщение) | поля: `invoice_payload`, `total_amount` (Stars), `telegram_payment_charge_id`, для подписок — `subscription_expiration_date` |
| `refundStarPayment` | Возврат Stars пользователю | нужен `telegram_payment_charge_id` из successful_payment |
| `getStarTransactions` | История всех Stars-транзакций бота | свой журнал платежей вести не обязательно — сверка возможна по API |
| `sendInvoice.subscription_period` | Нативная подписка на 30 дней с автосписанием Stars | появлялась в Bot API 9.0; **уточнить поддержку при реализации** — см. §4.2 |

Ключевое для Mini App: **платёжная форма не принадлежит нам** — мы только
создаём счёт (текст + цена + payload), всё остальное (экран оплаты, баланс
Stars, пополнение, чек) делает Telegram. Ни карт, ни ПДн на сервере.

### 2.3 Деньги: Stars ≠ fiat

- Ориентир курса для пользователя: **1 Star ≈ $0.013–0.02** (при покупке внутри
  Telegram). Т.е. $2–3 ≈ 150–200 Stars — приятная «игрушечная» цена для аудитории
  Telegram (звёзды часто уже есть на балансе после подарков/активностей).
- **Вывод** — через Fragment в TON; комиссия Telegram на вывод ≈ **30%**.
  Фактически из 150 ⭐ на руки выходит ~105 ⭐ ≈ $1–1.5. Для дизайна цен это
  значит: не закладывать в цену «минималку ради копейки» — мелкие суммы съедятся
  комиссией; ценить Stars-канал стоит как **низкий порог входа**, а не как
  эффективный по комиссиям.
- **Отметить владельцу** (вне дизайн-скоупа, зона решений владельца): вывод
  Stars — отдельный процесс (Fragment, TON-кошелёк, налоги/статус дохода).
  Продажи можно не запускать, пока этот вопрос не проработан — инфраструктуре
  бота это никак не мешает (§10, вопрос 5).

### 2.4 Что это значит для нас

- **Низкий порог входа**: не нужен эквайринг, договор с платёжным провайдером,
  хранение карт, PCI — счёт собирается тремя строками Bot API.
- Оплата живёт в интерфейсе, который пользователь уже открыл (чат бота или
  Mini App), конверсия выше внешних платёжных страниц.
- Скидки/промо = просто другая цена в счёте; возвраты = один API-вызов (§6.5).
- Минус: выручка в Stars, не в рублях/юанях на счёт — см. §2.3 и вопрос 5.

## 3. Что делаем платным — каталог предложений

### 3.0 Принцип (железный)

> **Всё, что работает сегодня, остаётся бесплатным навсегда.** Платным может быть
> только НОВОЕ (фичи, которых ещё нет) или НАД-ЛИМИТЫ (когда бесплатный лимит
> уже щедрый). Бесплатный тир должен оставаться конкурентным преимуществом —
> «бесплатный дневник без стора» (исследование §6, боль №6: «deeply skeptical
> of paywalls»).

Прямые следствия:
- `/export` (CSV) — **остаётся бесплатным** (работает сегодня);
- `/stats` и раздел «Статистика» в Mini App — бесплатны (премиум = только
  НОВЫЕ аналитические экраны поверх, §3.2);
- фон приложения, 2 темы, таймер, календарь, рекорды — бесплатны;
- история без ограничений по срокам — бесплатна (у конкурентов за это берут
  деньги — мы НЕ будем; это часть репутации «честного»).

### 3.1 (а) Лимиты шаблонов: 20 → 100

Сегодня: `TPL_LIMIT = 20` шаблонов, `TPL_EX_LIMIT = 20` упражнений на шаблон.
Предложение: free — как есть (20), премиум — **до 100 шаблонов**
(`TPL_EX_LIMIT` не трогаем — 20 упражнений на шаблон хватает всем, усложнять
не нужно).

| Критерий | Оценка |
|---|---|
| Ценность | ⭐⭐ Низкая-средняя: 20 шаблонов покрывают типового пользователя; лимит бьёт по «коллекционерам» программ (сплитов на 6–8 недель много). Реальная аудитория — 5–15% |
| Риск оттока | ⭐ Минимальный: ничего не отрезаем; перешедшие в free после истечения сохраняют все свои шаблоны (read-only, §5.2) |
| Честность | ✅ Высокая: это классический «над-лимит», а не отрезание; лимит 20 существует и виден сегодня («20 из 20») |

Роль в бандле: дешёвая в реализации (проверка лимита уже есть, добавляем
флаг), хорошо доносится («вместо 20 — 100»), но в одиночку продавать слабо.

### 3.2 (б) Продвинутая аналитика (НОВЫЕ экраны)

Сегодня: текстовая «Статистика» (время, подходы, максимумы), «Прогресс» против
предыдущей тренировки, живые рекорды, календарь [UX-S6]. Предложение —
премиум-раздел «📈 Аналитика» (вкладка/подэкран поверх Статистики):

- **Сравнение периодов**: этот месяц vs прошлый — объём (тоннаж), число
  тренировок, средняя длительность, ккал; дельты со стрелками ▲▼ (стиль
  `.dl-up/.dl-down` уже есть);
- **График по упражнению**: линия веса/1ПМ(Эпли)/объёма за выбранный период
  по любому упражнению из истории (данные уже есть — нужна отрисовка);
- **Сводка недели/месяца**: тепловая полоска частоты тренировок + топ
  мышечных групп (круги `.mgroups` уже есть — переиспользовать).

| Критерий | Оценка |
|---|---|
| Ценность | ⭐⭐⭐ Высокая: рынок подтвердил — юзеры платят за графики/аналитику (Strong прячет графики в PRO; Hevy — подписка на графики; исследование §16). Самая мотивирующая часть трекера |
| Риск оттока | ⭐ Низкий: существующая текстовая статистика остаётся; премиум = только новые красивые экраны |
| Честность | ✅ Высокая при условии: экспорт CSV НЕ прячем (он бесплатен сегодня, §3.0). Премиум — добавка, а не выкуп существующего |

⚠️ Именно здесь соблазн «немного отрезать» самый большой — экспорт, сравнение
периодов в текстовом виде и т.п. **Фиксируем: нет.** Бесплатная статистика
остаётся ровно той же; премиум добавляет отдельный раздел.

Роль в бандле: ядро ценности «Премиума», главный аргумент платить.

### 3.3 (в) Кастомизация: акцентные темы

Сегодня: тёмная + светлая тема, фон приложения из галереи (бесплатно — не
трогаем). Предложение: премиум = **акцентные цвета** интерфейса (янтарь по
умолчанию + 3–4 варианта: холодный синий, мятный, розовый, «графит»), тумблер
или чипы в Настройках → Оформление.

| Критерий | Оценка |
|---|---|
| Ценность | ⭐⭐ Низкая-средняя: косметика приятная, но сама по себе не повод платить; классический «поддержи проект и получи косметику» |
| Риск оттока | ⭐ Минимальный: дефолтная янтарная тема остаётся бесплатной |
| Честность | ✅ Высокая: чистая добавка |

Роль в бандле: наполнитель («и темы в придачу»), отдельно не продаём.

### 3.4 (г) Будущие тренер-функции / мультицели ([TRN-I4])

Раздел «🧑‍🏫 Персональный тренер» уже существует в Настройках как «в разработке».
В перспективе: готовые программы, мультицели, разборы техники, а [TRN-I4] —
приём платежей тренеров через бота с комиссией площадки.

**В v1 «Премиума» НЕ включаем**: продавать то, чего нет, нельзя (вымывание
доверия хуже отсутствия монетизации). Фиксируем в спецификации: когда
тренер-функции появятся, они станут вторым платным контуром (или частью
расширенного тарифа) — отдельное решение владельца, не часть этого эпика.

### 3.5 (д) Приоритетная поддержка — ИСКЛЮЧИТЬ из v1

При 6 пользователях владелец и так отвечает каждому лично — обещать

**Отменено решением 12.11: НЕ включаем** (молчание владельца = нет).

## 4. Тарифы

### 4.1 Модель: разовые периоды (рекомендация)

Покупка = счёт на период, премиум активен `until`, продление — новый счёт
(можно заранее, дни складываются). **Никаких автосписаний в v1**, если
владелец не выберет нативную подписку (4.2).

Тарифная сетка — **плейсхолдеры** (вопрос 3, §10). **Изменено решением 12.11: цены
утверждены — 150 / 400 / 1200 ⭐** (X/Y/Z ниже = 150/400/1200):

| Тариф | Цена (плейсхолдер) | Комментарий |
|---|---|---|
| 1 месяц | **X ⭐** (ориентир 150–200 ⭐ ≈ $2–3) | калибровка с конкурентами: Hevy Pro $2.99/мес; для аудитории Telegram Stars меньше «психологической» цены стора не надо |
| 3 месяца | **Y ⭐** (ориентир ~400 ⭐, −11…15%) | опция для тех, кто не хочет помнить о продлении |
| 12 месяцев | **Z ⭐** (ориентир ~1200 ⭐, −33…40%) | подсвечиваем как «выгоднее» (карточка с glow-рамкой в макете) |

Правило цены: не опускаться ниже ~100 ⭐ за период (комиссия вывода ~30% съедает
мелкие суммы, §2.3).

### 4.2 Нативная подписка Stars (опция B)

Bot API (с версии 9.0) поддерживает `sendInvoice` с `subscription_period`
(30 дней): автосписание каждый месяц, событие successful_payment на каждое
списание, пользователь отменяет подписку средствами Telegram (без бота).

| | Разовые периоды (A) | Подписка Stars (B) |
|---|---|---|
| Реализация | тривиальна, уже всё есть в Bot API 7.x | чуть сложнее: флаг автопродления, обработка рекуррентных списаний |
| Доход | стабильнее на «забывающих» юзерах платит чаще? нет — платит когда захочет | предсказуемая, автопродление по умолчанию |
| UX | пользователь сам решает продлить | «включил и забыл», отмена в один тап в Telegram |
| Риск | «отвалился» на продлении | нежелательные списания → раздражение/возвраты |

Рекомендация: **A в v1**, B — как апгрейд позже (вопрос 4). При B не забыть:
на каждое списание приходит successful_payment → просто продлеваем `until`,
хранить `autoRenew` для отображения статуса.

### 4.3 Пробный период

Telegram-счёт не умеет «0 ⭐», поэтому пробный — только серверная механика:
кнопка «🎁 14 дней бесплатно» → сервер ставит `until = now+14d`, `source:"trial"`
(без платежа и карты — просто флаг). Контроль злоупотреблений не нужен при
текущем размере (1 trial на чат; при росте — по chat_id).

Варианты (вопрос 4): (i) 14 дней всем новым по кнопке; (ii) без триала,
вместо него первый месяц со скидкой; (iii) без триала вовсе. В макете
показан вариант (i) — как самый понятный пользователям.
**Решено 12.11: вариант (i) — 14 дней, ДА; модель — разовые периоды (A) —
подтверждено.**

### 4.4 Что НЕ предлагаем по тарифам

- Пожизненная покупка («pay once, own forever») — подрывает будущую подписку
  и доход, конкуренты с lifetime не показывают устойчивой модели (§9).
- Персональные цены/промокоды — усложнение без аудитории (позже, при росте).
- «Платные услуги в звёздах у тренеров» — зона [TRN-I4], не этого эпика.

## 5. Интеграция с профилем и данные

### 5.1 Поле `premium` в GymData (обратная совместимость!)

Новый **опциональный** ключ верхнего уровня в `data/chat_<id>.json`:

```json
{
  "nextId": 12,
  "rev": 340,
  "restSec": 90,
  "premium": {
    "until": "2026-12-13T00:00:00Z",
    "source": "stars",
    "autoRenew": false,
    "lastChargeId": "W5Gb…telegramPaymentChargeId"
  },
  "profile": { … },
  "workouts": [ … ]
}
```

Правила (по паттернам `restSec`/`birthYear` — существующим в GymData.java):

- **Чтение**: ключа нет / null / мусор → `premium = null` → пользователь
  бесплатный. Старые файлы читаются ровно как сегодня. Невалидный `until` →
  считаем премиум истёкшим (толерантно, как birth-границы). `source`:
  `"stars"` | `"trial"` (появление новых значений не должно ломать чтение).
- **Запись**: пишем `premium` в JSON **только если он не null** (как `restSec`)
  — файл бесплатного пользователя остаётся байт-в-байт прежним, диффы в git
  и бэкапы не засоряются.
- **`isPremium()`** — вычисляемое: `premium != null && until > now`.
  Нигде не храним как факт — истина всегда из `until` (истечение «само»).
- **`lastChargeId`** — `telegram_payment_charge_id` последнего платежа: нужен
  для возврата (§6.5) и идемпотентности (§6.4). Это не ПДн — служебный id
  транзакции Telegram.
- **Контракт**: `GymContractTest` дополняется кейсом «файл без premium читается
  как сегодня» (эталон не меняется) + «файл с premium читается, мусорный until
  → бесплатный». Формат — обратно совместим по определению.

### 5.2 Истечение и downgrade — без потери данных

Когда `until` в прошлом:

- премиум-функции скрываются/гаснут (раздел «Аналитика» сворачивается до
  заглушки «⭐ Часть Премиума», темы — сброс на янтарь с сохранением выбора
  в памяти до возврата, лимит шаблонов — снова 20);
- **данные не удаляются никогда**: шаблоны сверх 20 остаются в списке
  (read-only: запускать из них тренировки можно, сохранять новые — нельзя до
  освобождения места или возврата премиума);
- одно вежливое сообщение в чат (§8.4), без назойливых повторов.

### 5.3 Бейдж в профиле

- **Mini App, карточка «Профиль»**: после имени строка/пилюля `.bdg`:
  «⭐ Премиум · до 13.12.2026» (формат даты локальный, как в истории).
  Бейдж кликабелен → экран «⭐ Премиум» (управление).
- **Бот, «⚙️ Профиль»**: строка в сводке «⭐ Премиум: активен до 13.12.2026».
- Публичность: бейдж виден только владельцу чата — демонстративности/соцсоревнования
  нет (и не планируем), это статус сервиса для пользователя, не «галочка
  важности».

### 5.4 Управление подпиской (Настройки)

Блок «⭐ Подписка» в «⚙️ Настройках» Mini App (между «🧑‍🏫 Персональный тренер»
и «ℹ️ О приложении»):

- free: строка «⭐ Премиум» с шевроном → экран продажи (§7.1);
- премиум: статус «Активна до …», строки «Управление подпиской» (экран §7.4),
  «Восстановить покупку» (перечитать сервер — на случай переустановки/нового
  устройства; премиум привязан к chat_id, так что «восстановление» = просто
  перечитать состояние), при подписке (4.2) — ссылка на управление подписками
  Telegram.

### 5.5 Агрегаты и ПДн

- В `/stats` добавляются счётчики (агрегаты, без ПДн — как `feedbackSent`):
  `premiumPaid` (число успешных платежей), `premiumStars` (сумма Stars),
  `premiumRefunded`. Никаких имён/usernames — только числа.
- ПДн: **не собираем ничего нового о личности**. Telegram сам проводит платёж;
  мы храним только факт премиума, дату окончания и служебный id транзакции.
  Возврат — по chat_id, владелец решает вручную (§6.5).

## 6. Механика оплаты (flow)

### 6.1 Точки входа

1. Mini App: ⚙️ Настройки → «⭐ Премиум» / «⭐ Подписка» → экран продажи.
2. Mini App: плашка «⭐ Премиум» в карточке Профиля (бейдж, §5.3).
3. Mini App: экран лимита шаблонов — при «20 из 20» в свободном слоте показываем
   мягкий тизер (§8.5 — тот же принцип, что в боте).
4. Бот: `/premium` (команда в меню BotFather добавляется при реализации);
   кнопка в «⚙️ Профиль» бота — только по решению владельца (не навязываем
   в основном меню, вопрос 8). Вопрос остаётся открытым (не отвечен 12.11);
   по умолчанию — только `/premium`.
5. ❌ Никаких пуш-рассылок «купи премиум» — `/announce` только для релизов
   и техработ (этикет продукта).

### 6.2 Flow из Mini App

Ограничение: Mini App **сам не выставляет счёт и не принимает оплату** — счёт
всегда создаёт сервер бота через Bot API, платит Telegram. Два UX-варианта:

**Вариант 1 — `WebApp.openInvoice` (рекомендуемый, если поддержан клиентом):**

```
[Mini App: экран «⭐ Премиум»]
  пользователь выбрал тариф → «⭐ Оплатить через Telegram»
        │  POST /api/premium/invoice {plan:"month"} + initData (HMAC — как все API)
        ▼
[Сервер] проверка initData → createInvoiceLink(payload="premium:m:<chatId>",
  currency=XTR, prices=[X]) → {invoiceUrl:"https://t.me/$…"}
        │
        ▼
[Mini App] tg.openInvoice(invoiceUrl) → счёт Telegram открывается ПОВЕРХ приложения
  пользователь платит Stars (или пополняет баланс в тот же момент)
        │  событие invoiceClosed: "paid" | "canceled" | "failed"
        ▼
[Telegram → бот] message.successful_payment (§6.4) → сервер ставит премиум
        │
        ▼
[Mini App] на invoiceClosed="paid" → перезагрузить /api/state →
  бейдж в Профиле, блок «Подписка» → «Активна», тост «⭐ Премиум активен»
```

**Вариант 2 — deep-link через чат бота (базовый, из брифа):**

```
[Mini App] «⭐ Оплатить через Telegram»
        │  POST /api/premium/invoice → сервер sendInvoice(chatId,…) —
        │  счёт приходит СООБЩЕНИЕМ в чат с ботом
        ▼
[Mini App] тост «Счёт отправлен в чат с ботом» + кнопка «Открыть чат»
  (tg.openTelegramLink("https://t.me/<bot>")) → пользователь платит в чате
        ▼
[Telegram → бот] successful_payment → сервер ставит премиум →
  подтверждение в чат (§8.2) → Mini App подхватит при следующем открытии
  (поллинг /api/state на visibilitychange — какRestSec/настройки сегодня)
```

Рекомендация: реализовать вариант 1 с автоматическим fallback на вариант 2
(если `tg.openInvoice` недоступен в клиенте). Итоговый выбор — за кодером
на этапе реализации; для пользователя оба пути заканчиваются одинаково.

### 6.3 Flow из бота (`/premium`)

```
/премиум → сообщение с выгодами и ценами (§8.1) + inline-клавиатура:
  [⭐ 1 месяц · X ⭐] [⭐ 12 месяцев · Z ⭐]
  [Что входит] [✖ Закрыть]
   тап по тарифу → sendInvoice прямо в этот чат → оплата Stars в чате
   → successful_payment → подтверждение (§8.2)
```

### 6.4 Обработка `successful_payment` на сервере

1. `payload` — формат `"premium:<period>:<chatId>"`, period ∈ {`m`,`q`,`y`,`trial`}.
   **chatId берём из сообщения** (payload — только cross-check; в чат бота
   чужой платеж попасть не может).
2. **Идемпотентность**: `telegram_payment_charge_id` сверяем с
   `premium.lastChargeId` (и, при сомнении, с `getStarTransactions`) —
   повторная доставка события не должна продлевать дважды.
3. `until = max(now, текущий until) + период` — продление заранее не теряет
   оплаченные дни.
4. Сохранение через Storage (с бэкапом — уже работает), обновление `rev`.
5. Подтверждение в чат (§8.2) + счётчики `/stats` (§5.5).

### 6.5 Возвраты

- `refundStarPayment(userId, lastChargeId)` —Stars вернутся пользователю,
  сервер: `until = now` (премиум гаснет), сообщение пользователю (§8.6).
- Инструмент владельца: admin-команда `/refund <chatId>` (шаг аккуратности:
  подтверждение второй командой). Автоматических возвратов нет.
- Политика «возврат по просьбе в течение 24 ч» — вопрос 7. **Подтверждено
  решением 12.11: ДА — 24 ч без вопросов.**

### 6.6 Edge cases

| Случай | Поведение |
|---|---|
| Пользователь закрыл счёт не заплатив (`invoiceClosed: canceled/failed`) | флаг не трогаем; тост «Оплата не завершилась — можно попробовать ещё раз» |
| Звёзд не хватает | Telegram сам предлагает пополнить баланс — наш UI не меняется |
| Бот перезапустился между оплатой и сохранением | long polling получит successful_payment после рестарта (сообщение доставляется); idempotency-guard от дублей |
| Двойной тап «Оплатить» | сервер игнорирует повторный запрос того же плана, пока первый счёт «жив» (или просто выпускает второй счёт — оплатят один, лишний истечёт) |
| Пользователь сменил телефон | премиум на chat_id — ничего восстанавливать не нужно; «Восстановить покупку» = перечитать сервер |
| Платёж в чате, Mini App открыт на другом экране | при visibilitychange поллинг /api/state подтянет флаг — бейдж появится сам |
| Истечение при закрытом приложении | при следующем открытии isPremium()=false → заглушки (§5.2); никаких пушей, кроме одного сообщения в чат (§8.4) |
| Возврат при активном триале | триал без платежа — возврата нет; /refund просто гасит until |
| Часовые пояса | `until` храним в UTC-инстанте; показываем локальной датой (как история) |

## 9. Что НЕ делаем и почему

| Отсечено | Почему |
|---|---|
| **Реклама** | отдельная идея #113 [MON-I2]; исследование §9: «дневник — приватное пространство, реклама убьёт доверие». В этом эпике не участвует |
| **Отрезание существующего бесплатного** (экспорт CSV, статистика, история, 20 шаблонов, темы, фон) | боль №6 рынка — недоверие к пейволлам; наш главный дифференциатор «бесплатное ядро». §3.0 — железный принцип |
| **Пожизненная покупка** | подрывает будущие периоды/подписку; нет подтверждённой модели у конкурентов; нельзя «повысить цену» позже |
| **Сбор ПДн / свои платёжные формы** | Stars всё делает внутри Telegram; мы не храним карты и не видим их — меньше рисков и регуляторики |
| **Продажа «вымышленных» фич** (тренер-раздел, мультицели) | фич нет — продажа разрушит доверие; их место в [TRN-I4]/целях, когда появятся |
| **Приоритетная поддержка как тариф** | при 6 пользователях нечестно (§3.5) |
| **Пуш-реклама премиума / рассылки продаж** | `/announce` — только релизы/техработы; этикет продукта: бот не навязывается |
| **Немедленный запуск продаж при 6 юзерах** | выручка будет копеечной (комиссия съест), а риск спалить доверие на старте — реальный. Сначала инфраструктура — продажи по решению владельца (вопрос 5) |
