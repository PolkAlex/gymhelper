## 1. Задача и контекст

Ревизия 1 этой спеки проектировала только «недельный вид» (сегмент
«Месяц | Неделя»). Владелец просмотрел макет и **расширил скоуп**: календарь
должен работать в 5 видах, как Outlook Mobile — «день, 3 дня, неделя, месяц
(уже есть), год». Паттерны Outlook (по скриншотам владельца):

1. **Полоса дней** сверху сеточных видов: «Пн Вт Ср Чт Пт Сб Вс» + числа;
   выбранный день — обводка-круг, сегодня — залитый круг; видимое окно
   («Рабочая неделя») подсвечено капсулой-подложкой;
2. **Сетка колонок × часы**: события — цветные блоки (время + название внутри),
   вертикальный скролл, метки часов слева;
3. **День** — одна колонка на весь экран + та же полоса дней для смены дня;
4. **Пикер вида** — нижний лист со списком видов;
5. **Плавающая пилюля «Сегодня»** внизу по центру (FAB «+» из Outlook —
   НЕ переносим: добавление тренировок живёт на главных вкладках, решение
   владельца).

Что сохраняется из ранее зафиксированных решений (#268 и ревизия 1):

- часы — **полные сутки 0–24, скролл** (ночные часы пустые);
- **тап по блоку → карточка тренировки** (`openHistory(w.id)`);
- тренировки **без времени → капсулы** в полосе над сеткой;
- пустой `ended` → блок **условно 1 час**;
- неделя с **понедельника**; листание ограниено 2020–2030;
- память в localStorage **по образцу `gymCalMonth`**;
- вкусы владельца из истории S6: моно-янтарь (без раскраски по типам), строки
  10–12px **не-жирные**, крупные тап-зоны, без дублей действий (никаких
  крестиков у листа), подэкран-оверлей с «← Назад», никаких сеток 2×2.

Данные — те же `G.workouts` (`date` «YYYY-MM-DD», `started`/`ended` ISO
«YYYY-MM-DDTHH:MM» или пустые; в терминах задачи — `startedAt`/`endedAt`,
`title`, `finished`). Никаких серверных изменений; вид — проекция тех же данных.

## 2. Архитектура видов (для кодера)

### 2.1 Одна дата + один вид

Вся навигация строится на **двух атомах состояния**:

- **`date`** — выбранная дата, ISO `'YYYY-MM-DD'`, **единая для всех видов**.
  Это «якорь»: День показывает её, 3 дня — окно от неё, Неделя — её неделю,
  Месяц — её месяц, Год — её год;
- **`view`** — `'day' | 'd3' | 'week' | 'month' | 'year'`.

Память (localStorage, каждый доступ в `try/catch`, паттерн `gymCalMonth`):

| Ключ | Значение | Дефолт при чтении |
|---|---|---|
| `gymCalView` | `'day'`/`'d3'`/`'week'`/`'month'`/`'year'` | **`'week'` («Неделя»)** — решение владельца 19.11 (§12.2). Применяется, когда ключ `gymCalView` отсутствует/невалиден: и у обновившихся пользователей, и у новых без ключей |
| `gymCalDate` | `'YYYY-MM-DD'` (валидная дата) | **`gymCalDate` нет → читать старый `gymCalMonth`** (разовая миграция: 1-е число сохранённого месяца, clamp в пределы) → нет и его: дата последней тренировки → сегодня |

`gymCalWeek` из ревизии 1 **не вводится** — её заменяет `gymCalDate`.
`gymCalMonth` **перестаёт писаться** (читается один раз как fallback миграции —
решение владельца §12.8); поведение S6 «месяц переживает закрытие» сохраняется
автоматически — теперь переживает дата. Запись `gymCalDate`/`gymCalView` — при
каждом изменении (листание, «Сегодня», тап по дню, смена вида). После первой же
записи у пользователя появляются оба ключа и дефолт «Неделя» больше не
срабатывает — вид живёт по явному выбору.

Состояние в памяти: `CAL = { view, date, panel }`, где `panel` — сессионный
флаг «панель дня открыта в месячном виде» (НЕ persists: при повторном открытии
календаря панель закрыта, как в S6 — «выбор дня сессионный»).

### 2.2 Сеточный движок (День / 3 дня / Неделя — один рендер)

**Ключевая идея**: сеточные виды — один движок `renderGrid(days, cols, hourHeight)`:

| Вид | `days` (колонки) | Кол-во | Высота часа | Стрелки ‹ › | Заголовок |
|---|---|---|---|---|---|
| День | `[date]` | 1 | **112px** | ±1 день | «Четверг, 19 ноября» (DOW_FULL + дата) |
| 3 дня | окно от `date`, старт ≤ date ≤ конец | 3 | **96px** | ±3 дня | «19–21 ноября» (формат ниже) |
| Неделя | Пн–Вс недели `date` | 7 | **88px** | ±7 дней | «16–22 ноября» (формат ниже) |

Высота часа — параметр движка: канвас = 24 × hourHeight (**2688/2304/2112px** —
рев. 4 [UX-B14]: ×2 к прежним 56/48/44, решение владельца 20.11 §12.11 — блок 1ч
читабелен: время + название даже в «Неделе»),
внутренний скролл-контейнер ≈440–480px (уточнить на устройстве; в макете 560px
для демонстрации). Остальное общее — §3.

Форматы заголовков (годы не пишутся, правило [UX-S6]): одно-месячные «16–22
ноября»; через месяц «30 ноября – 6 декабря»; через год «29 декабря – 4 января».

Остальные виды — отдельные вёрстки: Месяц = существующий `renderCalendar`
(§7), Год = новый `renderYear` (§8). Диспетчер: `renderCalendar()` становится
роутером по `CAL.view` (+ topbar подэкрана общий).

### 2.3 Синхронизация даты между видами

Правило простое — **дата всегда одна**, виды лишь по-разному её показывают:

- тап по дню **полосы дней** → `date =` этот день (в «Неделе» — если день той же
  недели, видимых изменений нет);
- тап по дню **в месячном виде** → `date =` этот день + панель дня (S6);
- тап по **мини-месяцу** в годовом виде → вид «Месяц»; `date`: если тапнули
  месяц якоря — дата сохраняется целиком ([решение владельца, ТЗ #274];
  преемственность §2.3 «смена вида дату не меняет»), другой месяц — 1-е число
  этого месяца; смена месяца закрывает панель дня (преемственность с S6 §10.9)
- стрелки меняют период: в «Дне» двигают дату, в «3 дня»/«Неделе» — двигают
  дату на 3/7 дней (окно/неделя пересчитываются от неё);
- **«Сегодня»** (пилюля) → `date =` сегодня;
- смена вида дату **не меняет** — День/3дня/Неделя сразу показывают ту же дату,
  которую показывал месяц; и наоборот.
- «Смена месяца сбрасывает выбор дня» из S6: стрелки месяца ставят `date` =
  1-е число нового месяца и `panel = false` — преемственность с S6 §10.9
  сохранена.

Границы листания: `MIN_DATE = '2020-01-01'`, `MAX_DATE = '2030-12-31'`
(константы, аналог `MIN_MONTH`/`MAX_MONTH`); стрелка на границе — `.dim` +
`disabled` + `aria-disabled`. Годовые стрелки — 2020…2030.

### 2.4 Полоса дней — общая для трёх сеточных видов

**Рев. 4 [UX-B14] (решение владельца 20.11.2026, §12.10): полоса = ТОЛЬКО дни
окна вида, растянутые на всю ширину сетки — каждая ячейка ровно над своей
колонкой**: «День» — 1 ячейка, «3 дня» — 3, «Неделя» — 7. Прежняя схема «7 ячеек
Пн–Вс недели якоря + капсула окна winpill» удалена: сетка 3 колонок под полосой
7 ячеек разрывала соответствие «день → колонка → тренировка» (блок 19-го
оказывался зрительно «под» ПН/ВТ — скриншот владельца), а капсула потеряла
смысл (окно теперь = вся полоса) — **winpill удалена решением владельца 20.11**.

- полоса делит ту же ширину, что колонки сетки: отступ слева равен гуттеру
  (30px, как `.wk-inner`), число колонок — inline
  `grid-template-columns:repeat(N,1fr)`; центры ячеек совпадают с центрами
  колонок 1:1 (геометрия `geoCol` 1px-инсет + 2px-зазоры зеркалит деление
  полосы; проверяется e2e, delta ≤ 3px);
- ячейка: буква «ПН»…«ВС» (8.5px/700, muted, uppercase) над **кругом 30px** с
  числом (13px/600, tabular); буквы/числа вычисляются по дате — окно «3 дней»
  может переходить через неделю (СБ, ВС, ПН…), прежний clamp капсулы исчез;
- **сегодня** — glow-круг: фон `var(--glow)`, рамка `var(--glow-brd)`, число
  `var(--accent)`/700 (прямое продолжение `.cal-d.today` месячного вида);
- **открытая дата (якорь)** — обводка-круг 1.5px `var(--accent)`; сегодня+якорь —
  glow-фон + accent-обводка;
- тап по ячейке → §2.3 (`wkDay` — прежнее поведение); тап-зона ≈ ширина колонки
  × 47px.

### 2.5 Пикер вида

Точка входа — кнопка в topbar подэкрана: **[ ← ][ Календарь ]
[ виду-кнопка ][ ⚙ ]** (иконка «тюнеры» 18px, стиль `.tbtn`; заголовок и
шестерёнка не меняются — e2e-локаторы целы). Тап → **нижний лист** «Вид
календаря» (фон `--sheet`, радиус 22px, backdrop `--backdrop`, blur —
существующие токены):

- 5 пунктов: **День / 3 дня / Неделя / Месяц / Год** (иконка 20px + подпись
  14.5px/600; «Рабочая неделя» и «Расписание» из Outlook — НЕ делаем, решение
  владельца);
- у текущего вида — янтарная иконка + **точка-отметка** 8px `accent` справа;
- тап по пункту → сменить `view` (дата сохраняется), записать `gymCalView`,
  закрыть лист; тап по backdrop → просто закрыть; крестика нет (дубль действий);
- на 320px пункты не переносятся (высота строки 44px, подпись короткая).

## 3. Сеточные виды: общая механика (движок)

### 3.1 Структура карточки

Та же стеклянная карточка внутри подэкрана календаря. Сверху вниз:

```
┌──────────────────────────────────────────┐
│ ←  Календарь               [ tune ] [ ⚙ ]│  ← topbar подэкрана
├──────────────────────────────────────────┤
│ ┌────────────────────────────────────┐   │
│ │  ‹      <заголовок периода>   ›    │   │  ← строка периода (§2.2)
│ │   ЧТ 19  ·  ПТ 20  ·  СБ 21        │   │  ← полоса дней окна (§2.4)
│ │ (без времени: [Жим лёжа]       )   │   │  ← аллдей-полоса (§3.6, при наличии)
│ │ ┌──────────────────────────────┐   │   │
│ │ │ 0 ┤ колонки × часы 0–24      │   │   │  ← скролл-сетка (§3.2–3.4)
│ │ └──────────────────────────────┘   │   │
│ └────────────────────────────────────┘   │
│         [Сегодня]  ← плавающая           │  ← пилюля, §9.2 (при наличии)
│              нижняя навигация            │
└──────────────────────────────────────────┘
```

### 3.2 Грид: гуттер и канвас

- Гуттер слева 30px (320px — 26px): метки «0»…«23», 9px, muted, tabular,
  по линиям часов; вертикальная граница гуттера 1px `btn-brd`;
- линии часов — 1px `nested-brd` каждый час (один repeating-gradient на канвас);
- канвас 24 × hourHeight (§2.2), скролл-контейнер `overflow-y:auto`, фон
  `nested`, радиус 12px, рамка `nested-brd`;
- **автоскролл при открытии/смене периода**: (а) в периоде есть активная
  тренировка → к её старту −30 мин; (б) есть тренировки со временем → к самой
  ранней −60 мин; (в) иначе → 06:00; clamp в `[0, canvas − окно]`;
- `scrollTop` запоминается при уходе в карточку (тап по блоку) и
  восстанавливается при возврате («← Назад» backbar'а возвращает в тот же вид,
  тот же период, ту же позицию скролла — паттерн S6 «calOpen не сбрасывается»);
- **линия «сейчас»** — только если период содержит сегодня: 1.5px `accent`
  через всю сетку + точка 7px на границе гуттера; перерисовка при очередном
  `render()`, без таймеров.

### 3.3 Блок тренировки

- Позиция: `top = (ч×60+м)/60 × hourHeight`; высота = длительность ×
  hourHeight, но ≥ **32px** (рев. 4 [UX-B14]: было 26px — под высоту часа ×2);
  `ended` пуст → длительность **60 мин** (условно);
- контент: **время** (в «Дне» — диапазон «11:00–12:30», в узких видах — старт
  «08:40», активная — «с 19:05»; 9.5px/700, accent, tabular, nowrap) +
  **название** по `firstLine` (title → 2 упражнения через « · » → «Без
  упражнений»; 10px/**400** — не-жирный, вкус владельца [S6-update6d]; clamp
  3 строки с ellipsis; в «Дне» — `.wide`: паддинг больше, bt 10.5px, bn 11.5px,
  clamp 2);
- стиль: фон — усиленный янтарный `rgba(255,194,32,.14)` (светлая —
  `rgba(255,176,0,.16)`; кодеру — токен в духе Amber Glass, напр. `--glow-2`,
  в обе темы), рамка 1px `glow-brd`, радиус 8–10px. **Единый янтарный цвет** —
  принцип S6 §5 (классификации «по типу» нет; синие блоки Outlook НЕ копируем);
- высота блока <44px → название скрывается (остаётся время; рев. 4 [UX-B14]:
  было 36px — полчаса и длиннее теперь с названием);
- **активная (незавершённая)** — контур: фон прозрачный, рамка 1.5px `accent`
  (аналог полой точки S6); в периоде с сегодня тянется от старта до линии
  «сейчас», в другом периоде — от старта до старт+1ч;
- **тап по блоку → `openHistory(w.id)`** (карточка; решение владельца);
  тап по пустому слоту — ничего.

### 3.4 Пересечения (2+ тренировок перекрываются)

- Пересечение строгое (`end == start` касанием не считается); кластер — цепочка
  пересекающихся тренировок одного дня; внутри кластера колонка делится на
  k дорожек (k = максимум одновременных), ширина = (колонка − 2px зазоры)/k;
- ширина дорожки **≥34px → блок с текстом** (в «Дне» дорожка ≈150px, в «3 дня»
  ≈47px), **<34px → полоса без текста** (в «Неделе» ≈20px) — макет, экраны 2–4;
- день группируется по `w.date` (консистентно с месячным видом), время — из
  `started`.

### 3.5 День группировки и «без времени»

- Группировка по `w.date`; блок ставится по времени `started`;
- тренировка с пустым/невалидным `started` → **аллдей-полоса** над сеткой:
  высота ≈26px, слева в гуттере подпись «без времени» (8.5px muted; на 320px
  скрывается), капсулы по дням (pill, accent, ellipsis, тап → карточка);
  несколько в день — в ряд с зазором 2px; полоса рендерится **только при
  наличии** таких тренировок; в «Дне» капсула крупнее (11px, слева).

### 3.6 Сводная таблица тапов (сеточные виды)

| Тап | Результат |
|---|---|
| Блок / полоса пересечения / капсула «без времени» | `openHistory(w.id)`; `scrollTop` периода запоминается |
| День в полосе дней | `date =` этот день (§2.3); в «3 дня» окно перестраивается |
| «‹» / «›» | ±1/±3/±7 дней (по виду), границы §2.3 |
| Плавающая «Сегодня» | `date =` сегодня |
| Кнопка-«тюнеры» | пикер вида (§2.5) |
| Пустой слот / линия «сейчас» / метки часов | ничего (инфо) |

## 4. Вид «День»

- 1 колонка на всю ширину сетки (≈306px) — блоки просторные (`.wide`);
- пересечения — дорожки с **полным текстом** (макет, экран 3: Кроссфит ∩
  Велосипед);
- заголовок «Суббота, 21 ноября» (DOW_FULL уже есть с 1.28);
- смена дня: стрелки ±1 (полоса = 1 ячейка выбранного дня, тапом другой день
  недоступен — рев. 4 [UX-B14]);
- **полоса дней — одна ячейка выбранного дня на всю ширину сетки** (§2.4,
  рев. 4 [UX-B14]); обводка-круг якоря; капсула winpill удалена (рев. 4);
- аллдей-полоса «одна колонка»: капсула слева, крупнее (§3.5);
- пилюля «Сегодня» — если `date ≠` сегодня (§9.2);
- это «главный» вид Outlook-паттерна: одна колонка + полоса дней сверху.

## 5. Вид «3 дня»

- окно из 3 колонок ≈98px; окно строится так, чтобы `date` была внутри
  (старт окна = `date`, если это не ломает содержимое — достаточно `date ∈ окно`);
- заголовок «19–21 ноября» (форматы §2.2); стрелки ±3 дня; «Сегодня» — окно от
  сегодня;
- **полоса дней — 3 ячейки окна, каждая ровно над своей колонкой** (§2.4);
  окно у края недели продолжается на следующую (СБ, ВС, ПН…) — clamp капсулы
  исчез вместе с капсулой (рев. 4 [UX-B14], §12.10);
- блоки: время старта + название clamp 2; пересечения — дорожки ≈47px с кратким
  текстом;
- пилюля «Сегодня» — если окно не содержит сегодня.

## 6. Вид «Неделя»

- 7 колонок ≈41px, Пн–Вс недели якоря (понедельник — конвенция проекта);
- заголовок «16–22 ноября»; стрелки ±7 дней; «Сегодня» — текущая неделя;
- блоки узкие: время старта + название до 3 строк (ellipsis), пересечения —
  полосы без текста (§3.4);
- **полоса дней — все 7 ячеек недели** (окно недели = вся полоса, §2.4);
- пилюля «Сегодня» — если неделя не текущая;
- высота часа 88px (рев. 4 [UX-B14]: ×2 к 44, §12.11) — блок 1ч читабелен:
  время + название; обзор недели не страдает (скролл сетки).

## 7. Вид «Месяц» — без изменений [UX-S6]

- Вся механика S6 остаётся: компактная сетка 38px, точки ×1–3/полое кольцо,
  «сегодня»-рамка, панель дня (единые строки `.drow`, 12px/400), лимиты,
  «Сегодня»-пилюля **в потоке карточки**, поведение тапов;
- интеграция с новой архитектурой:
  - месяц показывается **от `date`** (вместо `CAL.y/m` — месяц и год вычисляются
    из даты; `CAL.y/m` можно оставить как производные);
  - тап по дню → `date =` этот день + панель (было `sel` — заменяется);
  - стрелки месяца → `date` = 1-е число соседнего месяца, `panel = false`
    (§2.3);
  - «Сегодня»-пилюля месяца → `date =` сегодня (ключ/правила показа — прежние:
    только если месяц даты ≠ текущего);
  - в пикере вида «Месяц» участвует наравне с остальными; **сегмент
    «Месяц | Неделя» из ревизии 1 удаляется** — его заменяет пикер.

## 8. Вид «Год» (новый)

- **12 мини-месяцев сеткой 3×4** — весь год на одном экране (как в Outlook),
  без скролла на 390px (мини-месяц ≈106×110–125px, грид-контейнер ≈600px);
- мини-месяц: заголовок («Январь», 10px/700) + буквенный ряд «п в с ч п с в»
  (6.5px, muted) + сетка чисел 7×(8px/500, ячейка ≈14×15px, tabular);
- отметки — по образцу месячного вида, компактнее:
  - день с тренировкой → **точка 3px** `accent` под числом (несколько
    тренировок в день — одна точка; подробности — в месячном виде);
  - **сегодня** — число `accent`/700 (без рамки — ячейка мала);
  - активная тренировка — как обычная точка (кольцо в 3px не читается);
- пустые дни соседних месяцев — пустые ячейки (заглушки, как `.cal-blank`);
- навигация: заголовок «2026», стрелки ±1 год (пределы 2020–2030), плавающая
  пилюля «Сегодня» если год ≠ текущий;
- **тап по мини-месяцу → месячный вид этого месяца**: месяц якоря — дата
  сохраняется целиком, другой месяц — 1-е число (см. §2.3, [решение владельца,
  ТЗ #274]);
  отдельные дни в годовом виде НЕ тапуются: тап-зона ячейки ≈14px — против
  принципа «крупные тап-зоны» (вкусы владельца); выбор дня — в месячном виде.
  **Решение владельца 19.11 (§12.1): сетка 3×4 + тап по мини-месяцу** — принята
  (рекомендация спеки); альтернатива-лента отклонена.
- данные — тот же `byDate`-map, что в месячном виде (один проход, точки по
  количеству дней с тренировками).

## 9. Пикер вида и пилюля «Сегодня»

### 9.1 Пикер

- §2.5: нижний лист, 5 пунктов, отметка текущего, тап → переключение вида
  **с сохранением даты**; localStorage `gymCalView`;
- сегмент-контрол из ревизии 1 (`.cal-seg`) **удалить** — при 5 видах он не
  масштабируется, лист показал владелец на скриншотах;
- e2e: заголовок подэкрана и кнопка ⚙ не меняются (локаторы целы), пикер —
  новая кнопка с `aria-label="Вид календаря"`, лист — `role="dialog"` /
  `aria-modal`, пункты — кнопки.

### 9.2 Плавающая пилюля «Сегодня»

- **Да, делаем — решение владельца 19.11 (§12.3)**: плавающая пилюля внизу
  по центру (над нижней навигацией, `bottom ≈ 102px`, тень) во ВСЕХ новых видах
  (День, 3 дня, Неделя, Год);
- правило показа: открытая дата вне текущего дня/периода — «День»: `date ≠`
  сегодня; «3 дня»: окно не содержит сегодня; «Неделя»: неделя не текущая;
  «Год»: год не текущий. На «своём» периоде пилюли нет («ты и так там», правило
  S6 §7.2);
- тап → `date =` сегодня (+ запись `gymCalDate`);
- **в месячном виде — без изменений**: пилюля в потоке карточки, как в S6
  (унификация не требуется; месяц не трогаем).

## 10. Граничные случаи

1. **Пустой день** — сетка пустая, полоса «без времени» не рендерится, пилюля
   «Сегодня» по правилу §9.2 (макет, экран 6б);
2. **Пустое окно «3 дня» / пустая неделя** — сетка честно пустая + пилюля
   (если период не текущий); текстов вида «В октябре тренировок не было.» в
   сеточных видах НЕ заводим — пустота видна напрямую (часовая сетка сама
   честная); формулировка S6 остаётся только в месячном виде;
3. **Будущая дата** (рукотворная «⏱ Время») — обычный блок в своём слоте;
   активная забытая со вчера — контур на своём дне (§3.3);
4. **Длинные названия** — ellipsis по видам: День — 2 строки полным текстом,
   3 дня/Неделя — 2–3 строки укороченно; полное название — в карточке;
5. **10+ тренировок в день** — стопка блоков (каждый ≥32px — вертикальный
   скролл сетки), пересечения — дорожки (§3.4); список дня — тапом в месячный
   вид (панель) либо по карточкам;
6. **Без времени, несколько в одном дне** — капсулы в ряд, сужение, ellipsis
   (§3.5);
7. **Битая дата** (`parseDateISO` → null) — ни в один вид не попадает (S6
   §10.1); битый `started` при валидной `date` — аллдей-полоса;
8. **320px**: гуттер 26px, колонки ≈34px (Неделя) → все блоки переходят в
   режим полос; пикер-лист и полоса дней помещаются; заголовок периода —
   ellipsis (опыт S6 §9); мини-месяцы года ≈98px — числа 8px читаются;
9. **Обновление данных извне** (`reloadSilently`) — все виды читают
   `G.workouts` на каждом рендере, кэша нет;
10. **Устаревший/битый localStorage** — `gymCalView` вне списка → дефолт
    **`'week'`**; `gymCalDate` невалидна → цепочка дефолтов §2.1; clamp
    `2020-01-01…2030-12-31`;
11. **Первое открытие после обновления** (ключ `gymCalView` ещё не существует) —
    вид **«Неделя»** (дефолт, решение §12.2), дата — по миграции из старого
    `gymCalMonth` (§2.1): пользователь попадает на недельный вид того месяца,
    где он last time смотрел календарь; при первом же действии пишутся оба
    ключа;
12. **Часовой пояс** — локальные даты/время (как везде);
13. **Смена вида из карточки тренировки** — карточка открывается поверх
    (`calOpen` сохраняется), «← Назад» возвращает в тот же вид с той же датой и
    скроллом (§3.2);
14. **Двойной тап пункта пикера** — дедуп 400ms общего `dispatchFromEl`,
    повторное переключение безвредно (идемпотентно).

## 11. Что НЕ делаем и почему

| Отсечено | Почему |
|---|---|
| **«Рабочая неделя» (Пн–Пт) и «Расписание»** | решение владельца: ровно 5 видов |
| **Синие блоки и прочая палитра Outlook** | дизайн-система Amber Glass; блоки — единый янтарный (S6 §5) |
| **FAB «+» в календаре** (как в Outlook) | решение владельца: добавление тренировок живёт на главных вкладках |
| **Свайп-жесты** (листание сетки, полосы дней, окон) | конфликт с вертикальным скроллом (S6 §11); стрелки + тап по полосе достаточно |
| **Сегмент «Месяц | Неделя»** (ревизия 1) | заменён пикером-листом (5 видов не масштабируются сегментом) |
| **Тап по дню в годовом виде** | тап-зона ≈14px; тапуется мини-месяц целиком (§8; вопрос №1 владельцу) |
| **Счётчики тренировок в шапках периодов** | минимализм владельца (счётчик месяца отвергнут в S6) |
| **Планирование/создание по тапу на пустой слот** | календарь = журнал фактов; старт — FAB на вкладках |
| **Раскраска блоков по типам** | моно-янтарь — принцип владельца (S6) |
| **Изменения бэкенда/формата данных** | все 5 видов строятся из существующих `date`/`started`/`ended`/`finished` |
| **Изменение внутренностей месячного вида** | S6 устоялся после 7 редакций; меняется только источник периода (`date`) и точка входа (пикер) |
| **Линия «сейчас» вне периодов с сегодняшним днём** | шум; линия лжива вне «сейчас» |
| **Таймеры перерисовки линии «сейчас»** | WebView без лишней активности; перерисовка при рендере |
| **Крестик у пикер-листа** | дубль действий (урок UX-B 08.11); закрытие — тап по фону/пункту |
| **Горизонтальный скролл сетки** | колонки всегда помещаются (сжимаются по виду) |
