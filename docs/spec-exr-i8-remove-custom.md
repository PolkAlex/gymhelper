## 1. Цель и пользовательская проблема

«Своё» упражнение создаётся из тренировки за два тапа («✍️ Своё упражнение» → название), но **удалить его нельзя** — ни из базы, ни из подсказок. Последствия:

1. **Опечатки и мусор живут вечно.** «жим лёжа 45» остаётся в подсказках рядом с «Жим штанги лёжа».
2. **Подсказки засоряются.** «Свои» показываются в трёх местах: Техника → чип «Своё», пикер → «Коллекции → Свои», подсказки целей («Каталог», app.js:3398). Удалённые из обихода названия толкаются пользователю при каждом выборе упражнения.
3. **Нет ни одного пути управления.** Карточка своего в Технике некликабельна (без `data-act`, app.js:2773) — единственное живое действие на ней сегодня — звезда ★.

**Решение:** долгий тап на карточке «своего» в режиме «Своё» (вкладка Техника) открывает контекстное меню с пунктом «🗑 Удалить» — с подтверждением и гарантией, что **прошлые тренировки не трогаются** (решение владельца).

## 2. Решения владельца (зафиксированы — менять нельзя)

1. **Удалённое упражнение ОСТАЁТСЯ в прошлых тренировках** — удаляем только из базы и подсказок. Записи, сеты, даты, рекорды — нетронутыми.
2. **UI:** долгий тап на карточке «своего» → меню с «Удалить». Меню расширяемое — заложен слот под будущие пункты (переименование, коллекции — отдельные тикеты).
3. **Скоуп этой итерации** — вкладка Техника, режим «Своё» (чип «Своё» и «Коллекции → Свои» — обе ветки `techOwnMode()`). Пикер — вне скоупа (см. §13, вопрос 6).

## 4. Сценарии использования

**A. Удалить опечатку (основной)**
1. Вкладка «Техника» → чип «Своё». Видит список своих + строку-совет «долгий тап — меню» (§9).
2. Долгий тап на «жим лёжа 45» (~500 мс): карточка подсвечивается, вибро — открылось меню (Э2): имя упражнения, «🗑 Удалить упражнение» красным, «Отмена».
3. «🗑 Удалить упражнение» → диалог (Э3): «Удалить упражнение „жим лёжа 45“?» + пометка «Тренировки останутся без изменений».
4. «Удалить» → карточка исчезла из списка; в тренировке от 12.11 всё на месте (Э4).

**B. Передумал**
1–2 как выше → «Отмена» (или тап по фону) → меню закрылось, ничего не изменилось. То же на шаге 3: «Оставить».

**C. История не страдает**
1. Удаляет «Тяга гантели в разножке», с которой 3 тренировки.
2. Открывает календарь → 08.11: упражнение на месте, сеты и вес прежние. Решение 1 соблюдено.

**D. Удалил последнее**
1. Долгий тап → удалить → подтвердить. Список пуст: «Своих упражнений пока нет — добавь их из тренировки («✍️ Своё упражнение»)» (Э5).

**E. Пересоздание с тем же именем**
1. Через месяц создаёт «✍️ Своё упражнение» с тем же именем → упражнение снова в подсказках (томстон снят, §8.3).

## 5. Жест долгого тапа — переиспользуемая механика [UX-I20]

Первая реализация системного паттерна. Требование: **хелпер проектируется отдельно от «Своих»**, чтобы следующие экраны ([UX-I20]: меню упражнения на плитке тренировки, карточки календаря, записи подходов) подключались без копипасты.

### 5.1 Контракт хелпера

Делегированный слушатель на `document` (паттерн DRAG [UX-T14]), реагирует на элементы с `data-lp`-разметкой:

```
селектор жеста:  '.excard[data-custom]'  (T18: только внутри #techList)
атрибут цели:    data-name="<имя>"       (что передать в меню)
исключения:      ev.target.closest('[data-fav], button, input, textarea, a')
                 → звезда и кнопки живут своей жизнью, жест не стартует
одиночность:     LP — синглтон на документ (как DRAG); второй палец → отмена
```

### 5.2 Государственная машина

```
pointerdown → LP = {el, name, x0, y0, pointerId, fired:false}
  el.classList.add('lp-hold')            // подсветка + user-select/callout off
  LP.timer = setTimeout(lpFire, 500)

pointermove (тот же pointerId), !fired:
  |dx| > 14 или |dy| > 14  →  lpCancel()  // скролл побеждает жест

pointerup / pointercancel:
  !fired → lpCancel()
  fired  → __lpGuard = Date.now()         // гасим призрачный клик/тап (450 мс)
           lpCancel()

window blur / visibilitychange hidden → lpCancel()
lpFire: LP.fired = true; haptic('selectionChanged'); openCtxMenu(LP.name)
```

### 5.3 Тайминги и пороги (и почему)

| Параметр | Значение | Основание |
|---|---|---|
| Задержка срабатывания | **500 мс** (допустимый диапазон 500–650) | Стандарт системных контекст-меню iOS/Android. У drag плиток [UX-T14] 650 мс — там жест «тяжелее» (перестановка), и 350 мс исторически цеплялись при скролле. Карточка списка — лёгкая цель; конфликт с тапом в Технике нет (карточка некликабельна, §3). В макете демо — 600 мс для надёжности ручного показа |
| Порог отмены движением | **14px** | Тот же, что у drag (app.js:2420) — единый порог проекта, скролл всегда побеждает |
| Гард клика после срабатывания | **450 мс** | Тот же приём, что `__dragClickGuard` (app.js:2375): глобальный `click` (app.js:633) и `touchend`-тап (app.js:665–666) добавляют проверку `__lpGuard`. Без этого отпускание пальца после открытия меню «докликнется» до карточки/звезды под модалкой |
| Хаптик | `HapticFeedback.selectionChanged()` в момент открытия меню | Паритет с dragStart (app.js:2470); обёртка `dragHaptic` (app.js:2377) — рекомендация: переименовать в `haptic()` (переиспользование вне drag-контекста). Альтернатива `impactOccurred('medium')` — на выбор кодера, не принципиально |

### 5.4 Конфликты с существующими жестами

| С чем конфликт | Разрешение |
|---|---|
| Обычный тап | В Технике «Своё» карточка некликабельна — конфликта нет. Гард всё равно ставится: защита звезды и совместимость с будущими экранами, где карточка кликабельна (пикер) |
| Drag&drop плиток [UX-T14] | Не пересекаются: drag слушает `.expill` (плитки активной тренировки), хелпер — `.excard` в списке Техники. Обе системы — pointer-делегаты на document; на элементе срабатывает только «свой». **Правило на будущее** ([UX-I20]): на одном элементе drag и контекст-меню не совмещать; если появятся — drag (650 мс) объявляется в хелпере параметром `delay` и перехватывает жест первым |
| Скролл | Отмена движением 14px до срабатывания; после срабатывания страница под модалкой заблокирована фоном (как у всех модалок) |
| Нативное контекст-меню (Android/WebKit long-press) | `contextmenu` → `preventDefault()` на целевых карточках (паттерн app.js:2432); `.lp-hold` ставит `user-select:none` + `-webkit-touch-callout:none` (паттерн `.exhold`, style.css:730) |
| Десктоп | Удержание левой кнопки мыши = тот же pointer-жест (работает из коробки). Рекомендация: правый клик (`contextmenu` с `pointerType === 'mouse'`) открывает то же меню — бесплатно для ручного теста и e2e (вопрос 3) |

### 5.5 Что переиспользуют следующие экраны

Хелпер (делегат + state machine + гард + хаптик) переезжает как единый модуль; экран подключает селектором и обработчиком `onLongPress(name)`. Разметка: `data-custom` в T18 — пример нейтрального `data-lp` в будущем (переименование атрибута — решение кодера при обобщении, вне T18).

## 6. Контекстное меню (bottom sheet)

Макет: `exr-i8-remove-custom.html`, Э2. Открывается через `openModal()` — та же механика, что у всех модалок приложения (фон закрывает, safe-area, скролл).

### 6.1 Почему bottom sheet, а не popup у пальца

| Bottom sheet (выбрано) | Popup у пальца (отклонено) |
|---|---|
| Единый язык модалок приложения — уже 10+ экранных шитов через `openModal` | Новая система координат: позиционирование, флип у краёв, safe-area, z-слои |
| Пункты на всю ширину — помещаются длинные подписи будущих пунктов | Узкий попап ломается на длинных названиях упражнений |
| Палец не закрыл собой меню — цели под шитом видны (затемнённый список) | Меню у пальца физически накрывает карточку, с которой работают |
| Telegram Mini App — шиты привычны пользователю хоста | Нативных попапов в WebKit-webview нет, «свой» попап выглядит чужим |
| Дешёвое расширение: пункт = строка в разметке | Дорогая поддержка на каждом новом пункте |

## 8. «Исторические» упражнения

### 8.1 Проблема воскрешения

`ownCustomNames()` = **база ∪ история** (§3). Удаление имени из базы (`gymCustomEx`) НЕ убирает его из списка, пока существует хоть одна тренировка с этим упражнением. Без дополнительных мер «удалённое» упражнение останется в «Своё» с полным правом — пользователь нажал «Удалить», а карточка на месте.

### 8.2 Варианты

**(а) Показывать как сейчас, с пометкой «в тренировках», без повторного удаления.**
Карточка остаётся, теги `#своё · в тренировках`, долгий тап не открывает меню (или показывает неактивный пункт).
− Пользователь просил удалить — карточка осталась: ощущение сломанной кнопки, нужен объясняющий текст «почему нельзя».
− В списке смешиваются «живые» и «удалённые» — подсказки продолжают толкать то, от чего пользователь избавлялся.
− Новое понятие «удалено, но показываем» требует отдельного стиля и состояний.

**(б) Скрывать из подсказок после удаления — РЕКОМЕНДАЦИЯ.**
Удалённое исчезает из «Своё» (Техника), «Коллекции → Свои» (пикер) и подсказок целей — везде, где список строится от `ownCustomNames()`. В прошлых тренировках остаётся (решение 1 — не нарушается: тренировки не трогаем, меняется только список *подсказок*).
+ Удаление ведёт себя как удаление: нажал — исчезло.
+ Список «Своё» = то, чем пользователь реально пользуется.
+ Механика простая (§8.3), после миграции [EXR-S5] переезжает на сервер без изменений формата.

### 8.3 Механика (для варианта (б))

- **Томстоны:** localStorage `gymCustomExHidden: string[]` (имена). `removeCustom(name)` = убрать из `gymCustomEx` + добавить в `gymCustomExHidden`.
- **Фильтр:** `ownCustomNames()` возвращает union **минус томстоны** (одно место — все потребители: Техника 2770, пикер 4279, подсказки целей 3398 — ведут себя согласованно). `customBase()` не фильтруется (она и так без удалённых).
- **Раз-скрытие:** `createCustom()` с тем же именем убирает имя из томстонов (сценарий E) — пересоздание возвращает упражнение в подсказки. `addCustomBase` дедуплицирует базу, но томстон чистить обязательно.
- **Размер:** массив имён, растёт медленно, без чистки — норма.

### 8.4 Совместимость с [EXR-S5] (миграция «Своих» на сервер)

Если к моменту реализации T18 база уже на сервере (`G.customEx`): томстон = поле `G.customExHidden` (массив строк), `removeCustom` = правка двух массивов + `save()` (цикл /api/save с rev-контролем уже решает конфликты вкладок). Если ещё в localStorage — схема §8.3. Формат совместим 1:1, порядок работ не влияет на дизайн. **Обратная совместимость данных обязательна** (эталон `GymContractTest`): старые файлы без поля читаются с `[]`.

## 9. Обнаруживаемость и пустые состояния

- **Строка-совет** над списком в режиме «Своё» (Техника), при непустом списке: `Совет: долгий тап на упражнении — меню`. Стиль — muted 12px, **без** янтарного `.hint`: подсказка постоянная, должна быть тише контента. Макет Э1.
- Показывать также в «Коллекции → Свои» Техники (та же ветка рендера) — не нужно: подсказка один раз на ветку `techOwnMode()`.
- Не прячем после первого использования (без флага-состояния): одна тихая строка дешевле, чем новый ключ localStorage и логика «увидел/не увидел». Пересмотр — если владелец попросит (вопрос 5).
- **Пустое состояние** — существующий текст без изменений: `Своих упражнений пока нет — добавь их из тренировки («✍️ Своё упражнение»)`. Макет Э5.
- «Что нового»/туториал: экрана changelog в продукте нет; онбординг [ONB-T4] фиксирован на активной тренировке — шаг не добавляем (§13).

## 10. Граничные случаи

| Кейс | Поведение |
|---|---|
| Упражнение в **активной** тренировке (запись идёт, CUR) | Удаление из базы работает; тренировка не трогается — упражнение остаётся в карточке, записи продолжаются, `.restline` живёт. После завершения — обычная история. Основание: решение 1 + риск сломать идущую тренировку. Формально после удаления имя попадает в томстоны и из подсказок уходит — тренировке это не мешает (она рендерит свои `w.exercises`) |
| Удалён **последний** «свой» | Пустое состояние §9 (Э5) |
| Повторный тап по карточке, пока меню/анимация | Меню одно: LP — синглтон (второй pointerdown игнорируется), модалка перехватывает ввод (фон), `__lpGuard` гасит призрачный клик 450 мс. Двойное «Удалить» невозможно — диалог заменяет содержимое той же модалки |
| Долгий тап на **звезде** | Не стартует (исключение `[data-fav]` в контракте §5.1); тап по звезде — обычный тогл |
| Карточки **каталога** рядом | В Технике «Своё» их нет, но защита структурная: хелпер реагирует только на `[data-custom]`, каталог-карточки атрибут не получают. «Все»/«★ Любимые»/поиск — долгий тап ничего не делает (Э6) |
| Пересоздание удалённого имени | Томстон снят при `createCustom` (§8.3) — снова в подсказках |
| Удалённое было в ★ Любимых | Рекомендация: при `removeCustom` убрать имя и из `gymFavs` (только если `isCustomEx(name)`) — иначе после [EXR-S6] в «★ Любимые» попадёт призрачная звезда упражнения, которого нет в базе (вопрос 4) |
| Оффлайн | localStorage синхронен — удаление всегда применяется локально; после [EXR-S5] — очередь `save()` как у всех правок |
| Светлая тема | Только токены: `--danger`, `--btn`, `--glow-brd` двухтемные (style.css:14/72); новой палитры нет |
| Быстрый тап (не удержание) | Ничего не делает: карточка в Технике некликабельна (как сегодня); в макете Э6 — поведение каталога для сравнения |
| Имя с кавычками/эмодзи | Имя экранируется `esc()`/`escAttr()` как везде; в диалоге — внутри „ёлочек" |

## 12. Acceptance-критерии (для e2e)

1. Долгий тап ~500 мс на карточке «своего» в Технике «Своё» → открывается меню: имя упражнения, «🗑 Удалить упражнение» красным, «Отмена».
2. Быстрый тап по той же карточке — ничего (карточка некликабельна, как сегодня); тап по звезде — тогл ★, меню не открывается.
3. Скролл, начатый на карточке — скроллит список, меню не открывается (порог 14px).
4. Долгий тап на карточке каталога («Все», «★ Любимые», поиск) — ничего.
5. «Отмена» и тап по фону закрывают меню; состояние списка не изменилось.
6. «🗑 Удалить упражнение» → диалог: «Удалить упражнение „X"?» + пометка про тренировки; «Оставить» закрывает без изменений.
7. «Удалить» в диалоге: карточка исчезла из «Своё»; повторное открытие списка (пере-рендер) — не вернулась.
8. Тренировки с удалённым не изменились: даты, сеты, вес на месте (проверка в календаре).
9. Пикер «Коллекции → Свои» и подсказки целей — удалённого нет (при варианте (б)).
10. «✍️ Своё упражнение» с тем же именем → снова в «Своё» (томстон снят).
11. Удаление последнего → пустое состояние §9.
12. Активная тренировка с удаляемым упражнением: запись продолжается, после завершения история на месте.
13. Нативное контекст-меню (Android long-press) на карточке не открывается.
14. Светлая тема: меню и диалог читаемы, danger-акценты на месте.
15. Строка-совет «долгий тап — меню» видна при непустом списке «Своё».

## 13. Что НЕ делаем и почему

| Отсечено | Почему |
|---|---|
| Popup-меню у пальца | §6.1: позиционирование у краёв, накрывает цель, чужой для приложения паттерн, дороже в расширении |
| Undo/корзина удалённых | Усложнение без запроса владельца; пересоздание с тем же именем (§8.3) закрывает главный сценарий «удалёл зря» |
| Мультивыбор/массовое удаление | Списки «Своих» короткие; режим выделения — отдельная механика, отдельный тикет |
| Меню на карточках каталога | Каталог общий для всех пользователей — удалять его точки нельзя по определению |
| Пикер «Коллекции → Свои» в этом релизе | Скоуп зафиксирован (решение 3); карточки там кликабельны (выбор в тренировку) — жест конфликтует с быстрым выбором, стоит отдельной проверки. Хелпер §5 готов к подключению — вопрос 6 владельцу |
| Правка/удаление в прошлых тренировках | Запрещено решением 1 |
| Тост «Удалено» | Исчезновение карточки — само по себе подтверждение; лишний шум. (Тост оставлен кодеру как опция, если появится сценарий «удалил, но не заметил») |
| «Что нового»/шаг онбординга про жест | Экрана changelog нет; ONB-шаги про активную тренировку. Обнаруживаемость — строка-совет §9 |
| Переименование/«в коллекцию» в меню | Слот §6.2 заложен, пункты — отдельные тикеты семьи [EXR-I8] |
