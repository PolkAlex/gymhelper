# Спецификация [UX-T15] #106: «Разминка 10 мин» — время разминки входит в тренировку

**Автор:** агент design · **Дата:** 08.11.2026
**Тикет:** #106 [UX-T15] · Направление: UX · Метка: `need_design` · Статус: In Design

## 1. Цель и проблема

Желание владельца: **«Разминка 10 мин» как готовый шаблон; время разминки считается
временем тренировки**.

Сейчас пользователь, который разминается до того, как жмёт «Начать тренировку» (типичный
сценарий: пришёл в зал → размялся → открыл приложение), получает заниженную длительность
и ккал: `started` фиксируется в момент тапа, разминка в дневник не попадает никак. Добавлять
разминку «упражнением» нельзя — это замусоривает список записей и ломает объёмную MET-модель
(у разминки нет подходов с весом).

**Решение в одном абзаце:** быстрое действие **«🤸 Разминка 10 мин»** (в модалке старта и
чипом на карточке активной тренировки), которое сдвигает `started` на −10 минут и ставит
опциональный маркер `wm: 10`. Длительность и ккал пересчитываются сами — и в Mini App,
и в боте, потому что оба считают их из `started`. Никаких фиктивных упражнений, шаблон
`Template` не расширяется.

---

## 2. Выбор пути: действие (А) vs системный шаблон (Б)

### 2.1. Вариант А — действие со сдвигом `started` (РЕКОМЕНДОВАН)

Сдвиг `started` — единственная операция, при которой «время разминки считается временем
тренировки» выполняется **бесплатно и одинаково в MA и боте**: `durationMin` (app.js:203)
и `calcKcal` (BotLogic.java) читают `started`, поэтому длительность, пилл «🕐 с 11:15»,
ккал-пилл, прогресс и «🔥 Ккал» бота обновляются без единой ветки «если разминка».

### 2.2. Вариант Б — системный пресет-шаблон (ОТСЕЧЁН)

Модель `Template` — это **снимок списка упражнений** (`Template.java`: id, name, createdAt,
exercises). «Шаблон разминки» в неё не ложится:

- либо он добавлял бы разминочные упражнения в список тренировки — прямо противоречит
  требованию «БЕЗ добавления фиктивных упражнений» и портит объём/ккал-модель;
- либо старт из него делал бы «что-то другое» (сдвиг времени) — тогда нужен флаг
  «системный» в схеме `Template`, исключения во всех местах рендера списков шаблонов
  (MA `openStartModal`, бот `/templates`), в лимите 20, в подтверждении удаления, в
  «💾 В шаблоны» — много кода ради действия, которое вариантом А решается одной кнопкой;
- семантика «шаблон = список упражнений на старт» сломалась бы для пользователя: тап
  по шаблону создавал бы пустую тренировку с сдвинутым временем.

**Вывод: берём вариант А.** Слово «шаблон» из формулировки тикета трактуем как «готовое
быстрое действие» — по пользовательскому смыслу это ровно то, что просил владелец
(«разминка 10 мин» в один тап, время входит в тренировку).

## 3. Данные: опциональное поле `Workout.warmupMin`

### 3.1. Поле

```java
public final class Workout {
    /* …существующие поля… */
    /* [UX-T15] учтённая разминка, мин; 0 = нет (старые данные). Только 10 в v1. */
    public int warmupMin = 0;
}
```

| Свойство | Значение |
|---|---|
| JSON-ключ | **`wm`** (короткий стиль как `st/en/pw/ps/pr`) |
| Чтение | ключа нет → `0` — старые файлы читаются как раньше |
| Запись | пишется **только при `wm > 0`** — файлы без разминки остаются байт-в-байт прежними (тот же принцип, что `templates`/`del`/`pw-ps-pr`) |
| Значения | v1: только `10`. Формат допускает другие, но UI их не создаёт |

Зачем поле, если время уже сдвинуто: (1) **тогл** — без него второй тап сдвинул бы ещё на
−10 мин; (2) **маркер-пилл** «🤸 разминка 10 мин» в карточке; (3) **наследование** в
«🔁 Повторить прошлую»; (4) подсказка в ретро-модалке `timeModal`.

### 3.2. Контракт

`GymContractTest` дополнить: (а) legacy-файл без `wm` читается, `warmupMin == 0`;
(б) round-trip тренировки с `wm: 10` сохраняет ключ; (в) `wm: 0`/отсутствие → ключ
в JSON **не пишется**.

## 4. Поведение: две точки входа, один механизм

### 4.1. Быстрое действие в модалке старта

`openStartModal()` (`web/app.js:1907`) получает кнопку между «С пустого списка» и
«Повторить прошлую»:

```
┌──────────────────────────────────────┐
│ 🏋️ С пустого списка                  │  ← .bigstart (prime), как сейчас
│ 🤸 РАЗМИНКА 10 МИН                   │  ← .bigstart.alt
│    старт с −10 мин · войдёт в ккал   │     (.sub — подзаголовок)
│ 🔁 Повторить прошлую                 │  ← .bigstart.alt, как сейчас
│    03-11, Вт · 4 упр. · 🤸 с разм.   │
│ 📋 Шаблоны …                         │  ← без изменений
└──────────────────────────────────────┘
```

Действие: `startWarmupWorkout()` — то же, что `startBlank()`, но
`started = nowLocalISO() − 10 мин`, `wm = 10`, тост «🤸 Разминка учтена: тренировка с 11:15».
Проходит через существующий `activeConflictAsk()` [UX-B7] — при активной тренировке
диалог «Продолжить/Удалить и начать новую» работает как раньше.

> У новичка (нет ни истории, ни шаблонов) модалка не открывается [UX-T7] — действие
> доступно ему чипом на карточке (§4.2).

### 4.2. Чип на карточке активной тренировки

В ряд пилюль `.wcpill` (`workoutCard`, app.js:1129–1140) у **активной** тренировки
добавляется чип-кнопка ( ACTIONS: `warmupToggle`, `data-a = w.id`):

| Состояние | Вид чипа | Тап |
|---|---|---|
| разминки нет | `🤸 Разминка` (приглушённый, стиль .wpill) | `started −= 10 мин`; `wm = 10`; `date = дата(new started)`; тост «🤸 +10 мин разминки — начало сдвинуто на 11:15» |
| разминка есть | `🤸 разминка 10 мин` (янтарный, акцент) | `started += 10 мин`, но **не позже `now`** (clamp §6.10); `wm = 0`; тост «Разминка снята — начало возвращено» |

Чип **не рендерится** у завершённой тренировки (принцип [UX-T19]: минимум действий
на завершённой; ретро-случай — §6.5).

После любого тапа — `save()` + `render()`: пилл «🕐 с HH:MM», ккал-пилл и маркер
обновляются сразу.

### 4.3. Семантика (важно для текстов)

Действие означает: **«я размялся 10 минут до того, как начал тренировку»** — поэтому
`started` уходит назад. Если пользователь стартует ПЕРЕД разминкой (жмёт «Начать», потом
разминается), ничего отмечать не нужно: `started` уже стоит до разминки, и эти минуты
сами войдут в длительность и ккал. Оба сценария покрыты, отдельных режимов не заводим.

## 5. Ккал и время

### 5.1. MET-коэффициент разминки

**MET 3.0** — по каталогу проекта: «Кардио-разминка (ходьба/лёгкий бег)» (`wcardio`) = 3.0;
статические разминочные вращения = 2.5. Диапазон из задачи 2.8–3.5 — берём нижнюю середину.

Справочная формула (для документации и подсказок, **не** отдельный расчёт в коде):

```
ккал_разминки = 3.0 × 3.5 × вес / 200 × 10 = 0,525 × вес(кг)
  60 кг → ≈32 ккал · 80 кг → ≈42 ккал · 100 кг → ≈53 ккал
```

### 5.2. Как ккал считаются на самом деле (одна модель, без раздвоения)

Ккал по-прежнему считаются общей формулой от **полной** длительности
(`started → now/ended`, кап 240 мин): `MET × 3.5 × вес ÷ 200 × минуты`.

**Единственная правка модели — знаменатель MET-тира.** Сейчас `perMin = объём / все минуты`
(`calcWorkoutKcal` app.js:328, `calcKcal` BotLogic.java). Предлагается:

```
perMin = объём / max(все_минуты − wm, 1)     ← интенсивность по «основной» части
MET-тир по perMin — без изменений (3.5 / 5.0 / 6.0)
ккал = MET × 3.5 × вес / 200 × все_минуты    ← полная длительность, кап 240
```

Правка синхронная в обоих местах (иначе числа MA и бота разойдутся). Для тренировок
без `wm` — ноль изменений поведения (делитель совпадает со старым).

**Зачем:** без этой правки добавление разминки может **понизить** ккал. Пример-парадокс:
объём 4000 кг за 32 мин → perMin 125 → MET 5.0 → 269 ккал; с разминкой 42 мин →
perMin 95 → MET 3.5 → 206 ккал. «Добавил разминку — ккал упали» выглядит как баг
(и владельцем будет зафиксирован). С правкой: perMin остаётся 125 → MET 5.0 →
269 → **336 ккал**. Побочный эффект: прирост за разминко-минуту тарифицируется по тиру
основной работы (49–70 ккал за 10 мин при 80 кг), а не строго по 3.0 (≈42) — в пределах
точности дискретной MET-модели, отдельно не показываем (§10).

### 5.3. Отображение

| Место | Было | Стало (wm=10, сдвиг применён) |
|---|---|---|
| `.wcpill` карточки | `🕐 с 11:25 · 🔥 196 ккал · 🏋 6 подх.` | `🕐 с 11:15 · 🔥 245 ккал · 🏋 6 подх. · 🤸 разминка 10 мин` (маркер-пилл стиль .wpill, иконка/эмодзи 🤸) |
| Завершённая карточка | `🕐 11:25–12:05 · 🔥 …` | `🕐 11:15–12:05 · 🔥 … · 🤸 разминка 10 мин` (маркер-пилл без кнопки) |
| Превью в истории (`previewCard`) | `🕐 с 11:15` | **без маркера** — время уже отражает сдвиг, пилл-стек не расширяем |
| Пустая тренировка | — | `🕐 с 11:15 · 🤸 разминка 10 мин`; ккал-пилл скрыта (total = 0 — существующая логика `calcWorkoutKcal`) |
| Ретро-модалка `timeModal` | поля дат/времени | + строка-подсказка при `wm > 0`: «🤸 В длительность входит разминка 10 мин — поле „Начало“ уже сдвинуто» |

## 6. Edge-кейсы

1. **Тап на свежесозданной тренировке** (`started = now`): сдвиг назад, длительность сразу
   «10 м» при нуле записей — корректно, ккал-пилл не показывается.
2. **Полуночный переход**: `started` 00:05 → сдвиг уводит на 23:55 вчера. После сдвига
   `w.date = дата(new started)` — так же, как поступает `saveTime` в `timeModal`;
   `durationMin`/ккал считают от ISO-дат и не ломаются; заголовок карточки (`firstLine`)
   покажет предыдущий день.
3. **Двойной тап**: тогл (§4.2) — второй тап снимает разминку, сдвиг не суммируется.
4. **Ретро-ввод `timeModal` после разминки**: поля работают как раньше; ручная правка
   «Начало» **не сбрасывает** `wm` (маркер остаётся честным: «в длительность входит
   разминка 10 мин»); подсказка из §5.3 видна, пока `wm > 0`.
5. **Тренировка уже завершена (ретро-случай)**: чип «🤸» не рендерится. Путь: «⏱ Время» →
   вручную сдвинуть начало на −10 мин — длительность и ккал пересчитаются сами, маркер
   не ставится (осознанное упрощение v1; вопрос владельцу — §11.1).
6. **«🔁 Повторить прошлую»**: если в источнике `wm = 10` → `createFromList` создаёт
   тренировку с `started = now − 10`, `wm = 10`; подзаголовок кнопки получает «· 🤸 с
   разминкой» (`newRepeatLast`/`newRepeatFrom` прокидывают `warmupMin` источника).
   Старт из настоящего шаблона (`tplStart`) — **без** разминки: схему `Template` не
   расширяем (§2.2), пользователь ставит разминку чипом на карточке.
7. **Пустая тренировка / удаление**: тап «🤸» на пустой карточке легален; удаление
   тренировки (`deleteWorkout`) удаляет `wm` вместе с ней — спец-веток нет.
8. **Конфликт активной тренировки [UX-B7]**: быстрое действие модалки старта идёт через
   `activeConflictAsk()` — вторую незавершённую не создаём.
9. **Таймер отдыха / «автопауза»**: фича не трогает `REST` (`restbar`, `REST.paused`) —
   тап «🤸» во время отсчёта безопасен, панель переживает `render()` как всегда.
10. **Clamp toggle-off**: если тренировка идёт < 10 мин (`started = now − 3`), снятие
    разминки клампится: `newStarted = min(started + 10, now)` — время в будущее не уходит,
    отрицательной длительности нет.
11. **Старые данные / оба клиента**: файлы без `wm` читаются с `warmupMin = 0`;
    старый бот + новое MA (или наоборот) до деплоя: неизвестный ключ игнорируется,
    маркер/наследование теряются, но время (главное) уже в `started` — ничего не ломается.
    Деплой атомарный, как всегда.
12. **Кап 240 мин**: длительность с разминкой > 240 → ккал по 240 (существующий кап
    `KCAL_MAX_MIN`), предупреждение бота «(в расчёте учтено 240 мин)» работает как раньше.

## 10. Тест-кейсы e2e (Playwright, `tests/e2e.spec.js`)

1. **Старт с разминкой из модалки**: есть история → FAB → «🤸 Разминка 10 мин» → на сервере
   `started` ≈ now−10 мин (±2 мин), `wm = 10`, тост виден, пикер открыт.
2. **Чип тогл на карточке**: активная тренировка → тап «🤸 Разминка» → пилл «🕐 с HH:MM»
   сдвинулся на −10 мин (±1), маркер «🤸 разминка 10 мин» появился; повторный тап —
   время вернулось, маркер исчез, `wm` на сервере = отсутствует/0.
3. **Ккал растут от разминки** (без парадокса): тренировка с объёмом из e2e-фикстуры →
   тап «🤸» → число в 🔥-пилле не уменьшилось; при MET-тире 3.5 прирост ≈ 0,6125 × вес.
4. **Полуночный сдвиг**: тренировка с `started = 00:04` (через `timeModal`) → тап «🤸» →
   `date` и заголовок карточки = предыдущий день, `durationMin > 0`.
5. **Ретро-ввод не сбрасывает разминку**: включить «🤸» → `timeModal` → поменять время →
   сохранить → маркер на месте, `wm = 10` на сервере.
6. **Завершённая без чипа**: завершить тренировку с разминкой → маркер-пилл виден,
   кнопки `warmupToggle` нет; `aria-label` отсутствует.
7. **Повторить прошлую с разминкой**: завершить тренировку `wm=10` → «🔁 Повторить прошлую»
   → новая тренировка `wm = 10`, `started ≈ now−10`, подзаголовок с «🤸 с разминкой».
8. **Legacy**: JSON без `wm` → чип «🤸 Разминка» в выключенном состоянии, пиллы как сейчас;
   после включения файл на сервере содержит `wm` (round-trip).
9. **Новичок**: чистые данные → FAB стартует мгновенно (без модалки) → чип «🤸 Разминка»
   доступен на карточке.

## 11. Что НЕ делаем и почему

| Отсечено | Почему |
|---|---|
| **Вариант Б — системный шаблон** в списке шаблонов | §2.2: ломает семантику `Template`, требует флага-исключения во всех списках MA и бота; решается одной кнопкой варианта А |
| Разминочные упражнения из каталога в список тренировки | Прямо противоречит требованию владельца; портит объёмную модель и список записей (существующий фильтр `isWarmupName` в `previewCard` остаётся для legacy-случаев) |
| Отдельная ккал-строка разминки в MA | Раздваивает расчёт, усложняет per-exercise разбивку `lines`; прирост и так виден в 🔥-пилле (§5.2) |
| Точный «смешанный» тариф (осн. по тиру + разминка по 3.0) | Две правки формулы в MA и боте вместо одной; выигрыш ≈10–25 ккал — в пределах погрешности дискретной MET-модели. Вернуться при фидбэке владельца |
| Настраиваемая длительность разминки (5/10/15 в Профиле) | v1 — фикс 10 мин (формулировка владельца); поле `wm` допускает значения, UI-настройку можно добавить отдельным тикетом |
| Кнопка «🤸» в боте и строка в «🔥 Ккал» бота | v1 — MA-фича; бот совместим без UI-изменений (§7, вопрос владельцу) |
| Ретро-чип на завершённой тренировке | Принцип [UX-T19] минимум действий; есть ручной путь через «⏱ Время» (§6.5) |
