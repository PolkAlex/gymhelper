**Тикет:** #353 [UX-S17] · Направление: UX · Метка: `need_design` · Статус: In Design

**Макет:** `docs/mockups/ux-s17-notes.html` (ред. 2)

> **Ред. 2 — что изменилось.** Владелец отклонил решения ред. 1: пилюля «📝 Заметка»,

> с `nutrition`, редактирование у завершённых, отсутствие заметки в share/шаблонах, бот вне v1.

---

## 1. Цель и проблема

Желание владельца: **писать текстовые заметки во время тренировки** в Mini App — самочувствие,
как идёт упражнение, мысли про веса («в следующий раз попробовать 50 кг»).

Сейчас этому контенту некуда деться: карточка тренировки — это только подходы (вес × повторы),
питание (`nutrition`) и название (`title`). Свободные мысли остаются в голове или в заметках
телефона — вне дневника, и через неделю недоступны именно в контексте той тренировки.

**Решение в одном абзаце (формулировка владельца):** «Текстовое поле, в нём "Добавить заметку"
и всё. Поле расширяется на 4 строки текста, дальше скролл. Не надо кнопок сохранить и
предлагать предыдущую заметку. Просто поле для ввода текста.» — одно поле `textarea` в карточке
тренировки (активной и завершённой), автосохранение в существующую очередь `save()`, хранение —
опциональный ключ `note` на объекте тренировки. Старые файлы без `note` читаются как раньше
(GymContractTest). Бот в v1 не меняется.

## 2. Решение: поле заметки в карточке

### 2.1. Что это

Обычная `textarea` в стиле полей приложения (фон `--field`, рамка `--field-brd`, радиус 12px,
паддинги 10px 12px, шрифт 15px — как `input/textarea` в `web/style.css`), встроенная в карточку
тренировки. Никаких дополнительных обёрток-кнопок вокруг неё.

| Свойство | Значение |
|---|---|
| Плейсхолдер | `Добавить заметку` |
| Авто-высота | старт — 1 строка; растёт с вводом; **максимум 4 строки** (высота фиксируется), дальше внутренний скролл (`overflow-y: auto`) |
| maxlength | 1000 символов (тихая обрезка, без тоста; вопрос 1000 vs 2000 — §8) |
| Мультистрочность | переносы `\n` сохраняются и отображаются |
| Автосохранение | без кнопок: debounce ~800 мс после последнего ввода + на потере фокуса (blur) — §3 |
| Где | в карточке **активной** и **завершённой** тренировки, одна и та же точка: после блока упражнений (у активной — после «➕ Добавить упражнение», у завершённой — после «📤 Поделиться»), до details-аккордеонов |

### 2.2. Место в карточке (активная тренировка)

```
┌─ карточка тренировки ──────────────────────┐
│ шапка: название ……………… ⏱                   │
│ [ 🕐 с 18:30 | 🔥 210 ккал | 🏋 12 подх. ]   │
│ (🥤 питание — если задано)                  │
│ ▸ плитка упражнения 1 (+ Добавить подход)   │
│ ▸ плитка упражнения 2 (+ Добавить подход)   │
│ [ ➕ Добавить упражнение ]                  │
│ ┌─────────────────────────────────────────┐ │
│ │ Добавить заметку          ← textarea    │ │
│ └─────────────────────────────────────────┘ │
│ ▸ 📈 Прогресс (в разработке)                │
└─────────────────────────────────────────────┘
```

Основной поток ввода подходов (плитки + добавление упражнения) остаётся верхним и нетронутым;
поле заметки — нижний «хвост» карточки, оно не перекрывает и не сдвигает существующие блоки.

### 2.3. Завершённая тренировка

То же самое поле (с текстом, если заметка была). Редактирование у завершённых разрешено —
как `titleModal`/питание сегодня (существующий `isDirty`-флоу открытой карточки). Отдельный
«блок для чтения» не нужен: поле с текстом и есть отображение заметки; чтение = взглянуть,
редактирование = тапнуть и писать.

### 2.4. Поведение авто-высоты (требование к реализации)

- Начальная высота — одна строка (с плейсхолдером).
- На каждый ввод: `height: auto` → `scrollHeight`, высота поля следует контенту.
- При достижении 4 строк высота фиксируется на 4 строках; дальнейший текст скроллится
  внутри поля (`scrollHeight > clientHeight`), курсор остаётся видимым (авто-скролл к
  позиции курсора — нативное поведение `textarea`).
- Пересчёт высоты — при вводе и при программном заполнении (рендер карточки с существующей
  заметкой: поле сразу рисуется своей высотой, без «прыжка»).
- `resize: none` (нативная ручка ресайза не нужна).

## 3. Автосохранение (честно по коду `web/app.js`)

Как устроено сохранение в приложении сегодня:

- `save()` (app.js:511) — **очередь-цепочка** `__saveChain`: каждое сохранение ждёт завершения
  предыдущего, POST `/api/save` c `rev` и данными; ответ обновляет `G.rev`.
- Тосты **ошибок** показывает сам `doSave()` (app.js:516): «Данные были удалены — приложение
  обновлено» (409), «Ошибка сохранения: сервер ответил N», «Ошибка сохранения: нет связи с
  сервером».
- Тост **успеха** показывает вызывающий код (`save().then(r => r === 'ok' && toast('✓ Сохранено'))`)
  — и только у явных действий (модалки питания/названия, запись подхода).
- **Ближайший существующий паттерн автосейва — drag-перестановка упражнений** (app.js:2447):
  `save()` молча при успехе, ошибки — тосты `doSave`, после — `render()`.

**Заметка встраивается в этот же цикл:**

| Момент | Поведение |
|---|---|
| Ввод символов | обновляется только `w.note` в памяти; таймер debounce перезапускается |
| 800 мс тишины после ввода **или** blur | `save()` — **без тоста успеха и без `render()`** (render сбросил бы фокус/курсор; полю заметки рендер не нужен — высоту оно пересчитало само) |
| Ошибка сохранения | штатные тосты `doSave` (409/сервер/нет связи) — пользователь видит проблему, текст остаётся в поле и в `w.note`; следующее сохранение (правка или любая другая запись) повторит попытку через очередь |
| Переключение экрана/закрытие приложения до таймера | на `blur`/`visibilitychange` триггерить отложенный `save()` немедленно (финальный flush) — чтобы пауза «набрал и спрятал телефон» не теряла хвост текста |
| Параллельные сохранения | очередь `__saveChain` уже сериализует; заметка не делает ничего сверх неё |

Тоста «✓ Сохранено» на каждый автосейв **нет** — иначе ввод длинной заметки заспамит тостами
(это противоречило бы и духу правки владельца «не надо кнопок»).

## 4. Тексты интерфейса (единый источник для coder)

| Место | Текст |
|---|---|
| Плейсхолдер поля | `Добавить заметку` |
| Тосты ошибок | существующие тексты `doSave` — без изменений («Ошибка сохранения: нет связи с сервером» и др.) |
| Тост успеха | НЕТ (автосейв молчит) |
| maxlength-обрезка | тихая, без тоста |

Больше новых текстов нет — по замыслу владельца «просто поле».

## 5. Хранение: требования к GymData (без изменений с ред. 1; только требования)

Объект тренировки (`Workout`) дополняется **одним опциональным полем** свободного текста.

| Свойство | Требование |
|---|---|
| JSON-ключ | **`note`** на объекте тренировки (верхний уровень `wm`, рядом с `nutrition`) |
| Тип | строка (`String`); `null` = заметки нет |
| Чтение | ключа нет → `null` — **старые файлы читаются как раньше**; мусорное значение (число/объект) → игнор без падения чтения файла (паттерн `shareId`); читается как есть, включая `\n` |
| Запись | ключ пишется **только когда заметка непустая** (trim ≠ ""); пустая/отсутствующая — ключа в JSON нет: файлы пользователей без заметок остаются байт-в-байт прежними (принцип `templates`/`del`/`pw-ps-pr`/`birthYear`) |
| Позиция в карте | после `nutrition`, до `shareId` (группировка «метаданные тренировки»; позиция нового ключа на чтение старых файлов не влияет) |
| Лимит | enforcing 1000 — на стороне UI; серверный парсер не режет и не валидирует длину (не теряем легаси-данные) |
| Совместимость контракта | GymContractTest: (1) эталонный файл **без** `note` читается, `note == null`, `toJson()` не добавляет ключ; (2) файл **с** `note` (строка с `\n` и эмодзи) — round-trip сохраняет строку |
| Шаблоны | `Template` НЕ расширяется (шаблон = список упражнений, заметка не часть шаблона) |
| Экспорт/шеринг | заметка НЕ включается в share-картинку/текст [UX-I14/I16]; `/export` из полного `toJson()` получит поле естественным образом |
| Мультиустройство/rev | заметка — обычное поле тренировки в существующем save()-флоу (`rev`, 409-конфликты обрабатываются существующей механикой `doSave`) |

JS-сторона: у новых тренировок поле создавать не обязательно (`w.note` — undefined работает
как «пусто»); единая точка правды `w.note: string|null`.

## 6. Состояния и edge cases

| Случай | Поведение |
|---|---|
| Пусто (нет ключа / null / "") | поле одной строки с плейсхолдером «Добавить заметку» |
| Фокус/ввод | рамка поля — акцентная (`:focus` → `border-color: var(--accent)`, существующий стиль полей); высота растёт до 4 строк |
| Текст длиннее 4 строк | высота зафиксирована на 4 строках, внутренний скролл; курсор виден |
| 1000 символов | `maxlength` обрезает тихо (в т.ч. вставку из буфера); тоста нет |
| Текст 1–3 строки при потере фокуса | высота остаётся по контенту (не схлопывается обратно в 1 строку) |
| Ошибка сети при автосейве | тосты `doSave`; текст не теряется (в поле и в `w.note`); повтор — при следующей правке/записи через очередь |
| 409 conflict | существующая механика («Данные были удалены — приложение обновлено» + перечитывание) |
| Многострочный текст | сохраняется с `\n` как есть |
| Эмодзи/кавычки/`<script>` | поле `textarea` безопасно по определению; при любом будущем выводе заметки в текст — `esc()` (как везде) |
| Данные длиннее 1000 (легаси) | отображаются и сохраняются как есть, не режутся |
| Завершение тренировки с заметкой | `finishWorkout` поле не трогает — заметка переживает завершение |
| Удаление тренировки | заметка уходит вместе с тренировкой (поле на объекте) |
| Рендер карточки во время набора | автосейв не вызывает `render()`; если рендер случился по другой причине (например, drag) — значение берётся из `w.note`, несохранённый хвост может сброситься до последнего автосейва: debounce 800 мс делает окно потерь пренебрежимым (меньше, чем разрыв между подходами) |
| Очистка поля пользователем | пустая строка → при автосейве `w.note = null` (ключ в JSON не пишется) |

Загрузочное состояние — без скелетонов (поле из локального состояния `G`, открывается мгновенно).

## 7. Что НЕ делаем и почему

**Отклонено владельцем 23.11.2026 (ред. 1 → ред. 2):**

| Вариант ред. 1 | Причина отклонения (фидбек) |
|---|---|
| Пилюля «📝 Заметка» как точка входа | «не так» — лишний посредник; точка входа = само поле |
| Шит-модалка ввода | «не надо» — ввод сразу в карточке |
| Кнопки «💾 Сохранить» / «🚫 Очистить» | «не надо кнопок сохранить» — автосохранение |
| Подсказка «🗓 В прошлый раз» + чип «Вставить» | «не… предлагать предыдущую заметку» — отменена полностью |

**Отсечено по-прежнему (ред. 1, не противоречит фидбеку):**

| Вариант | Почему нет |
|---|---|
| Заметка на упражнение / на подход | перегруз плитки упражнения; запрос — поток мысли о дне; схема допускает этап 2 (ключ на `ExerciseEntry`) |
| Иконка/кнопка в шапке карточки | [UX-T23]: шапка — ТОЛЬКО «⏱ Время» |
| Кнопка в backbar | backbar — действия завершения/удаления/навигации |
| Заметка в списке подходов (entry-строкой) | смешивает структурированные записи (вес×повторы) со свободным текстом; ломает `entryLine` и ботовую карточку |
| Заметка в share-карточке/тексте [UX-I14/I16] | личные мысли не для публикации |
| Заметка в превью-карточке истории (pcard) | список плотный; заметка видна в карточке тренировки |
| Заметка в боте (v1) | пошаговый ввод текста в боте неудобен; ноль правок BotLogic = ноль регрессий (этап 2 — §8) |
| Заметка в шаблонах | `Template` — снимок списка упражнений |
| Markdown/форматирование | plain text с `\n` |
| Подтверждение на очистку поля | поле можно переписать заново, потерь «кнопки Очистить» больше нет; пустое поле = заметки нет |

## 8. Открытые вопросы владельцу (ред. 2)

1. **Лимит** — дефолт 1000 символов (`maxlength`). Если планируются «конспекты» — поднять
   до 2000. Тихая обрезка без тоста — ок?
2. **Длинная заметка в завершённой карточке** — с полем-скроллом (4 строки + внутренний
   скролл) вопрос стал менее острым, но: нужен ли разворот «на весь текст» (развернуть поле
   до конца текста тапом по индикатору) для чтения длинных заметок? Дефолт — не делать.
3. **Заметка в боте** — этап 2 по желанию (кнопка «📝 Заметка» рядом с «🥤 Питание» в ботовой
   карточке). Дефолт — не делать в v1.

## 9. Критерии приёмки (для будущих тикетов реализации)

1. Поле с плейсхолдером «Добавить заметку» в карточке активной и завершённой тренировки —
   по макету ред. 2; существующие блоки карточки не сдвинулись.
2. Авто-высота: 1 строка пусто, рост с вводом, фиксация на 4 строках, внутренний скролл дальше.
3. Автосейв: debounce ~800 мс + blur/flush — `save()` без тоста успеха и без `render()`; ошибки
   — тосты `doSave`; очередь `__saveChain` не нарушена.
4. Старый файл без `note` читается; `toJson()` без заметки не добавляет ключ (GymContractTest —
   оба кейса).
5. Заметка переживает завершение тренировки, видна в истории, не попадает в share/шаблоны.
