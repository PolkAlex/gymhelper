**Автор:** агент design · **Дата:** 19.11.2026 (ред. 2 — решения владельца по макет-ревью)
**Тикет:** #295 [UX-T40] · Семья [UX-I18] #292 · Направление: UX · Дефолт: **выкл**
**Мини-макет:** `docs/mockups/ux-t40-toggle-snippet.html` (OFF / ON со свёрнутым селектором / раскрытый лист выбора)
**Связанные:** [UX-T15] #106 «Разминка 10 мин» (`docs/spec-ux-t15-warmup.md` — сдвиг `started`, не упражнение), коллекция «Разминка и заминка» каталога (`web/catalog.js`: `warmcool`), [EXR-T4] тег `cat:warmup`
**Код этой задачей не трогается; воплощение — coder.**

## 1. Цель и пользовательская проблема

Часть пользователей каждый раз забывает про разминку: жмёт «Начать тренировку» — и
сразу идёт к рабочему весу. Владелец (решение 19.11.2026): **«дать выбор первого
упражнения самому пользователю. По умолчанию — Разминка. И по умолчанию этот
тоггл — выключен»**.

**Решение в одном абзаце:** в Настройках — карточка **«🏋️ Тренировка»**: тоггл
«Разминка первым упражнением» (дефолт — выкл, прежнее поведение) + селектор
упражнения разминки (виден при включённом тоггле). В списке селектора —
обобщённая запись **«Разминка»** (по умолчанию) и упражнения каталога с тегом
`cat:warmup`. Включён — `startBlank()` кладёт в новую тренировку первым
упражнением выбранную разминку. Ровно один раз на тренировку, в момент создания.

## 2. Селектор упражнения разминки

### 2.1. Факт каталога: упражнения «Разминка» НЕТ

Точного упражнения «Разминка» в `CATALOG` нет — `id: 'warmup'` (`web/catalog.js:142`)
это **категория тег-фильтра** («Разминка», теги `['cat:warmup']`); «Разминка и
заминка» (`warmcool`) — коллекция-категория списка «Коллекции». Реальные
упражнения разминки — элементы `CATALOG` с тегом `cat:warmup` (`wcardio`,
`wneck`, `bodysquat`, `jumpingjack` и др., ~20 шт.).

Владелец на вопрос «какое упражнение» ответил «Разминка» — реализуем это как
**системная запись «Разминка»** (первый пункт селектора, значение по умолчанию):
обобщённое упражнение без привязки к каталогу. Фильтры приложения её уже
понимают: `isWarmupName('Разминка')` → `findCatalog` = null → fallback
`/^разминка/i` = **true** (web/app.js:422) — скрытие из превью истории, из
рекордов и e1RM работает без правок кода.

### 2.2. Дефолт селектора — системная запись «Разминка» (утверждено по ответу владельца)

| Вариант | Вердикт |
|---|---|
| **(а) Системная запись «Разминка» — первый пункт списка и значение по умолчанию** | ✅ выбрано |
| (б) Дефолт = первое упражнение каталога (`wcardio`) | ❌ отсечён |

Обоснование (а): владелец явно назвал «Разминку»; конкретное каталогное
упражнение навязало бы тип разминки (кардио-разминка подходит не всем — кто-то
разминается вращениями или приседаниями без веса); «Разминка» — честная
обобщённая запись, которую пользователь при желании заменит в селекторе.
Технически выбранное имя поддержано `isWarmupName` legacy-фоллбеком (§2.1).

### 2.3. Состав и порядок списка селектора

Нижний лист **«Упражнение разминки»** (стиль пикера вида календаря
`calPickerHtml`: строки `.pli`, у выбранного янтарная отметка-точка; фон закрывает):

1. **«Разминка»** — системная запись, всегда первый пункт, подпись
   «по умолчанию» (пока значение = дефолт).
2. Далее — упражнения `CATALOG` с `exTagMatch(c, 'cat:warmup')`, **отсортированные
   по возрастанию `met`** (равный met — в порядке каталога): сначала «лёгкие»
   (вращения/махи ~2.0–2.8 и `wcardio` 3.0), затем активные (`bodysquat` 3.8,
   `highknees`/`buttkicks` 7.0, `jumpingjack` 8.0). Порядок механический и
   переживает правки каталога — ничего не хардкодим, кроме правила сортировки.

В список НЕ входят: категория фильтра `warmup` и коллекция `warmcool` (не
упражнения — отсеиваются правилом «есть `met`», §2.4 старой редкиции заменено
этим пунктом).

### 2.4. Что попадает в тренировку

| Значение селектора | Вставляемое упражнение | Свойства |
|---|---|---|
| «Разминка» (дефолт) | `{ name: 'Разминка', sets: [], st: nowLocalISO(), en: '' }` | без каталогной карточки (описания/техники нет — это ок); `isWarmupName` = true через regex-фоллбек |
| Каталогное (`id`) | `{ name: c.n, sets: [], st, en: '' }` | полноценное каталогное: карточка, техника, фото |

Подходы у разминки не запрещены (обычное упражнение списка), но типично
остаются пустыми: пустое упражнение не влияет на объём, ккал
(`calcWorkoutKcal` учитывает только упражнения с подходами) и сводку
«подходов»; из превью истории скрыто фильтром `isWarmupName` (с подходами — тоже).

### 2.5. Ккал и [UX-T15]: согласование моделей

- Время разминки входит в тренировку **без дополнительной механики**: длительность
  считается из `started → ended` (`durationMin`) — разминка, добавленная при
  старте, лежит внутри этого окна. Это та же модель, что [UX-T15] («время
  разминки — время тренировки»), только без сдвига `started`.
- Ккал: разминочное упражнение без подходов в MET-модели не участвует —
  отдельный расчёт не нужен. Для справочного MET системной записи «Разминка»
  зафиксировать константу **2.5** (средний статических разминочных каталога;
  в [UX-T15] §5.1: вращения 2.5, `wcardio` 3.0) — чтобы глобальный fallback
  `exMet() = 4.0` никогда не применялся к «Разминке», если справочный MET
  где-то понадобится (сегодня `exMet` в web/ не вызывается — проверено
  grep'ом; константа — защита на будущее).

### 2.6. Резолв при старте (fallback, если каталог поменяется)

```
warmupEx == null            → системная запись «Разминка»
warmupEx = <id>             → CATALOG по id; имя = c.n
id не найден (каталог правили) → системная запись «Разминка», БЕЗ ошибки/тоста
```

Резолв — в момент старта (не кэшируем имя): правки каталога подхватываются сразу,
устаревший id безопасно падает в дефолт. Поиск упражнения по имени — как везде
(`findEx`/`findCatalog` сравнивают `name`).

## 3. Карточка «🏋️ Тренировка» в Настройках: место и тексты

### 3.1. Место

`renderSettings()` — **новая карточка «🏋️ Тренировка»** между «⏱ Таймер отдыха»
и «🧑‍🏫 Персональный тренер»: соседство по смыслу (всё про тренировки рядом),
«Персональный тренер» и «О приложении» остаются хвостом списка.

### 3.2. Тексты

| Элемент | Текст |
|---|---|
| Заголовок карточки | `🏋️ Тренировка` |
| Тоггл (`.lbl`) | `Разминка первым упражнением` |
| Тоггл-компонент | `swToggleHtml(...)` — как «Звук по окончании» |
| Подпись тоггла (`.meta`) | `При старте новой тренировки первым добавится выбранное упражнение разминки` |
| Строка селектора (видна ТОЛЬКО при включённом тоггле) | label `Упражнение разминки` · значение `Разминка · по умолчанию` (или имя каталогного упражнения) · шеврон `>` (кнопка `.arow`) |
| Заголовок нижнего листа | `Упражнение разминки` |
| Первый пункт листа | `Разминка` + подпись `по умолчанию` (пока выбран дефолт) |
| aria-label тоггла | `Разминка первым упражнением` |
| aria-label селектора | `Выбор упражнения разминки` |

Тоггл выключен → строки селектора нет (карточка = только тоггл + meta) —
прогрессивное раскрытие, не пугаем выключившего настройку лишней строкой.
Смена значения селектора лист закрывает и сразу перерисовывает значение.

## 4. Поведение

### 4.1. Что трогаем

Только **новые тренировки, созданные с пустым списком**: `startBlank()` — путь
FAB / «Начать тренировку» / «С пустого списка» из модалки старта, включая
новичка без истории (`startWorkout` у него вызывает `startBlank` напрямую).
Вставка — **в момент создания** тренировки, после прохождения
`activeConflictAsk` (конфликт активной [UX-B7] разрешается как раньше, разминка
попадает в итоговую новую тренировку): первым элементом `exercises` (§2.4),
тем же способом, что `startExercise`, но **без** установки `CUR` (текущее
упражнение остаётся непроставленным, пока пользователь не выберет что-то сам).

### 4.2. Что НЕ трогаем и почему

| Путь | Почему без разминки |
|---|---|
| **Шаблоны** (`tplStart`) | У шаблона свой список упражнений — это осознанный план пользователя; автодобавка ломала бы предсказуемость и план-подсказки |
| **«Повторить прошлую»** (`newRepeatLast/From`) | Повтор = снимок прошлой тренировки; если в прошлой была разминка — она и так повторится |
| **Ретро-ввод** (бот, `timeModal`, правки существующих) | Ретро-ввод ломать нельзя (требование владельца); автодобавка в прошлое бессмысленна и опасна для данных |
| **Активная тренировка** | Настройка применяется только при СОЗДАНИИ. Удалил разминку из текущей тренировки — **не возвращаем**: добавление происходит один раз в момент старта, никаких проверок «а есть ли разминка» при рендере/сохранении (иначе удаление станет невозможным). Следующая новая тренировка снова получит разминку — это ожидаемо |
| **Смена значения селектора** | Влияет только на БУДУЩИЕ тренировки; уже созданные не редактируются задним числом |

### 4.3. Совместное использование с [UX-T15] «🤸 Разминка 10 мин»

Механизмы независимы и не пересекаются: [UX-T15] сдвигает `started` на −10 мин
(маркер `wm`), эта фича добавляет упражнение в список (§2.5 — время в обоих
случаях входит в длительность). Оба включены — при старте через «🤸 Разминка
10 мин» пользователь получит и сдвиг времени, и упражнение разминки: осмысленная
комбинация. Ни пересечения по данным (`wm` vs `exercises[0]`), ни отдельных
веток не нужно.

### 4.4. Коллекция «Разминка и заминка» каталога

Коллекция (`warmcool`) и все разминочные упражнения каталога остаются как есть —
ручной путь выбора разминки. Тоггл и селектор не меняют каталог, фильтры,
«★ Любимые»; категории `warmup`/`warmcool` в списке селектора не участвуют (§2.3).

## 5. Хранение настройки: ДВА поля

**`GymData` — два новых поля** (настройка «о пользователе», живёт при смене
устройства — как `restSec`, а не как тема):

```java
/* GymData.java */
public Boolean warmupFirst; /* null/false = выкл (дефолт, прежнее поведение) */
public String warmupEx;     /* null = системная «Разминка» (дефолт); иначе id строки CATALOG */

/* fromJson — по образцу restSec: */
Object wf = m.get("warmupFirst");
if (wf instanceof Boolean) d.warmupFirst = (Boolean) wf;
Object wx = m.get("warmupEx");
if (wx instanceof String && !((String) wx).isEmpty()) d.warmupEx = (String) wx;

/* toJson — ключи пишутся только когда задано: */
if (warmupFirst != null) m.put("warmupFirst", warmupFirst);
if (warmupEx != null) m.put("warmupEx", warmupEx);
```

| Свойство | Значение |
|---|---|
| JSON-ключи | `warmupFirst`, `warmupEx` |
| Чтение | ключа нет → `null` — старые файлы читаются как раньше (`warmupFirst` = выкл, `warmupEx` = дефолт «Разминка») |
| Запись | `null` → ключа нет; однажды переключённый тоггл пишет `true`/`false` явно (иначе «выключил» не пережил бы сохранение); выбор селектора пишется при отличии от «не выбирал» |
| Сервер | `WebServer` merge по образцу `restSec`/`goalRemind`: `if (data.warmupFirst != null) …`, `if (data.warmupEx != null) …` — клиент без ключей не затирает серверные значения |
| Валидация id | при чтении сохраняем строку как есть; устаревший id отфильтрует резолв при старте (§2.6) — без клампов и белых списков в fromJson |
| Бот | поля v1 не читает (бот ничего не добавляет, §4.2); для него прозрачно |

MA-сторона: тоггл ON = `G.warmupFirst === true`; значение селектора =
`G.warmupEx` (null → «Разминка»). Тап тоггла пишет `true`/`false` + `save()`;
выбор в листе пишет id (или `null` при возврате к «Разминке») + `save()` +
закрытие листа.

`GymContractTest` дополнить: (а) legacy-файл без обоих ключей читается, оба поля
`null`; (б) round-trip `warmupFirst=true` + `warmupEx="wcardio"` сохраняет ключи
и значения; (в) `null`/пустая строка → ключей в JSON нет. **Обратная
совместимость формата — полная.**

## 6. Состояния и edge-кейсы

| # | Кейс | Поведение |
|---|---|---|
| E1 | Тоггл выключен (дефолт) | Всё как сейчас — ни одной новой ветки в старте; строки селектора нет |
| E2 | Новичок без истории/шаблонов | `startWorkout` → `startBlank` напрямую — разминка добавляется и ему |
| E3 | Выбранный id исчез из каталога | Тихий резолв в системную «Разминку» (§2.6); селектор продолжает показывать имя? — НЕТ: лист строится из живого каталога + системной записи, устаревший id не подсвечивается; значение в карточке показывается как «Разминка · по умолчанию» после первого резолва |
| E4 | Конфликт активной тренировки [UX-B7] | «Удалить и начать новую» → новая получает разминку; «Продолжить» → ничего не создаётся |
| E5 | Пользователь удалил разминку из новой тренировки | Не возвращается (§4.2) |
| E6 | «Повторить прошлую» / шаблон при включённом тоггле | Без автодобавки (§4.2); разминка есть только если была в источнике |
| E7 | Оффлайн-старт (`save` = 'err') | Разминка уже в локальной тренировке — уедет с первым успешным сейвом |
| E8 | Данные с сервера без ключей + старый бот | Поля прозрачны, ничего не ломается (§5) |
| E9 | «Разминка» без подходов в списке упражнений | Пустое упражнение — обычная строка списка без карточки каталога; на ккал/объём/сводку не влияет (§2.4) |

## 9. Что НЕ делаем и почему

| Отсечено | Почему |
|---|---|
| Фиктивная запись «Разминка» БЕЗ селектора (ред. 1 спеки) | Заменено решением владельца «выбор — пользователю» (§8.1) |
| Дефолт селектора = каталогное упражнение (`wcardio`, вариант «б» §2.2) | Владелец назвал «Разминку»; каталогное упражнение навязывало бы тип разминки |
| Категории/коллекции каталога (`warmup`, `warmcool`) в списке селектора | Это не упражнения (у `warmup` нет `met`, `warmcool` — коллекция): тап по ним не может «добавить упражнение» |
| Автодобавка в шаблоны / «Повторить прошлую» / ретро | §4.2: ломает предсказуемость планов, снимков и ретро-ввода |
| Ре-добавка разминки при рендере/сейве, если её удалили | §4.2: делает удаление невозможным; «один раз при создании» |
