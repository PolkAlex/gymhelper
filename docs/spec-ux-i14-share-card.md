# [UX-I14] Виральный шеринг карточки тренировки

- **Idea**: https://github.com/PolkAlex/gymhelper/issues/252 ([UX-I14], статус In Design)
- **Макет**: `docs/mockups/ux-i14-share-card.html` — кнопка «Поделиться» на карточке
  завершённой тренировки (рекомендуемое место + отклонённый вариант backbar),
  3 дизайн-концепта картинки-шеринга (720×1280 в телефонной рамке), 2 edge-состояния
  (без рекорда; калистеника без весов)
- **Статус**: In Design. Гейт: **код не пишется до одобрения концепта картинки
  владельцем** (правило макет-ревью, 09.11.2026)
- **Затрагивает**: `web/` (рендер канвы + кнопка; модуль — новое ванильное JS-расширение
  `app.js` или отдельный `share.js`, решает coder), `web/style.css` (кнопка),
  `src/gym/Stats.java` + `src/gym/web/WebServer.java` (3 ключа-счётчика, §5)
- **НЕ затрагивает**: `src/gym/BotLogic.java` (бот, клавиатуры и тексты бота не меняются),
  формат `GymData` (ничего нового не сохраняется — картинка живёт только в памяти
  устройства), лендинг, канал @MyHelperGym

## 1. Цель и пользовательская проблема

**Продуктовая проблема** (гэп №2 стратегического анализа, `docs/analysis-strategy-2026-11.md`):
продукт не шерится вообще — Telegram даёт виральную механику почти бесплатно,
а у GymHelper нет ни одного способа «похвастаться тренировкой». Дистрибуция —
главный гэп проекта (6 пользователей); шеринг — самый дешёвый её канал.
У Hevy эту роль играет соц-лента, у Strong — Workout Sharing; свою роль карточка-шеринг
может сыграть без соц-фич и без сервера.

**Пользовательская проблема**: после сильной тренировки есть чем гордиться —
рекорд 1ПМ, объём, серия дней, — но поделиться нечем. Скриншот приложения выглядит
как таблица админки, а не как достижение. Текстом « пожал 120×8» в чате — сухо
и без контекста.

**Решение**: кнопка «Поделиться» на завершённой тренировке → генерируется красивая
картинка-итог в стиле продукта (Amber Glass) → системный шеринг Telegram → картинка
уезжает в любой чат/канал вместе со ссылкой `t.me/MyHelperGymBot/app` → получатель
тапает и попадает сразу в Mini App (ноль установки). Каждый пользователь = канал
привлечения (K-фактор).

**Тон картинки**: вау-эффект «хочу так же», а не рекламный баннер. Только факты
тренировки, никаких «скачай», «бесплатно», «без регистрации» — подпись бренда
одной строкой в футере. Продукт в текстах — от третьего лица.

## 2. Сценарии использования

### Сценарий 1 — «Побил рекорд» (главный виральный)

1. Пользователь завершает тренировку: жим штанги лёжа 120 кг × 3×8 — бот поздравил
   с рекордом (1ПМ ≈ 152 кг по Эпли), в приложении янтарный тост.
2. История → тап по тренировке → карточка → **«📤 Поделиться»**.
3. ~мгновенно системная шторка шеринга Telegram с готовой PNG → выбор чата
   («смотрите, что надо») → отправка. Подпись не обязательна — ссылка на самой картинке.
4. Получатель тапает `t.me/MyHelperGymBot/app` → Mini App открывается сразу,
   онбординг ~60 секунд → записал первую тренировку.

### Сценарий 2 — «Обычная тренировка + серия»

Без рекорда картинка тоже собирается: герой — объём кг, вместо плашки рекорда —
только строки упражнений; серия «🔥 12 тренировок подряд» добавляет эффект
постоянства («у него система»). Делиться можно любой завершённой тренировкой.

### Сценарий 3 — «Калистеника / кардио» (без весов)

Объём кг = 0 — герой-слот подменяется (повторения или ккал, §3), строки без «кг»,
рекорд объёма повторений показывается без 1ПМ. Макет состояния — в HTML,
секция «Состояния».

### Сценарий 4 — «Старый webview» (fallback)

`navigator.share` недоступен → PNG скачивается в «Загрузки», тост подсказывает
прикрепить картинку в чат вручную. Ссылка остаётся на картинке — механика не ломается.

## 3. Состав карточки: минимум данных

**Правило композиции: один герой + три цифры + список + футер.** Всё, что не работает
на «хочу так же», срезается. Картинка — не копия карточки приложения, а плакат итога.

| # | Блок | Источник (функции `app.js` — те же, что у карточки) | Формат на картинке |
|---|---|---|---|
| 1 | Шапка: дата + бренд | `w.date` | «16 ноября · понедельник», **без года**; «GymHelper» — янтарным |
| 2 | **Герой-слот** (одно крупное число) | `workoutVolume(w)` / `e1rmOf` | силовая с весами: **«5 340 кг»** (объём); при рекорде в этой тренировке — **«152 кг · 1ПМ»** (см. ниже) |
| 3 | Стат-ряд (3 значения, не больше) | `durationMin`, `calcWorkoutKcal`, `setsCount` | «⏱ 1:14» (компактная запись `durationText` «1 ч 14 м») · «🔥 622 ккал» · «🏋 9 подходов» |
| 4 | Плашка рекорда (если есть) | `prChipSetIdx` + `e1rmOf` | «🏆 Новый рекорд · Жим штанги лёжа — 1ПМ ≈ 152 кг» + подстрока «оценка по Эпли» |
| 5 | Упражнения (первые 3) | `w.exercises`, `entryLine` | «Жим штанги лёжа — 120 кг × 3×8» (компактнее `entryLine`); у строки-рекордсмена янтарный 🏆 |
| 6 | Серия (если есть) | `monthStreak()` | «🔥 Серия: 12 тренировок подряд» — только при n ≥ 2 (порог `streakCardHtml`) |
| 7 | Футер | константы | «GymHelper · дневник тренировок в Telegram» + пилюля-ссылка `t.me/MyHelperGymBot/app` |

**Герой-слот — ключевое решение.** Одно число должно считываться с превью в ленте:

- по умолчанию — **объём кг** (самое понятное «вау»-число силовой тренировки);
- если в тренировке есть живой рекорд 1ПМ (в приложении у записи стоит чип 🏆) —
  герой = **1ПМ по Эпли**, а плашка рекорда становится эмоциональным центром
  (концепт C в макете показывает этот режим как самостоятельный постер);
- тренировка без весов (калистеника/кардио): объём = 0 → герой = **сумма повторений**
  («108 повторений»), при заданном профиле в стат-ряде остаются ккал (§8, кейс 1).

**Честность данных**: все числа считаются теми же функциями, что и карточка
в приложении (`workoutVolume`, `calcWorkoutKcal`, `e1rmOf`, `monthStreak`) —
расхождение «приложение vs картинка» технически исключено. Округления — как
в приложении (объём — целые кг, ккал — `Math.round`).

**Не попадают на карточку (осознанно):**

- имя / @username / фото пользователя — ПДн; вопрос владельцу отдельной секцией (§10);
- **кастомное название тренировки** — может содержать личное («Тренировка с Машей»);
  на картинке только дата и упражнения;
- время начала и конца (часы) — паттерн распорядка дня («всегда в 7:00 утра») —
  лишняя информация о человеке; на картинке только длительность;
- вес тела, пол, возраст, дата рождения — ПДн, на картинке не нужны;
- прогресс vs прошлая тренировка, ккал по упражнениям, MET-детали — шум;
- призывы к действию («скачай», «попробуй бесплатно») — тон продукта: факт + ссылка.

**Терминология серии**: в приложении `monthStreak()` считает **тренировки** в череде
подряд идущих дней («Серия: 12 тренировок подряд»). На картинке та же формулировка
продукта — не «12 дней» (число дней ≠ число тренировок в данных).

## 4. Формат картинки

| Параметр | Решение |
|---|---|
| Ориентация | вертикаль |
| **Базовый формат** | **1080×1920 (9:16)** — канва генерируется в этом размере; пост в чат/канал, сторис и полноэкранный просмотр покрываются одним файлом |
| Доп. формат (v2) | 1080×1350 (4:5) — плотнее в превью ленты каналов; та же функция рендера с другим холстом (компоновка flex сжимает воздух, список остаётся 3 строки). Макет отрисован в 720×1280 (9:16) как эталон композиции |
| Тема | **всегда тёмная** (бренд Amber Glass) независимо от темы приложения: тёмная карточка выглядит родной в тёмном интерфейсе Telegram, светлая — как скриншот чужого сайта |
| Формат файла | PNG (`canvas.toBlob('image/png')`), ожидаемо 200–400 КБ — Telegram пережимает без артефактов текста при 1080px |
| Шрифты | системный стек приложения (`-apple-system / Segoe UI / Roboto`) — без webfont-загрузок и без новых зависимостей |
| Безопасная зона | контент в полях ≥ 56px от краёв; футер с ссылкой — всегда физически нижняя полоса (в сжатых превью читается последним) |
| EXIF/гео | отсутствуют по природе canvas-рендера — картинка чище скриншота камеры |

**Почему один формат в v1**: `navigator.share` передаёт один файл; выбор формата —
дополнительный экран и трение. 9:16 покрывает чаты, каналы и сторис; 4:5 —
осмысленная v2, если владелец захочет спец-вариант для постов канала (§10).

## 5. Генерация и сценарий тапов

**Технически**: client-side canvas 2D в Mini App (в духе проекта — `web/` без npm
и фреймворков). Рендер offscreen-canvas по данным `w` из памяти страницы → PNG-blob.
Сервер не участвует: картинка собирается и живёт только на устройстве пользователя.

**Сценарий**:

1. Завершённая тренировка (История → тап по тренировке).
2. Тап **«📤 Поделиться»** → кнопка блокируется, текст «Готовим картинку…»
   (норма < 300 мс на среднем телефоне; рендер синхронный, без сети).
3. `navigator.share({ files: [new File([blob], 'gymhelper-16-11.png', {type:'image/png'})] })`
   — Web Share API Level 2, поддерживается webview Telegram (iOS WKWebView,
   Android Chromium) → **системная шторка Telegram** → выбор чата/канала → отправка.
4. Fallback (API нет): PNG скачивается через `<a download>`, тост:
   **«Картинка сохранена — прикрепите её в чат»**.
5. Подпись поста: Web Share не передаёт текст вместе с файлом (iOS игнорирует `text`
   при наличии `files`) — поэтому **ссылка нанесена на саму картинку**. Пользователь
   свободно добавляет свой текст — живой пост работает лучше рекламы.
6. События-счётчики (воронка виральности; ключи в `Stats.KEYS` + белый список
   `WebServer`, агрегаты без ПДн — как остальные ключи `/stats`):

| Ключ | Событие |
|---|---|
| `shareClick` | тап по «Поделиться» |
| `shareOk` | `navigator.share` resolved (картинка ушла в шторку) |
| `shareDownload` | сработал fallback скачивания |

Метрика виральности на старте: `shareClick / workoutsCompleted` (доля тренировок,
которыми делятся); дальше — переходы по `t.me/MyHelperGymBot/app` из постов
(считается владельцем по TG-статистике бота; реферальный deep-link — отдельная
идея №4 distribution-plan, сюда не входит).

## 6. Ссылка на карточке

- На картинке: **`t.me/MyHelperGymBot/app`** — deep-link сразу в Mini App.
  Аудитория картинки — Telegram-пользователи (картинка рождается и расходится
  внутри TG), промежуточный лендинг режет конверсию.
- **`gym-helper.com` на карточку НЕ ставим**: по схеме дистрибуции
  (`docs/marketing/distribution-plan-2026-11.md`) лендинг — точка входа статей
  (VC/Habr/Pikabu) и SEO; второй домен на картинке дробит воронку.
- Подпись бренда: **«GymHelper · дневник тренировок в Telegram»** — у картинки нет
  контекста чата, одна строка объясняет, что это и почему выглядит так.
- Опция v2 (вопрос владельцу): вариант картинки с `gym-helper.com` для постов
  канала @MyHelperGym, которые репостируют за пределы Telegram.

## 7. Кнопка «Поделиться» в Mini App

**Место (рекомендация)**: тело карточки завершённой тренировки — full-width
`btn sec wide` **«📤 Поделиться»** после списка упражнений, перед свёрнутыми
секциями («🔥 Ккал по упражнениям», «📈 Прогресс»). Паттерн повторяет
«➕ Добавить упражнение» у активной тренировки.

**Почему не backbar**: там уже 3 кнопки (🗑 Удалить / ↻ Повторить / ← Назад) —
четвёртая на 320px давит подписи; backbar — служебная панель действий записи,
а шеринг — акция «гордости», ему место в контенте карточки. Отклонённый вариант
показан в макете рядом с рекомендуемым для сравнения.

**Состояния кнопки**:

| Состояние | Правило |
|---|---|
| видна | `w.finished` **и** `setsTotal > 0` (пустая тренировка — делиться нечем) |
| нажата | текст «Готовим картинку…», повторный тап заблокирован до завершения |
| после fallback | тост «Картинка сохранена — прикрепите её в чат» (см. §5) |
| скрыта | тренировка не завершена или без подходов |

**Экраны, где кнопка есть**: только просмотр завершённой тренировки (из Истории,
из календаря, из ленты Истории — все пути рендерят одну `workoutCard`).
В боте кнопки нет (§9).

**Про «рядом с Экспорт CSV»**: в Mini App кнопки экспорта нет — `/export` живёт
командой бота (README). Если под «рядом с CSV» имелся в виду ряд из двух кнопок
в приложении («📤 Поделиться» + «CSV»), то CSV-кнопка — новая функциональность вне
скоупа тикета; решение — вопрос владельцу (§10, п. 7).

## 8. Edge-кейсы

1. **Тренировка без весов** (калистеника, кардио): `workoutVolume = 0` →
   герой = сумма повторений («108 повторений»); строки без «кг» («Подтягивания —
   4×8»); рекорд по объёму повторений (тип `vol` из `prCheck`) — плашка
   «🏆 Рекорд · Подтягивания — 32 повторения» **без 1ПМ и «Эпли»**. Ккал считаются
   по MET при заданном профиле (в приложении та же логика: объём/мин → 3.5 MET).
2. **Рекордов нет**: плашки нет, герой = объём, у строк нет 🏆. Композиция не
   перестраивается — исчезает один блок.
3. **Длинные названия упражнений** («Подъём гантелей через стороны лёжа на наклонной
   скамье»): перенос на 2 строки с многоточием (canvas wrap по ширине списка);
   значение («12 кг × 3×12») уходит на вторую строку под названием — как `exsub`
   в приложении. Названия «своих» упражнений — те же правила.
4. **6+ упражнений**: показываются **первые 3** (порядок пользователя, как в
   автозаголовке `titleLines` — не «топ по объёму»); под списком строка
   «+ 3 упражнения» приглушённым цветом.
5. **Профиль без веса** (ккал недоступны): стат-ряд из 2 значений (⏱ и 🏋);
   герой не меняется.
6. **Серия < 2**: блок серии не рисуется.
7. **Малые/дробные веса** («30 кг», «12,5 кг»): формат как в `entryLine` —
   с запятой-децималью, без лишних нулей; объём округляется до целых кг.
8. **Очень длинная серия** (100+): рисуется как есть («🔥 Серия: 104 тренировки
   подряд», склонение `trainWord`).
9. **Крошечная тренировка** (1 упражнение, 1 подход): картинка собирается
   (список из 1 строки); кнопка видна, т.к. `setsTotal > 0`.
10. **Нет `navigator.share`** (десктоп-браузер, старый Android): fallback
    скачивания + тост (§5). Ошибку рендера (теоретическую) ловим try/catch →
    тост «Не получилось подготовить картинку», кнопка разблокируется.
11. **Смена данных после рендера**: картинка мгновенная и одноразовая —
    не кешируется, при повторном тапе рендерится заново из актуальных данных.
12. **Приватность артефактов**: blob не пишется на диск в сценарии share;
    в fallback пишется файл в «Загрузки» — имя без даты-времени персонального
    формата (`gymhelper-16-11.png`).

## 9. Что НЕ делаем и почему

| Отсечено | Почему |
|---|---|
| Соц-лента, лайки, комментарии (Hevy-style) | чужая механика и чужой скоуп; приватность продукта — «дневник без соцсети»; карточка-шеринг даёт виральность без сервера и фидов |
| Серверный рендер картинки | зависимость + пользовательские данные на сервере в момент рендера; client-side canvas бесплатно и приватнее (сервер знает только безликий счётчик) |
| Выбор темы/шаблона карточки пользователем | выбор = трение перед шеринга-импульсом; один утверждённый дизайн, вариативность — v3 при доказанном спросе |
| Кнопка шеринга в боте («✅ Записано», «Посмотреть тренировку») | v1 — только Mini App: канва возможна только в webview; в боте картинку придётся рисовать на Java (сложно, отдельно) — вопрос владельцу §10 |
| Реферальные deep-links `?start=ref_<id>` | отдельная идея distribution-plan №4; смешивать в один тикет не стоит |
| Видео/GIF/анимации картинки | canvas-анимация в файл — отдельная сложность, Telegram пережимает с артефактами |
| EN-вариант картинки | RU-фокус стратегии; EN — после доказательства ниши |
| Светлая тема картинки | тёмная — бренд; светлая тема пользователя на картинку не влияет |
| 4:5 в v1 | `navigator.share` передаёт один файл; 9:16 покрывает чаты/каналы/сторис, 4:5 — v2-опция (§4, §10) |

## 10. Вопросы владельцу

1. **Концепт картинки**: A «Amber Glass» / B «Минималистичный» / C «Рекорд-постер»?
   Рекомендация: **A** как база; режим «есть рекорд» внутри A наследует поведение C
   (герой = 1ПМ) — C как отдельный постер не нужен, если принят A.
2. **Имя на карточке**: добавлять ли имя пользователя («Антон · 12 тренировок
   подряд»)? По умолчанию — **нет** (ПДн-минимализм, privacy-first — позиция
   продукта из стратегического анализа). Если да — только opt-in-тумблер в Профиле
   («Показывать имя на картинке шеринга»), по умолчанию выключен.
3. **Формат v1**: подтверждаете 9:16 (1080×1920) как единственный формат?
   4:5 — отложить в v2?
4. **Кнопка**: место в теле карточки (рекомендация) или всё же backbar?
5. **Вариант картинки с `gym-helper.com`** для постов канала @MyHelperGym
   (репосты вне Telegram) — нужен? Или канал постит ту же картинку с t.me?
6. **Шеринг из бота**: дублировать ли механику кнопкой в боте (текстовый пост
   вместо картинки или отложенная Java-канва)? Рекомендация: нет, v1 — Mini App.
7. **Кнопка экспорта CSV в приложении** (ряд «📤 Поделиться | 💾 CSV»): нужна?
   Вне скоупа тикета — отдельное решение/тикет.
8. **Порог видимости кнопки**: текущее правило «завершена и есть хотя бы 1 подход» —
   ок? Альтернатива: только тренировки с ≥ 3 подходами (картинка-плакат с одним
   подходом выглядит слабо и может вредить виральности).

## 11. Критерии приёмки (для coder / tester)

- Кнопка «📤 Поделиться» на завершённой тренировке в теле карточки; у активной и
  у пустой — отсутствует (§7).
- Рендер ≤ 300 мс на среднем телефоне; после тапа — системная шторка Telegram.
- Числа на картинке равны числам карточки приложения (§3, честность: те же функции).
- Чек-лист приватности §3 «не попадают на карточку» — на трёх тестовых датасетах
  (с рекордом / без рекорда / калистеника).
- `shareClick` / `shareOk` / `shareDownload` видны в `/stats` (недельные агрегаты тоже).
- Fallback без `navigator.share`: файл скачивается, тост показан, `shareDownload` +1.
- Edge-кейсы §8 (1, 3, 4, 5) — e2e-сценарии; длинное название не ломает композицию.
- e2e: регресс — карточка без кнопки у `finished: false`.
