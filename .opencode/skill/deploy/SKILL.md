# Деплой на прод (VPS, Docker)

## ГЕЙТ — проверить ДО любого действия

Деплой возможен ТОЛЬКО после явной **безусловной** отмашки владельца на выкатку
(«тест пройден», «ок, выкатывай», «едем»). Владелец сообщает её сам.

**НЕ отмашка** (продолжаем работу без деплоя):
- «поправишь макеты, посмотрю», «внесу правки», «после одобрения» — отложенная
  выкатка: сначала перечисленные шаги и просмотр владельцем, деплой — только после
  его явного «посмотрел / ок / выкатывай» в ответ на результат (инцидент 11.11).
- Сообщение владельца читать ЦЕЛИКОМ: точечный запрет в нём же («не выкатывай до
  аппрува», «сначала макеты») имеет приоритет над общим мандатом «деплой сразу»
  (инцидент 09.11).

Автоматического деплоя в проекте нет и появляться не должно. Нарушение гейта —
критический инцидент.

## Шаги (только после прохождения гейта)

1) Убедиться, что изменения слиты в `main` и Docker job CI завершился успехом
   (публикация образа ghcr.io/polkalex/gymhelper:latest, ~3–4 мин после merge):

   ```powershell
   gh run list --branch main --limit 3
   ```

   Последний ран на main — success. **Ранний pull запрещён**: до завершения Docker
   job `docker compose pull` молча вытянет старый образ («Already exists»).

2) Обновить контейнер на VPS:

   ```powershell
   ssh root@45.91.169.125 "cd /opt/gym; docker compose pull gymbot && docker compose up -d"
   ```

3) Проверки после обновления:

   ```powershell
   ssh root@45.91.169.125 "docker ps"        # gymbot: healthy, свежий Started
   curl https://gym-helper.com/health        # uptimeSec ~ 10
   ```

   Свежая статика: открыть `https://gym-helper.com/app.js?nocache=<рандом>` и найти
   маркер свежей правки (новая строка кода из релиза).

4) Отчёт владельцу: что выкачено, результаты всех проверок, номер релиза/тикеты.

## Запрещено

- `update.ps1` / `update.bat` — устарели и опасны (рестартят остановленный systemd-юнит,
  порт 8080 занят контейнером; оставлены только для экстренного отката по
  docs/docker-migration.md).
- `docker compose pull` до завершения Docker job CI.
- Любые действия на проде без отмашки владельца.
- Читать/печатать `token.txt`, `deploy_key*` (прод-токен живёт только на VPS).
