3 · Онбординг — шаг «Сколько дней в неделю?» между каруселью и туториалом

Флоу: приветствие-карусель → «Начать» → этот шаг → туториал (новые) / приложение (существующие). Модальный слой без нижней навигации (как карусель). Тап по чипу = ответ и переход (один тап, «Дальше» не нужен); «Пока не знаю» = пропуск. Ответ пишется в GymData.cadence (нужно серверу — пороги реактивации и строка дайджеста); «спрошен ли» — localStorage gymCadenceAsk. Показывается всем один раз после релиза.

4 · Чат — незавершённая тренировка висит >1 дня

Триггер: активная тренировка с датой ≤ вчера + юзер не трогал данные ≥24 ч. Одно сообщение на тренировку (notifyLastWid), повторных нет. Обычный пуш (со звуком). Дата — формат истории «24-11». «▶️ Продолжить» — существующий callback wk:resume; «🔕» пишет notifyUnfinished=false и снимает кнопки.

5 · Чат — реактивация 7 / 14 / 21 три сообщения, потом стоп

Молчание = дней с последней ЗАВЕРШЁННОЙ тренировки (нулевой истории — с последнего захода). Текст выбирается по факту: 7–13 дней → «неделя», 14–20 → «две», ≥21 → «последнее» (молчун с релиза получит сразу третье — честно и один раз). «💪 Начать» → menu:start. У последнего сообщения отписки нет: сообщений больше не будет. Юзер с cadence=1 получает серию по 14/21/28 дней (его норма — раз в неделю).

6 · Чат — итоги недели понедельник · тихий пуш

7 · Чат — первая тренировка событие · строка в финише

Реализация — ключевые зацепки (полные детали в спеке)

Потокnotify-ticker: отдельный daemon-ScheduledExecutorService в BotLogic (НЕ общий с таймером отдыха), тик раз в час, notifyTickSafe = try/catch по паттерну restTickSafe. Обход storage.chatIds(), паузы 50 мс.
Времяякорь — UTC+3: System.currentTimeMillis() + GYM_NOTIFY_TZ_MIN (дефолт 180 = UTC+3). Тихие часы 21:00–10:00; окна: утро 10–13 / день 13–17 (null) / вечер 17–21.
ОтправкаsendMessageResult (ошибка не съедает лимит дня, файл не пишется). Чек-ин и дайджест — тихий пуш (новый sendMessageSilentKb); web_app-кнопка — новый TelegramApi.webAppButton(text,url), фолбэк urlButton(appLink).
Данныеcadence, notifyMaster, notifyUnfinished, notifyComeback, notifyDigest, notifyWhen (клиент-авторитетны, merge как restSec) + книга notifyStage, notifyLastWid, firstDone, notifyLog[{d,t}]≤7 (только сервер, из payload не принимаются). Чек-ин целей — существующее goalRemind. Совместимость: null-поля не пишутся — старые файлы байт-в-байт.
МетрикиnotifySent{Unf,Rc,Goal,First}, digestSent, notifyReacted{Unf,Rc,Goal,Digest} (завершённая тренировка ≤24 ч после напоминания), notifyOff, digestOff — агрегаты, без ПДн.

Макет статичный (открывается двойным кликом). Тексты утверждены владельцем 25.11 (машинная вычитка от ИИ-измов пройдена — чисто; финальную вычитку владелец делает перед выкаткой, решения — спека §17). Даты/значения условные.
