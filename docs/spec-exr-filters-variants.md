# [EXR] Фильтры каталога «Техника» — 3 варианта UI на выбор владельца

- **Статус:** дизайн-ревью. Код не тронут (`src/`, `web/`, `tests/` — без изменений).
- **Файлы:**
  - `docs/mockups/exr-filters-variants.html` — новый макет: вводка-исследование конкурентов, варианты A/B/C, сравнительная таблица, рекомендация, 320px-регресс (9 экранов, 390px, Amber Glass).
  - `docs/mockups/exr-filters.html` — существующий 8-экранный референс Варианта A. **Не менялся.**
- **Контекст:** Вариант A уже реализован (PR #212, EXR-T4), лежит на main и **не выкачан на прод**. Владелец: «не знаю, как фильтры сделать лучше, чем сейчас — покажи варианты конкурентов». Задача этого документа — дать владельцу честное сравнение и рекомендацию.

## 1. Цель и пользовательская проблема

**Проблема владельца (продуктовая):** фильтры Техники реализованы в одном конкретном паттерне (чипы + bottom-sheet), и непонятно, оптимален ли он: у конкурентов встречаются как минимум три разных решения, и без сравнения выбор выглядит случайным.

**Проблема пользователя (проверяемая гипотезами):** найти упражнения под текущий контекст — «что делать на спину без штанги», «какое кардио есть в каталоге» — за минимальное число тапов, не теряя контекст и не упираясь в пустой результат.

**Данные:** 243 упражнения, теги `m:<мышца>`, `e:<инвентарь>`, `cat:<категория>` (контракт EXR-T3). Фильтры: «Группы мышц» (8), «Инвентарь» (19 пунктов в 5 подгруппах), одиночные категории «Кардио / Растяжка / Разминка и заминка / Стретчинг». Матчинг: ИЛИ внутри группы, И между группами (`techFiltered`).

## 2. Исследование конкурентов

| Продукт | Паттерн фильтров библиотеки | Источник |
|---|---|---|
| **Strong** | Минимализм («Think less. Lift more.»): поиск — главный инструмент, фильтр по группам мышц простой, без тяжёлых панелей | strong.app (маркетинг: «simplest, most intuitive»), help-центр (категория «Exercises») |
| **Hevy** | Кнопка-воронка → **полный экран фильтров**: секции чекбоксов (мышцы/инвентарь), Apply/Reset; активные фильтры — чипы с × над списком | hevy.com — SPA, контент не отдаётся; паттерн по поведению приложения и публичным обзорам |
| **JEFIT** | База 1400+: фильтры «часть тела / инвентарь / тип тренировки» (8 типов: Strength…Yoga); **на веб-базе — дропдауны**, в мобильном приложении — фильтр-панель | jefit.com, jefit.com/features/exercise-library (получено webfetch) |
| **Gymverse / FitBod** | Планировщики: каталог вторичен, просмотр — плитки «группа мышц/инвентарь», фильтры минимальны | gymverse.app (получено); fitbod.me — 403, по публичным материалам |

Вывод для продукта: паттерн фильтров масштабируют под размер базы. Hevy (1000+) нужен полный экран; Strong держит каталог «негромко»; у нашей базы — 243 упражнения, ближе к Strong.

## 3. Варианты (экраны макета)

Общее для всех: режимы «★ Любимые / Своё / Все / Коллекции» и логика `techFiltered` не меняются — варианты отличаются только UI-слоем выбора фильтров. Список чисел результатов в макетах иллюстративный.

### Вариант A — чип-ряд + sheet-модалки (реализован, референс)

- **Экраны:** A1 (дефолт, два ряда чипов), A2 (sheet «Группы мышц», 2 выбрано; на кнопке «Применить · 27 †» — опциональный гибрид, в коде сейчас просто «Применить»).
- **Сценарий:** категории — 1 тап; группа — 4 тапа (чип → галки → «Применить»); правка — × на мини-чипе.
- **Состояния:** все уже реализованы и покрыты e2e EXR-T4, включая пустой результат («Ничего не найдено» + «Сбросить фильтры»).

### Вариант B — полный экран фильтров (Hevy-стиль, предложение)

- **Экраны:** B1 (в списке один чип «⚙ Фильтры»), B2 (полный экран: аккордеоны «Группы мышц» 8 чекбоксов / «Инвентарь» 5 подгрупп·19 / «Тип» 4 чипа; липкая панель «Показать N упражнений» + «Сбросить»; нижняя навигация скрыта — страница-«пуш»), B3 (результат: янтарный чип «⚙ Фильтры (3)» + строка чипов с ×).
- **Сценарий (группа):** «⚙ Фильтры» → галки → «Показать 9 упражнений» (4 тапа). Категория — 3 тапа.
- **Состояния и edge cases:**
  - N = 0 → кнопка «Показать» гаснет, подпись «Нет подходящих — ослабь фильтры» (превентивно убивает пустой результат);
  - «Сбросить» в шапке экрана и на панели — двойной доступ к сбросу;
  - возврат по «‹» без «Показать» — выбор не применяется (каноничный Apply-паттерн);
  - живой счётчик пересчитывается на каждый тап чекбокса (`techFiltered` — локально, без запросов).

### Вариант C — дропдауны (JEFIT-стиль, предложение)

- **Экраны:** C1 (3 дропдауна «Группа мышц ▾ / Оборудование ▾ / Тип ▾»), C2 (меню чекбоксов над приглушённым списком, «Готово»), C3 (результат: янтарная кнопка с бейджем 2 + «Сбросить»).
- **Сценарий:** группа — 4 тапа; категория — 2 тапа; правка — 2 тапа (переоткрыть, снять галку).
- **Edge cases:** тап мимо меню закрывает с применением; «Оборудование ▾» — меню на 19 пунктов со внутренним скроллом; на 320px ряд из трёх кнопок переносится (паттерн ломается); поповеры поверх скролла — риск клиппинга в Telegram WebView.

## 4. Сравнение (как в макете, таблица)

| | A · чипы+шиты | B · полный экран | C · дропдауны |
|---|---|---|---|
| «Кардио» | **1 тап** | 3 тапа | 2 тапа |
| «Спина+Ягодицы» | 4 тапа | 4 тапа | 4 тапа |
| Правка | × чип, 1 тап | × чип, 1 тап | 2 тапа |
| Список при выборе | виден | скрыт, но счётчик N | виден за меню |
| Верх экрана | до 4 рядов | 1 чип | 1 ряд (320px — перенос) |
| Риск внедрения | нет (реализован) | средний (новый экран + e2e) | высокий (тач/WebView/320px) |

## 5. Рекомендация lead'а

1. **Оставить A как базу** — реализован, протестирован, минимум тапов на частых сценариях; база 243 упражнения не требует полного экрана.
2. **Гибрид B → A (опционально):** живой счётчик «Применить · N упражнений» на кнопках существующих шитов — маленькая надстройка, устраняет главный минус A (пустой результат после 19-пунктового шита «Инвентарь»). Требует точечного обновления e2e EXR-T4.
3. **B** — держать в запасе на случай роста базы/фильтров или фидбека о перегрузе чип-ряда.
4. **C не рекомендовать** — веб-паттерн, слабые тач-цели, у самого JEFIT в мобильном приложении панель, а не меню.

## 6. Что НЕ делаем и почему

- **Боковой сайдбар фильтров** (desktop-паттерн) — на 390px съедает весь экран, в Telegram Mini App чужероден.
- **Дропдаун-дерево в проде** (C) — оставлено только как макет-альтернатива: плохо ложится на тач (см. п.4), у JEFIT это в основном веб-паттерн.
- **Плитки-категории как у Gymverse/FitBod** — конфликтуют с существующими секциями каталога (`CAT_SECTIONS` Мышцы/Инвентарь в пикере) и удваивают навигацию.
- **Сортировка списка** — вне скоупа задачи о фильтрах; отдельная идея.
- **Единый чип «⚙ Фильтры» вместо одиночных категорий без проверки** — ломает самый частый сценарий («Кардио» 1 тап → 3 тапа) ради редкого сценария «собрать 3+ фильтра разом».
- **Изменение `FILTERS`, тегов и матчинга** — не требуется ни в одном варианте; совместимость контракта EXR-T3 сохраняется.
