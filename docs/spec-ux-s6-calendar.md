## 1. Цель и пользовательская проблема

История тренировок — плоский список карточек сверху вниз. Когда тренировок становится
десятки, невозможно ответить на частые вопросы «взглядом»:

- «как часто я тренировался в этом месяце?» — есть ли пропуски, где окна без нагрузок;
- «что было 8-го числа?» — надо скроллить и глазами искать дату в тексте карточки;
- «сколько раз я занимался на неделе?» — список не даёт календарного контекста.

Статистика (`monthStreak`, «в этом месяце N») отвечает числами, но не показывает
**когда именно** были тренировки. Решение — месячная сетка календаря с отметками дней
и переходом в тренировку через панель дня (как в списке).

Календарь — **другой взгляд на те же данные** (`G.workouts`), а не новая сущность:
никакого планирования будущих тренировок, никаких серверных изменений.

Дополнение ред. 5: фидбек владельца по прод-версии — сетка занимает слишком много
высоты на телефоне, а тап по дню с одной тренировкой мгновенно открывает карточку
без обзора. Компактная сетка + панель краткого содержания дают: (а) больше календаря
на одном экране, (б) единый сценарий «сначала обзор дня → потом карточка» для любого
числа тренировок.

## 2. Сценарии использования

1. **«Как я тренировался в этом месяце»**: открыл любую вкладку → тап иконку календаря
   в шапке → у дней точки, окна без тренировок видны сразу; компактная сетка — месяц
   почти целиком на одном экране. Листнул назад, посмотрел прошлый месяц → «Сегодня»
   вернуло в текущий. Закрыл календарь, открыл снова — тот же месяц, на котором
   остановился (память `gymCalMonth`).
2. **«Что было 8 ноября»**: календарь → тап на день с тренировками → под сеткой
   панель дня (строки: время · упражнения/название · 🏋) → тап по строке →
   карточка тренировки (как из списка).
3. **«Дописать сегодняшнюю»**: календарь → у сегодняшнего дня кольцо «идёт» → тап →
   панель дня с пилюлей «⚫ идёт» → тап по панели → карточка активной тренировки
   (тот же `openHistory`, что и из списка).
4. **«Пропустил ли я неделю»**: листнул на прошлый месяц → пустая неделя без точек —
   видно честно; в полностью пустом месяце — только честный текст + «Сегодня».

## 3. Точка входа [S6-update 09.11; «все вкладки» — S6-update4 09.11]

### 3.1 Решение

Вход в календарь — **иконка-кнопка в topbar, на ВСЕХ вкладках** [S6-update4 09.11 —
решение владельца: «Кнопка календаря пусть будет на всех экранах видна, как и
настройки»]. Ранее (ред. 2–4 / 1.28) кнопка была только на Истории — владелец попросил
единообразие с шестерёнкой. Переключатель «Список / Календарь» (сегмент под топбаром,
редакция 1, вариант А) — по-прежнему **отменён владельцем**; шестая вкладка (вариант Б)
отсечена (§11). История остаётся списком без каких-либо изменений разметки и поведения.

### 3.2 Кнопка в topbar: разметка, порядок, видимость

Кнопка — точная копия шестерёнки по геометрии и стилю (класс `.tb-user`: 32×32,
радиус 9px, фон `var(--btn)`, иконка 18px `currentColor` — паттерн [UX-S4]):

```js
/* topbarHtml(), общая ветка — на всех вкладках [S6-update4 09.11] */
const calBtn = !viewWid ?
    '<button class="tb-user" data-act="openCal" title="Календарь" aria-label="Календарь">' + ICONS.calendar + '</button>' : '';
return '<div class="topbar"><span class="tb-title">GymHelper · ' + (names[tab] || 'История') + '</span>' + calBtn +
    '<button class="tb-user" data-act="openSettings" title="Настройки" aria-label="Настройки">' + ICONS.gear + '</button></div>';
```

**Порядок кнопок: календарь СЛЕВА от шестерёнки: `[ 📅 ][ ⚙ ]`** (порядок ред. 4
сохранён на всех вкладках). Обоснование:
- шестерёнка — глобальное действие; её физическая позиция (крайняя справа) — «якорь»
  мышечной памяти. Теперь обе кнопки на всех вкладках, пара `[ 📅 ][ ⚙ ]` стоит
  **всегда в одном месте** — ни одна из кнопок не «прыгает» между экранами;
- владелец явно попросил видимость «как и настройки» — календарь становится таким же
  глобальным входом; аргумент «контекстное действие одной вкладки» (ред. 4) больше
  не применяется;
- на 320px заголовок + две кнопки 32px помещаются в строку (проверка §9, макет,
  экран 12).

**Видимость** (условие в `topbarHtml()`):
- ранний `return` при `settingsOpen` — экран Настроек со своей шапкой «← Назад»,
  обе кнопки скрыты (как сейчас, 1.28);
- ранний `return` при `calOpen` — экран календаря рендерит **свой topbar**:
  «← Назад» + «GymHelper · Календарь» + **шестерёнка Настроек** [S6-update5 10.11 —
  «не вижу Настройки. Добавляй»]; кнопки 📅 при открытом календаре нет — он уже
  открыт;
- при открытой карточке тренировки (`viewWid`) кнопки нет: у карточки свой backbar,
  а уход в календарь из карточки терял бы её контекст;

## 5. Отметки дней (визуальная система) — подтверждено владельцем [S6-update 09.11; не меняется ред. 5]

Все цвета — существующие токены Amber Glass, новых переменных не вводится.
Высоты ячеек — см. §4.3 (компакт); визуальная система ниже не меняется.

| Состояние дня | Класс | Вид |
|---|---|---|
| Обычный день (без тренировок) | `.cal-d` | число обычным цветом, фон прозрачный |
| **День с 1 тренировкой** | `.cal-d` + 1×`.dot` | **точка 5px** `var(--accent)` по центру, под числом (bottom 2px) |
| **День с 2 тренировками** | 2×`.dot` | две точки рядом (gap 3px) |
| **День с 3+ тренировками** | 3×`.dot` | три точки; счётчик не показываем (§11) |
| **Активная (незавершённая) тренировка** | `.dot.hollow` | **полая точка** (кольцо 7px, обводка `var(--accent)` 1.5px) вместо заливки — по ней видно «эта ещё идёт» |
| **Сегодня** | `.cal-d.today` | фон `var(--glow)`, рамка 1px `var(--glow-brd)`, число — `var(--accent)`, 700 |
| **Выбранный день** (открыта панель дня) | `.cal-d.sel` | фон `var(--nested)`, рамка 1px `var(--btn-brd)` |
| День вне месяца | `.cal-blank` | пустая заглушка |

Совместимости отметок (важно):
- «Сегодня» + тренировки → рамка/фон сегодня + обычные точки;
- «Сегодня» + активная тренировка → рамка сегодня + **полая** точка (типичный кейс
  «тренируюсь прямо сейчас» — макет, экран 3);
- выбранный + сегодня → фон `.sel` перекрывает фон `.today` (CSS-порядок: `.today`
  выше `.sel` в селекторах), рамка остаётся — состояние различимо;
- активная может быть не сегодня (забыли завершить вчера): кольцо стоит на дне
  фактической даты тренировки, тап открывает её панель.

Точки — **единый янтарный цвет** без разбивки по типам/мышечным группам (§11).

## 6. Переходы по тапу [S6-update4 09.11 — ПАНЕЛЬ ВСЕГДА ПЕРВАЯ]

| Тап | Результат |
|---|---|
| День с 1 тренировкой | **инлайн-панель дня** (§6.1): день получает `.sel`, под сеткой панель с заголовком дня и ОДНОЙ строкой `.drow` (время \| запятая-список до 4 упражнений [S6-update6b] \| 🏋) — тот же вид, что при 2+. **Карточка напрямую НЕ открывается** [S6-update4; сетка 2×2 отменена — S6-update6] |
| День с 2+ тренировками | **инлайн-панель дня со строками списка** (как в 1.28): день получает `.sel`, сетка не перекрывается. Тоже сначала панель, не карточка |
| Строка панели при 1 тренировке (время \| запятая-список упражнений \| 🏋) | `openHistory(w.id)` — карточка тренировки. `calOpen` сохраняется → выход («← Назад» backbar'а) возвращает **в календарь** — тот же месяц (из `gymCalMonth`) и тот же выбранный день |
| Строка панели при 2+ тренировках | `openHistory(w.id)` |
| Другой день при открытой панели | панель **переключается** на новый день — содержимое заменяется на месте |
| Повторный тап по выбранному дню | сброс панели (`sel = null`) |
| День без тренировок | ничего (ячейка без действия; today без тренировок тоже ничего — старт есть на FAB) |
| `‹` / `›` / «Сегодня» | §7 |

Почему единый сценарий «сначала панель → потом карточка» для любого числа тренировок:
- владелец явно: «Тап на день с ОДНОЙ и более тренировкой НЕ перекидывает сразу
  в карточку, а показывает внизу краткое содержание»;
- случайный тап по соседней ячейке больше не уводит в чужую карточку — цена ошибки
  снижена (закрыть панель дешевле, чем карточку);
- обзор «а что там было» перед переходом полезен и при одной тренировке.

### 6.1 Панель дня — инлайн, не модалка
**Решение: инлайн под сеткой**, внутри той же карточки (не меняется, ред. 2):
- сетка остаётся видимой — контекст «где я в месяце» не пропадает;
- на один лишний слой (backdrop, закрытие) меньше; выбор другого дня мгновенно
  перерисовывает панель на месте;
- паттерн «подсеточный список» уже есть у приложения (раскрывающиеся details).

Панель показывается **ВСЕГДА при выборе дня с 1+ тренировками** [S6-update4 09.11]
(в 1.28 — только при 2+).

**Общие элементы панели:**
- Контейнер `.daypanel` — как в 1.28: фон `var(--nested)`, рамка `var(--nested-brd)`,
  радиус 14px, паддинг `10px 11px 11px`, `margin-top: 10px`, `aria-live="polite"`.
- Заголовок `.dph`: **«Воскресенье, 8 ноября»** слева (DOW_FULL + дата) + справа
  счётчик **«1 тренировка» / «2 тренировки»** (`trainWord(n)`, янтарный). У активной
  тренировки — пилюля `⚫ идёт` (в строке списка или рядом со счётчиком).

**Панель ЕДИНАЯ для любого числа тренировок [S6-update6 10.11 — владелец: сетка
2×2 «НЕ используем»; ОТДЕЛЬНОЙ ВЕТКИ для 1 тренировки НЕТ]:**

- Панель всегда рендерит: заголовок `.dph` («Пятница, 6 ноября» + справа счётчик
  «1 тренировка» / «N тренировок», янтарный — инфо, **не таповый**) + строки
  `.drow` по числу тренировок дня (по возрастанию времени начала): при 1
  тренировке — ровно одна строка, при 2+ — по строке на тренировку. Скрин-эталон
  владельца 10.11 — панель с ОБЫЧНЫМИ строками.
- Строка — обычная `.drow` из 1.28 (структура без изменений): время `.tm`
  (`08:40–09:30`; нет `started` → `—`; идёт → `с 08:40`) | подходы `.st`
  `🏋 N` (сумма `setsCount`); у активной — пилюля `⚫ идёт` (как в `previewCard`).
- **Содержимое и стиль `.nm` [S6-update6b + S6-update6c→6d 10.11]:**
  - **Стиль — единый при любом числе тренировок [S6-update6c→6d]**: **12px,
    weight 400 (БЕЗ жирного — «не жирным вообще, чтобы побольше слов
    поместилось»)**, цвет `var(--text)`; правка существующего стиля 1.28
    (было 13.5px/600), одобрена владельцем (промежуточно 6c задавал 700 —
    отменено 6d). `.tm` (12px/700) и `.st` (11.5px,
    muted) — НЕ меняются. Механика переноса без изменений: обычные строки —
    одна строка с ellipsis, `.drow.multi` при 1 тренировке — clamp-2.
  - **при 1 тренировке** — НЕ название, а **до 4 подходящих упражнений через
    запятую**: «Приседания, Жим ногами, Разгибания, Икры стоя». Фильтр как в
    `previewCard` (`e.sets.length && !isWarmupName(e.name)`), порядок — порядок
    упражнений в тренировке, join(`', '`), `esc()` обязателен. До **2 строк**
    с переносом и ellipsis на конце: модификатор строки `.drow.multi` → для
    `.nm` `white-space: normal; display: -webkit-box; -webkit-line-clamp: 2;
    -webkit-box-orient: vertical; overflow: hidden`. 5+ упражнений → первые 4,
    «и ещё N» НЕ пишем (полный состав в карточке по тапу); 0 подходящих →
    «Без упражнений» (fallback остаётся).
  - **при 2+ тренировках** — БЕЗ ИЗМЕНЕНИЙ: название по правилу `firstLine`
    (первая строка `title`, иначе первые 2 упражнения через « · », иначе
    «Без упражнений»), одна строка с ellipsis.
- Сетка упражнений 2×2 (`.dsum`, ред. 5–6) — **удалена из кода полностью**:
  разметки и CSS-классов (`.dsum`, `.dsum .ex`) быть не должно; правило
  «пустые ячейки»/«колоночная раскладка» отменено вместе с ней. (Малый хелпер
  запятая-списка для `.nm` — НУЖЕН, см. выше и §13 [S6-update6b].)
- Тап по строке → `openHistory(w.id)`; тап по любому месту строки (время,
  название, подходы) открывает карточку. Заголовок `.dph` — инфо, не таповый.
- Высота панели — естественная: ≈40px на строку (строка при 1 тренировке —
  1–2 строки текста, до ≈56px) + шапка; специально НЕ фиксированная (правило
  «не уменьшать высоту» из ред. 5 относилось к сетке и потеряло смысл вместе
  с ней).

**Строки `.drow` — как в 1.28, без изменений (правила выше справедливы для любого
числа тренировок в дне):**

- Строки `.drow` дня (по возрастанию времени начала):
  - время: `08:40–09:30` (12px, 700, tabular, muted, фикс. ширина ~74px); нет `started` → `—`;
    идёт → `с 08:40`;
  - название: первая строка `title`, иначе первые 2 упражнения с сетами через ` · `,
    иначе «Без упражнений»; одна строка с ellipsis;
  - подходы: `🏋 18` (сумма `setsCount` по упражнениям);
  - у активной — пилюля `⚫ идёт` (как в `previewCard`).
- Тап по строке → `openHistory(w.id)`.

**Сброс/замена:** повторный тап по выбранному дню — сброс панели; тап по другому дню —
замена содержимого; смена месяца — `sel` сбрасывается (§10.9). Закрывать панель
крестиком не нужно (паттерн чипов).

## 7. Навигация по месяцам (не меняется ред. 5)

### 7.1 Стрелки и границы [S6-update 09.11; лимиты — S6-update3 09.11, решение владельца]
- `‹` — предыдущий месяц, `›` — следующий (с переходом года: «Декабрь 2025» ↔ «Январь 2026»).
- **Границы листания — фиксированные константы, от данных не зависят**:
  - `minMonth` = **«Январь 2020»** (константа `2020-01`) — замена редакции 1
    («месяц первой тренировки»); на «Январе 2020» стрелка `‹` disabled;
  - `maxMonth` = **«Декабрь 2030»** (константа `2030-12`) [S6-update3 09.11] —
    заменяет редакцию 2 «max(текущий месяц, месяц последней тренировки)»:
    **будущие месяцы теперь ПОКАЗЫВАЕМ** — пользователь может листать вперёд
    (страховка на случай рукотворной будущей даты «⏱ Время» не нужна: такая
    тренировка просто видна точкой в своём будущем месяце); на «Декабре 2030»
    стрелка `›` disabled;
  - стрелка на границе — `.dim`, `disabled`, `aria-disabled="true"`.
- **Пустой будущий месяц** — тот же вид, что у пустого прошлого: сетка с числами
  без точек, текст «В <месяц> тренировок не было.» + пилюля «Сегодня» (месяц не
  текущий). Специального режима «планирования» нет (§11).
- **⚠️ 2028: расширить лимит будущих месяцев (до 2030+)** — напоминание владельца.
  Лимит — одна константа (`MAX_MONTH`), правка — одна строка; lead дублирует
  напоминание в issue #162.

### 7.2 Кнопка «Сегодня»
- Пилюля **«Сегодня»** по центру под сеткой (`margin-top: 10px`): фон `var(--glow)`,
  рамка `var(--glow-brd)`, текст `var(--accent)` 12.5px 700 — стиль `.prevpill`.
- Тап: месяц = текущий (и записывается в `gymCalMonth`), `sel = null`.
- Правило показа [S6-update2 09.11 — решение владельца]: **пилюля видна ТОЛЬКО когда
  просматриваемый месяц ≠ текущий; если месяц и так текущий — кнопки нет** («ты и
  так там», мёртвой кнопки не бывает — макет, экран 3). Правило едино для прошлых
  И будущих месяцев [S6-update3 09.11]: листнул вперёд — «Сегодня» тоже видна.
  С памятью месяца (§7.3) «Сегодня» остаётся всегда доступным путём к данным:
  открыв календарь на запомненном прошлом месяце, пользователь сразу видит пилюлю
  и одним тапом возвращается. (Раньше — открытый вопрос §16.5, снят этим решением.)

### 7.3 Начальный месяц и память месяца [S6-update 09.11 — решение владельца]
Память вида — **ДА**: ключ `localStorage gymCalMonth`, значение `'YYYY-MM'`.

- **Запись**: каждая смена месяца (`calPrev`/`calNext`/`calToday`/вычисление при
  `openCal`) пишет текущий просматриваемый месяц. `try/catch`, паттерн `gymRestSound`;
  недоступный localStorage — работаем без памяти, не падаем.
- **Чтение при `openCal`**: валидный `gymCalMonth` → открываем этот месяц (clamp в
  `[2020-01, 2030-12]` — на случай устаревшего сохранения, например месяц,
  ставший вне лимитов). Невалидное значение (`'99x'`, пусто) → игнор, дефолт ниже.
- **Дефолт** (нет валидного ключа): месяц **последней тренировки** (по дате), clamp
  в пределы; тренировок нет — текущий месяц. Практически это почти всегда текущий
  месяц, а вернувшемуся после перерыва пользователю сразу виден месяц с данными.
- Выбор дня (`sel`) — сессионный, между открытиями не хранится.

## 8. Данные и алгоритмы (клиент, без серверных запросов)

- Источник — **только `G.workouts`** на клиенте; ни `/api/init`, ни `/api/save`
  календарь не вызывает. Данных достаточно: дата (`w.date`), флаг (`w.finished`),
  время (`w.started`) есть у каждой тренировки.
- На каждый рендер строится map: `byDate = { '2026-11-08': [w1, w2] }` — один проход
  по массиву, O(n). Внутри дня сортировка по `started` (или по id при равенстве).
  Количество точек = число элементов (законченные — заливка, активная — кольцо).
- `G.workouts` хронологический (push-порядок), но опираться на порядок не нужно —
  map сам группирует.
- **Тренировки без валидной даты в календарь не попадают** (см. §10.1); список их
  по-прежнему показывает — поведение списка не меняется.
- **Подсказки пустого месяца** [S6-update 09.11; правки S6-update2/S6-update3 09.11]:
  - `prevWorkoutBefore(y, m)` — дата последней тренировки СТРОГО раньше 1-го числа
    просматриваемого месяца (максимум по валидным датам из map) — **реализована**
    (1.28), но рендер подсказки выключен флагом (заготовка, §12/§13);
  - `nextWorkoutAfter(y, m)` — **удалён** [S6-update2 09.11]: ветку «Следующая
    тренировка» не показываем (§12), хелпер не нужен;
  - формат (для заготовки) «26 сентября» — день + месяц в родительном падеже:
    `MONTHS_GEN` (`['января',…,'декабря']`); **год не добавляется никогда** —
    даже если дата не в году просматриваемого месяца [S6-update2 09.11 — решение
    владельца, двусмысленность принята сознательно];
  - **подсказки СКРЫТЫ** [S6-update3 09.11 — решение владельца, «скрыто, вернёмся
    позже»]: в пустом месяце рендерится только текст пустоты + «Сегодня»;
    включение — флаг `SHOW_MONTH_HINTS = true` в app.js (§13).
- Русские месяцы в предложном падеже для пустого месяца: `MONTHS_PREP`
  (`['январе','феврале','марте','апреле','мае','июне','июле','августе','сентябре',
  'октябре','ноябре','декабре']`) — реализовано (1.28); nominative уже есть
  (`MONTHS_FULL`).
- Склонения «тренировка/тренировки/тренировок» — существующая `trainWord(n)`;
  «подход/…» — `setsWord`.
- Перезагрузка данных (`reloadSilently` → `render`) сама обновляет точки и панель:
  календарь читает `G.workouts` на каждом рендере, кэша нет (§11).

## 10. Edge-кейсы

1. **Тренировка без даты / с битой датой** — валидность проверена: `date` ставится
   при любом создании (`startBlank`, `createFromList` — `todayISO()`), правится
   «⏱ Время» (`saveTime`), сервер хранит как есть. Но формат не гарантирован для
   гипотетически старых/рукотворных данных (`GymData` читает строку как есть):
   `parseDateISO` возвращает `null` → день не отмечается, тренировка не попадает в map
   и не участвует в подсказках пустого месяца (§8); в списке — как раньше
   (`firstLine` уже имеет fallback). Ничего не падает.
2. **Активная тренировка со «вчерашней» датой** (не завершили вовремя) — кольцо на её
   дне в прошлом; тап открывает её панель, из панели — карточка. В списке она
   по-прежнему первая (поведение списка не трогается).
3. **Сегодня + активная** — рамка «сегодня» + полая точка одновременно (§5).
4. **Две тренировки в один день** (завершил и начал ещё) — две точки, панель дня
   с двумя строками; тап по строке ведёт в конкретную карточку.
5. **4+ тренировок в день** — показываем 3 точки (без «×N»): случай редкий, точный
   счётчик в ячейке не окупается; точное число видно в панели дня (§11.4).
6. **Длинные названия** — в ячейках сетки названий нет (только точки); в панели:
   строка `.drow` — одна строка с ellipsis (обрезка на уровне CSS, `esc()` от
   инъекций).
7. **Переход года** — «Декабрь 2025» ← «Январь 2026»: `new Date(y, m±1, 1)` с
   нормализацией месяца. Предел «Январь 2020» тоже через годовую границу
   («Декабрь 2020» → «Январь 2020» → `‹` disabled).
8. **Часовой пояс** — все даты локальные (`todayISO` уже локальный); календарь
   строится на тех же локальных датах, что firstLine и статистика — расхождений нет.
9. **Смена месяца при открытом дне** — `sel` сбрасывается (панель не «переезжает»
   на другой месяц).
10. **Обновление данных извне** (второе устройство, `reloadSilently`) — точки,
    подсказки пустого месяца и содержимое панели пересчитываются на следующем
    рендере автоматически.
11. **Очень длинная история** — map O(n) на рендер; при сотнях тренировок это
    микросекунды. Memoization не вводим (§11.6).
12. **Устаревший `gymCalMonth`** — сохранённый месяц вне `[2020-01, 2030-12]`
    (значение «из другого устройства», правка лимитов и т.п.) → clamp
    на границу при `openCal` (§7.3); битая строка → дефолт. Не падаем.
13. **Пустой месяц у нижней границы** (смотрим «Январь 2020», а первая тренировка
    была позже) — только «В январе тренировок не было.», без строк-подсказок
    (ранних нет, «Следующую» не показываем — [S6-update2 09.11]); пилюля «Сегодня»
    видна (месяц не текущий) — единственный быстрый путь к данным (§7.2, §12).
14. **Подсказка через год** — смотрим «Январь 2026», предыдущая тренировка
    «26 сентября 2024»: год всё равно НЕ добавляем — «Предыдущая тренировка —
    26 сентября» [S6-update2 09.11 — решение владельца; двусмысленность принята
    сознательно, вопрос §16.3a снят]. (Сама подсказка пока скрыта — §12.)
15. **Будущий месяц** [S6-update3 09.11] — смотрим месяц позже текущего: точек
    нет, текст «В <месяц> тренировок не было.», пилюля «Сегодня» видна (месяц
    не текущий); `›` активна до «Декабря 2030» включительно. Тренировка с
    рукотворной будущей датой («⏱ Время») видна точкой в своём будущем месяце —
    прежняя страховка «max(текущий, последняя тренировка)» не нужна.
16. **Тренировка без упражнений с сетами** — в панели строка `.drow` с
    «Без упражнений» (fallback запятая-списка при 1 тренировке и `firstLine`
    при 2+; сетка 2×2 из ред. 5–6 отменена [S6-update6]); тап по строке
    открывает карточку (там виден полный состав).
17. **5+ упражнений у тренировки в панели** — при 1 тренировке в строке первые 4
    через запятую, «и ещё N» НЕ пишем [S6-update6b]; полный состав — в карточке
    по тапу.
18. **Календарь открыт не с Истории** [S6-update4 09.11] — «← Назад» возвращает на
    вкладку-источник (`calFromTab`, §3.4); уход в карточку из календаря ставит
    `tab='history'` (существующее `openHistory`), но «Назад» календаря всё равно
    вернёт на источник. Тап по табу нижней навигации закрывает календарь без
    восстановления источника — пользователь выбрал вкладку сам.
19. **Выбранный день, тренировка удалена извне** (`reloadSilently`) — на следующем
    рендере панель дня с пустым списком не рендерится (`list.length === 0`),
    ячейка остаётся с `.sel` до следующего тапа/сброса; не падаем.
