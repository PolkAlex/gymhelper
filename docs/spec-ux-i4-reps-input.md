# [UX-I4] Ввод повторений: изучение вариантов и рекомендация

- **Idea**: [UX-I4] «Изучить другие варианты ввода повторений» (issue #26)
- **Связанные**: [UX-I2] (#12, полноэкранный режим — на ввод не влияет, в работе не используется);
  [UX-I1] → реализовано как [UX-T12] (автоподстановка веса прошлого подхода) + [UX-E5] (пилюля плана);
  [UX-T26] (плюс-кнопки инкрементов с жёлтым контуром — свежая правка рядов)
- **Статус**: проект решения для владельца (idea в Backlog, код не пишется до отмашки)
- **Формат данных НЕ меняется**: `sets[].reps` остаётся строкой («12», «8-10», «5+1», «до отказа»).

---

## 1. Цель и пользовательская проблема

Модалка записи («Новая запись» / «Изменить запись») — самый частый экран в приложении:
она открывается на каждый подход. Поле «Повторения» сейчас требует либо набор текста
на телефоне (медленно, с открытием клавиатуры), либо тап по чипам, покрывающим только
1–8, 10, 12.

Проблемы:
1. Значения **9, 11, 13, 14, 15** чипами не покрываются — открытие клавиатуры ради «15».
2. **Диапазоны** («8-10») и текстовые записи («до отказа», «макс») вводятся только с клавиатуры.
3. Нет способа **повторить прошлый подход целиком** (вес+подходы+повторения одним тапом) —
   вес подставляется молча [UX-T12], а подходы/повторения сбрасываются в «1»/«1».
4. Скрытая ловушка: инкременты «+1/+2/+5/+10» **затирают диапазон** — «8-10» + тап «+2»
   даёт «12» (вся строка заменяется числом), пользователь может не заметить потерю «-10».

## 2. Текущее состояние (as is, web/app.js)

Модалка `openEntryModalIdx` (~строки 2302–2391), секция повторений:

| Элемент | Поведение |
|---|---|
| Поле `mReps` (text) | value = `s.r \|\| '1'`, свободный текст; при фокусе выделяется целиком |
| «Очистить» (`rClr`) | ставит «1» |
| Ряд 1: `repsSet` [1 2 3 4 5 6 7 8] | тап **заменяет** значение целиком |
| Ряд 2: `repsSet` [10 12] + `repsAdd` [+1 +2 +5 +10] | пресеты заменяют; инкремент берёт последнее число строки и **заменяет всю строку** результатом (`repsAdd`, ~2425) |
| Валидация `saveEntry` | только «не пусто и ≤ 15 символов» — «до отказа»/«5+1» проходят |
| Пилюля плана [UX-E5] | «📋 План: 50 кг × 3 × 12 — подставить» — только пока у упражнения нет записей; `planTake` подставляет w/s/r |

Смежные решения, которые нельзя молча реверсировать:
- **[UX-T12/T17-пометка в коде]**: при «Новой записи» вес прошлого подхода этой тренировки
  подставляется **автоматически**, повторения и подходы — **осознанно НЕ подставляются** (дефолт «1»/«1»).
- **[UX-T26]**: состав рядов только что настраивался владельцем (инкремент веса 0,25; жёлтый
  контур плюс-кнопок) — состав инкрементов повторений владелец явно одобрил, не выбрасывать без спроса.

Формат строки уже легаси-совместим и покрыт статами: Java `Records.repsAvg` понимает
«12» → 12, «8-10» → 9, «5+1» → 6, «макс» → 10 (нечисловой текст). `entryLine` →
«50 кг, 3 подхода по 12 повторений» / «3 подхода по до отказа».

## 3. Сценарии использования

### Сценарий А — «тот же вес, те же повторения» (самый частый: 2-й…N-й подход)
1. Пользователь закончил подход (60 кг × 12), тапает «+» у упражнения → модалка «Новая запись».
2. Вес 60 уже подставлен [UX-T12]; подходы «1», повторения «1».
3. **Сейчас**: тап «12» на чипе, тап «➕ Добавить». Приемлемо, но подходы остаются «1» —
   если в плане 3 подхода, пользователь каждый раз правит и «подходы», и «повторения».
4. **С рекомендацией**: тап по пилюле «🔁 Прошлый подход: 60 кг × 3 × 12» → все три поля
   заполнены одним тапом → «➕ Добавить». Клавиатура не открывается вообще.

### Сценарий B — «первый подход по плану из шаблона»
1. Упражнение добавлено из шаблона с планом (pw/ps/pr), записей ещё нет.
2. Модалка показывает пилюлю «📋 План: 50 кг × 3 × 12 — подставить» [UX-E5] — без изменений.
3. После первой записи пилюля плана сменяется пилюлей «🔁 Прошлый подход» (см. рекомендацию).

### Сценарий C — «нестандарт: 8-10»
1. Тап «8» → поле «8».
2. Набрать «-10» с клавиатуры (3 символа) → «8-10». Или, если прошлый подход тоже был
   «8-10», — тап по пилюле «🔁 Прошлый подход», значение копируется как есть.
3. Сохранение проходит (валидация разрешает), в карточке — «60 кг, 3 подхода по 8-10 повторений».

### Сценарий D — «до отказа»
1. Очистить поле («Очистить» ставит «1»), набрать «до отказа» с клавиатуры.
2. Сохранение: валидация пропускает; в карточке — «3 подхода по до отказа» (текущая
   формулировка `repsPhrase`, косметику не трогаем в этом тикете — см. §8).

## 4. Варианты и оценки

Критерии: скорость (тапы/открытия клавиатуры), ошибки ввода, совместимость со
строковым `reps` и свободным текстом, размер диффа.

### (А) Степперы −/+ вокруг значения
| Критерий | Оценка |
|---|---|
| Скорость | Низкая-средняя: с дефолта «1» до «12» — 11 тапов «+» (или long-press repeat — новый компонент с таймерами) |
| Ошибки | Минимальные (мусор невозможен), но легко промотать мимо нужного |
| Совместимость | **Ломается о строку**: «8-10»/«до отказа» не имеют числового значения — степпер надо дизейблить или прятать; частичные состояния = ветвления |
| Дифф | Средний: новый компонент + состояния + правила для нечисловых значений |
| Вердикт | **Отсекаем.** Дублирует то, что уже делают чипы-пресеты (тап заменяет) и чипы-инкременты, при этом хуже на типичных значениях и конфликтует со свободным текстом |

### (Б) Пресеты «как в прошлый раз» (автоподстановка повторений прошлого подхода)
| Критерий | Оценка |
|---|---|
| Скорость | Максимальная: 0 тапов (если автоподстановка) или 1 тап (если явная) |
| Ошибки | Нет; строка копируется как есть, «8-10» остаётся «8-10» |
| Совместимость | Идеальная: строка в строку, формат данных не трогается |
| Дифф | Минимальный при явном тапе |
| Риски | **Конфликт с решением [UX-T12/T17]** «повторения НЕ подставляются автоматически» — молчаливая автоподстановка также опасна «самоходом» данных (пользователь сохраняет не глядя) |
| Вердикт | **Берём в смягчённой форме**: не автоподстановка, а явная пилюля «🔁 Прошлый подход» одним тапом подставляет вес+подходы+повторения. Решение [UX-T12/T17] не реверсируется (по умолчанию поля не меняются), но частый кейс ускоряется до 1 тапа. Бонус: закрывает edge-кейс «копирование подхода целиком», которого сейчас нет |

### (В) Тап-по-числу: крупные цифры 1–15 в два ряда
| Критерий | Оценка |
|---|---|
| Скорость | 1 тап для 1–15 — покрывает ~95% реальных значений |
| Ошибки | Нет — значение всегда валидно |
| Совместимость | Полная: пресеты заменяют строку целиком, как текущие `repsSet` |
| Дифф | Минимальный: та же механика, новая кнопка «15» |
| Риски | Полная сетка 1–15 (2×8) не оставляет места инкрементам +1/+2/+5/+10, которые владелец только что настраивал [UX-T26] — выбрасывать без спроса нельзя |
| Вердикт | **Берём частично**: добавляем недостающее «15» в существующий ряд пресетов (6→7 кнопок, влезает), сетку 9/11/13/14 не раздуваем — они редки, а «🔁 Прошлый подход» из (Б) чаще закрывает повтор значения |

### (Г) Голосовой/пульс-ввод
**Отсекаем сразу**: ванильный JS без внешних зависимостей; Web Speech API ненадёжен в
Telegram webview (WebKit/Android поведение расходится), распознавание русских числительных
требует моделей. Несовместимо с конвенциями проекта.

## 5. Рекомендация (минимальный дифф, максимальная скорость)

Три точечных изменения в секции повторений модалки записи. Формат данных, валидация,
`entryLine`, статс-расчёты — без изменений.

### 5.1 Пилюля «🔁 Прошлый подход» (главное ускорение)
Расширяем существующий механизм `entryPillHtml` (пилюля уже есть, паттерн `prevpill` в CSS готов):
- **Условия показа**: только для «Новой записи» (`isNew`), у упражнения ЕСТЬ записи в текущей
  тренировке, прошлый подход существует. Взаимоисключаемо с пилюлей плана
  (план виден только пока `sets.length === 0`): пока записей нет — «📋 План», как появилась
  первая запись — «🔁 Прошлый подход».
- **Текст**: `🔁 Прошлый подход: 60 кг × 3 × 12 — подставить`; без веса: `🔁 Прошлый подход: 3 × 12 — подставить`;
  нечисловые повторения копируются как есть: `🔁 Прошлый подход: 60 кг × 3 × 8-10 — подставить`.
- **Тап**: подставить все три поля ровно значениями прошлого подхода (вес — включая пустой,
  подходы, повторения — строкой). Идемпотентно к [UX-T12]: вес и так уже подставлен,
  пилюля дозаполняет подходы и повторения.
- **«Изменить запись»**: пилюля не показывается (как и пилюля плана).

### 5.2 Чип «15» в ряд пресетов повторений
Ряд 2 секции повторений: `[10] [12] [15] [+1] [+2] [+5] [+10]` — 7 кнопок (сейчас 6).
Механика `repsSet` без изменений (тап заменяет значение). Ряд 1 [1–8] — без изменений.

### 5.3 Инкременты — не трогаем (но фиксируем известное поведение)
`+1/+2/+5/+10` работают как сейчас: от последнего числа строки, результат **заменяет всю
строку**. Поведение «8-10» + «+2» → «12» документировано (§7, edge-кейс E1) и вынесено
вопросом владельцу (§9, Q2) — в базовой рекомендации НЕ меняем, чтобы дифф остался
минимальным и предсказуемым.

### 5.4 Что пользователь получает
| Кейс | Было | Стало |
|---|---|---|
| 2-й подход, тот же вес | вес подставлен, тап «12», правка «подходов» | 1 тап по пилюле — всё подставлено |
| «15 повторений» | клавиатура | 1 тап по чипу |
| «8-10» повторно | клавиатура каждый раз | 1 тап по пилюле (копия прошлой записи) |
| Первый подход по плану | пилюля «📋 План» [UX-E5] | без изменений |

## 6. Тексты UI

| Место | Текст |
|---|---|
| Лейбл поля | `Повторения (например 12, 8-10)` — без изменений |
| Пилюля (с весом) | `🔁 Прошлый подход: {вес} кг × {подходы} × {повторения} — подставить` |
| Пилюля (без веса) | `🔁 Прошлый подход: {подходы} × {повторения} — подставить` |
| Тост ошибки (без изменений) | `Повторения: например 12, 8-10` |
| aria-label пилюли | `Подставить значения прошлого подхода` |

Вес в пилюле — с запятой как десятичным разделителем (`String(pw).replace('.', ',')`),
как в `entryPillHtml`.

## 7. Edge-кейсы

| # | Кейс | Поведение |
|---|---|---|
| E1 | Диапазон «8-10» + тап инкремента | Текущее поведение: строка заменяется числом («8-10» + «+2» → «12»). НЕ чиним в этом тикете (см. §9 Q2); чипы-пресеты и пилюля диапазон сохраняют |
| E2 | «до отказа» / «макс» / «5+1» | Валидация пропускает (≤ 15 символов); чипы-числа заменяют целиком; пилюля копирует строку как есть; `repsAvg` в статах уже понимает |
| E3 | Пустое поле | «Очистить» ставит «1»; пустое при сохранении → тост «Повторения: например 12, 8-10» |
| E4 | Копирование подхода целиком | Сейчас НЕТ (только вес молча [UX-T12]). Закрывается пилюлей «🔁 Прошлый подход» одним тапом |
| E5 | Упражнение без записей | Пилюля «🔁» не рендерится; работает пилюля «📋 План» (если есть план) или ничего |
| E6 | Прошлый подход без веса (свой вес) | Пилюля без «веса»: «🔁 Прошлый подход: 3 × 12 — подставить»; тап ставит поле веса в пустое значение (как было у прошлого подхода) |
| E7 | Удаление последней записи, модалка открыта заново | «Прошлый подход» берётся из `e.sets[e.sets.length - 1]` на момент открытия — если записей 0, пилюли нет |
| E8 | «Изменить запись» | Пилюли «🔁» нет (только «Новая запись»), поля как сейчас |
| E9 | Длинная строка прошлой записи («до отказа», 9 симв.) | Влезает в пилюлю (12.5px, одна строка, как пилюля плана); ограничений по длине прошлой строки не добавляем — валидация ≤ 15 симв. уже гарантирует компактность |

## 8. Что НЕ делаем и почему

| Не делаем | Почему |
|---|---|
| Степперы −/+ (вариант А) | Дублируют чипы; ломаются о нечисловые строки; медленнее на типичных значениях; лишний дифф |
| Молчаливая автоподстановка повторений | Реверс осознанного решения [UX-T12/T17]; риск «самохода» данных (сохранить не глядя) |
| Сетка 1–15 двумя полными рядами | Выдавила бы инкременты +1/+2/+5/+10 [UX-T26]; 9/11/13/14 редки, «🔁 Прошлый подход» закрывает повтор значения быстрее |
| Голосовой/пульс-ввод | Ванильный JS, Web Speech API ненадёжен в webview Telegram |
| Отдельные чипы-диапазоны («8-10» как пресет) | Нишевый кейс; угадывание нужных диапазонов владельца; клавиатура + копирование пилюлей уже приемлемы. Вернуться, если владелец скажет, что диапазоны частые (§9 Q3) |
| Чинить затирание диапазона инкрементами (E1) | Изменение поведения свеженастроенных [UX-T26] чипов — только по явному решению владельца |
| Косметика фразы «по до отказа» в `entryLine` | Отдельная микро-работа по текстам, к вводу отношения не имеет; в этом тикете дифф держим минимальным |
| Валидация/ограничения формата reps | Строка «12», «8-10», «5+1», «макс» — легаси-формат, `repsAvg` уже его ест; любое ужесточение ломает совместимость |

## 9. Вопросы владельцу

- **Q1. Пилюля «🔁 Прошлый подход»** — подставлять одним тапом ВСЕ три поля (вес+подходы+повторения)? Или только повторения (вес и так подставлен [UX-T12])? Рекомендация: все три — закрывает «копирование подхода целиком».
- **Q2. Инкременты и диапазоны**: оставить «8-10» + «+2» → «12» (как сейчас, затирание) или починить до «8-12» (правка последнего числа на месте)? Рекомендация: оставить как есть в этом тикете, починить отдельным micro-task, если владелец считает ловушкой.
- **Q3. Нужен ли чип «15»** (ряд станет 7 кнопок) или вместо него пресет конкретного диапазона, например «8-10»? Рекомендация: «15» — универсальнее.
- **Q4. Issue #26** упоминает «счётчик подходов» как альтернативу — понимается как «повторение значений прошлого подхода» (закрыто пилюлей) или как отдельный UI-счётчик подходов на экране тренировки? Если второе — это отдельная идея, сюда не входит.

   «60 кг, 3 подхода по 12 повторений».
3. **Пилюля копирует диапазон и пустой вес**: подход с `w=''`, `r='8-10'` → пилюля
   «🔁 Прошлый подход: 3 × 8-10 — подставить»; тап → `#mWeight=''`, `#mReps='8-10'`.
4. **Взаимоисключение пилюль**: свежее упражнение из шаблона с планом → пилюля «📋 План…»
   (репёрский тест [UX-E5] не должен сломаться); после первой записи вместо неё — «🔁 Прошлый подход».
5. **«Изменить запись» без пилюль**: открыть существующую запись → пилюль нет.
6. **Регресс**: тап «15» ставит «15»; тап «+2» на «8-10» даёт «12» (зафиксировать текущее
   поведение E1, чтобы изменение не проскочило незаметно).
