## 1. Цель и пользовательская проблема

Каждый, кто приходит в GymHelper из Strong (или присматривается), несёт с собой историю:
годы тренировок с датами, упражнениями, весами и подходами. Сегодня перенести её некуда —
дневник начинается с нуля, и новичок либо заводит записи руками (нереально для 300+
тренировок), либо уходит обратно в Strong. README прямо ставит продукт в opposition к
Strong/Hevy/JEFIT («русский язык нативно»), но путь миграции не открыт.

**Решение в одном абзаце:** одноразовый импорт CSV-выгрузки Strong **целиком на клиенте**
Mini App: пользователь выбирает файл (нативный file picker), файл парсится локально в JS
(без библиотек), пользователь видит предпросмотр-сводку (сколько тренировок/подходов,
диапазон дат, что распозналось, где совпадения с дневником), подтверждает — и тренировки
дописываются в обычный `GymData.workouts` через существующий `save()`. Сервер и бот не
меняются вообще: импорт не создаёт новых ключей в `data/*.json` — только новые объекты
тренировок привычной схемы. Незнакомые каталогу упражнения становятся «Своими» существующей
механикой. Тон — на «Вы» (конвенция ONB, решение 14 онбординга).

## 2. Ключевые решения

### В.1 — Точка входа

| Место | Решение | Обоснование |
|---|---|---|
| **⚙️ Настройки** — карточка «📦 Переезд из Strong» | **ДА — основная** (Э1) | Импорт — разовое служебное действие уровня «Оформление/Таймер». Настройки уже содержат «ℹ️ О приложении», «Таймер» — карточка рядом не шумит и находится предсказуемо (туториал шаг 3 уже учит: ⚙️ = настройки) |
| **Пустая История** («Пока пусто 💪») — плашка-приглашение | ДА — вторичная (Э9) | Момент, когда импорт нужнее всего: дневник пуст, пользователь смотрит «и что теперь». Плашка видна только пока история пуста — после импорта исчезает естественно, флаг не нужен |
| Онбординг (шаг «переезд с приложения») | **НЕТ** | (а) онбординг ред. 5 уже одобрен владельцем — новый шаг = новый круг макет-ревью; (б) аудитория импорта — люди **с историей**, т.е. чаще уже существующие пользователи, онбординг они видели; (в) принцип онбординга «всё скипаемое, ничего обязательного» — импорт туда не вписывается. Вместо шага — дешёвая строка в FAQ «Как переехать из Strong?» (кандидат, не в этом скоупе) |
| Профиль | НЕТ | Профиль — метрики тела и «Любимые»; импорт туда не смотрится |
| Бот (кнопка/файл в чат) | НЕТ v1 | CSV в чат не прикрепить в Mini App-сценарии; бот не трогаем (§7) |

### В.2 — Где парсим: только клиент

Парсинг CSV — **в Mini App, на устройстве пользователя** (vanilla JS, без библиотек).
Потом — обычная запись: `G.workouts.push(...)` → один `save()` (очередь `__saveChain`,
`doSave` → POST `/api/save` с `rev`). Следствия:

- **Сервер не меняется**: нет нового эндпоинта, нет приёма файлов, нет парсера на Java.
- **Бот не меняется**: импортированные тренировки — обычные объекты `Workout`, бот видит
  их в истории как свои.
- **Приватность как у продукта**: файл никуда не загружается (продуктовое ДНК «данные на
  своём сервере, без трекеров» усиливается строкой на экране выбора файла).
- `GymContractTest` не расширяется новыми ключами: файл с импортированными тренировками
  структурно не отличается от файла после ручного ввода.

Риск объёма: выгрузка за много лет — единицы МБ CSV; JSON тренировок сопоставим. Обычный
`/api/save` уже принимает весь `GymData` целиком, но кодер обязан проверить реальным
файлом владельца (§9, п.4). Файл >15 МБ — отказ с понятным текстом (§6.4).

### В.3 — Маппинг Strong CSV → GymData

Формат выгрузки Strong: CSV с **заголовками**, одна строка = **один подход**. Типовой набор
колонок: `Date`, `Workout Name`, `Duration`, `Exercise Name`, `SET ORDER`, `Weight`,
`Reps`, `Distance`, `Time`, `Notes`, `RPE` (в новых версиях — также `Workout Notes`,
`Exercise Notes`; точный состав зависит от версии приложения — **сверить на реальной
выгрузке владельца при реализации**). Парсер сопоставляет колонки **по именам заголовков**
(не по позициям), кавычки и запятые внутри значений — по правилам CSV, BOM — игнор.

| Strong | GymData | Правило |
|---|---|---|
| `Date` (`2024-11-18 07:00`, допускаем секунды/слэши — толерантный разбор) | `w.date` = `YYYY-MM-DD`; `w.started` = локальный ISO datetime | Время отсутствует → `00:00` (не влияет на дату; часть дня в UI — «ночь», приемлемо) |
| `Duration` (`1h 6m 25s` / минуты) | `w.ended` = started + duration | Пусто → `ended` не пишется (как у тренировок без времени конца) |
| `Workout Name` | `w.title` | Переносим как есть; пустое → пустое (карточка покажет авто-название GymHelper). Вопрос владельцу — §11.7 |
| `Exercise Name` | `e.name` | Как есть, без переводов (§В.4); trim |
| `SET ORDER` | порядок `sets` | Сортировка подходов по нему внутри упражнения |
| `Weight` (число в единицах Strong) | `s.w` | Сегмент «кг/фунты» на шаге выбора (§6.1): кг — как есть; фунты — ×0.4536, округление до 0.5. Пусто → `""` (вес тела) |
| `Reps` | `s.r` | Число; пусто/0 → строка пропускается (счётчик ошибок) |
| `Distance`, `Time`, `RPE`, `Notes`, `Workout Notes` | — | **v1 не переносим** (§10); кардио-подходы (есть `Distance`/`Time`, нет `Reps`) пропускаются с причиной в результате |

**Мерж подряд одинаковых подходов:** соседние записи упражнения с тем же весом и
повторами (`60×8, 60×8, 60×8`) схлопываются в один `SetEntry` `w=60, s=3, r=8` —
карточка выглядит «как будто вводил руками» («60 кг · 3×8»), история не разбухает.
Рядом стоящие разные (60×8, 62.5×8) остаются отдельными. Рекомендация — §11.6.

`finished: true`, `id` из `G.nextId++`; активная (незавершённая) тренировка пользователя
не трогается — импорт добавляет только завершённые. `nutrition` не пишется.

### В.4 — Упражнения без пары в каталоге → «Свои» (уже работает)

Каталог русский (`findCatalog`, catalog.js:964 — точное/префиксное совпадение), названия
в Strong обычно английские («Bench Press (Barbell)») — **большинство упражнений приедет
«неузнанным»**, и это нормально:

- Существующая механика уже решает «авто-создание своих»: `isCustomEx(name)` =
  `!findCatalog(name)` (app.js:417), а `ownCustomNames()` (app.js:4196) собирает «Свои»
  из всех тренировок — импортированные имена **сразу** видны в пикере (режим «Своё»),
  в Технике с тегом `#своё`, без единой строчки нового кода.
- **Всё работает на «Своих»**: статистика по имени, рекорды и 1ПМ по Эпли (считаются по
  имени на лету), калории (MET дефолт 4.0), карта мышц [FIT-S2] — с плашкой «группы не
  указаны».
- **Чего не делаем**: отдельную пометку источника «из Strong» (в схеме `gymCustomEx`
  нет полей — только имена) и словарь переводов английских названий на русский каталог
  (крупная работа семейства [EXR] — кандидат этапа 2, §11.8).
- В предпросмотре список «не из каталога» показывается честно, с числом тренировок на
  каждое имя (Э5) — чтобы пользователь видел, что приедет.

### В.5 — Дубликаты дат: «оба + предупреждение» (рекомендация)

Совпадение = импортируемая дата уже существует в дневнике (типично для переходного
периода, когда пользователь уже начал вести GymHelper). Разбор вариантов:

| Вариант | Оценка |
|---|---|
| **Оба + жёлтая плашка в предпросмотре** (список совпавших дат по раскрытию) | **Рекомендую.** Ничего не теряется молча; пользователю показан факт, он решает (отменить импорт / удалить дубль руками в Истории). Простая реализация |
| Мерж (дописать подходы в существующую тренировку дня) | Нет в v1: слияние подходов/упражнений и разрешение конфликтов — самая рискованная логика фичи; ценность низкая (случай редкий) |
| Тихий пропуск совпадающих дат | Нет: молчаливая потеря данных — худший вариант; «пропущено 3 тренировки» в результате пользователь не поймёт |

Импорт **никогда не изменяет и не удаляет** существующие данные — только дописывает.
Полный откат — кнопка «Отменить импорт» на экране результата (§6.3).

## 3. Сценарии использования

**A. Переезд целиком (главный, Э1→Э6)**
1. Пользователь открывает ⚙️ Настройки → «📦 Переезд из Strong».
2. Экран «Переедем за минуту»: короткое описание, мини-инструкция выгрузки (3 шага),
   сегмент единиц (кг/фунты) → «📄 Выбрать файл CSV».
3. Нативный file picker → выбрал `strong-export.csv`.
4. Прогресс «Читаем файл…» (Э3) — пара секунд.
5. Предпросмотр (Э4): «128 тренировок · 4 812 подходов · 12.03.2021—18.11.2026», плашки
   «5 упражнений не из каталога» и «3 даты совпадают» — раскрыл, посмотрел (Э5).
6. «Импортировать 128 тренировок» → прогресс записи → результат (Э6): «✓ Готово».
7. «Открыть историю» — вся жизнь до GymHelper теперь в дневнике; рекорды, калории и
   статистика посчитались сами (расчёты на лету).

**B. Не помнит, как выгрузить CSV** — раскрыл аккордеон «Как выгрузить CSV из Strong»
на шаге выбора: Strong → ⚙️ Настройки → «Export Data» → письмо с файлом на почту →
скачать на телефон.

**C. Выбрал не тот файл** (фото, чужой CSV) — «⚠️ Не похоже на выгрузку Strong» (Э7),
«Выбрать другой файл».

**D. Файл пустой** (экспорт пустого дневника) — «В файле нет тренировок» (Э8).

**E. Перешёл на GymHelper неделю назад, часть дней задвоится** — плашка «3 даты
совпадают с дневником» в предпросмотре; оставил «оба»; в Истории видит обе тренировки
того дня; лишнюю удалил стандартной 🗑 карточки.

**F. Передумал сразу после импорта** — на экране результата «Отменить импорт» —
все добавленные этим импортом тренировки удалены, дневник как до импорта.

**G. Сильная история в фунтах** — Strong у него в lbs: поставил сегмент «фунты» до
выбора файла — веса пересчитались в кг при парсинге.

## 4. Экран Mini App: флоу импорта

Экран — обычный экран Mini App (топбар, нижняя навигация на месте; активный таб —
«Настройки» из Э1, внутри флоу — без активного таба). Состояния шагов: выбор файла →
парсинг → предпросмотр → запись → результат / ошибка. Назад с любого шага — «← Назад»
или свайп-жест Telegram; повторный вход в экран всегда начинает с шага выбора.

### 4.1. Шаг 1 — выбор файла (Э2)

| # | Элемент | Содержание |
|---|---|---|
| 1 | Заголовок | `📦 Переезд из Strong` |
| 2 | Подзаголовок | `Переедем за минуту: тренировки приедут в дневник — с датами, упражнениями, весами и подходами.` |
| 3 | Блок «Единицы» | подпись `Веса в выгрузке Strong` + сегмент `кг | фунты` (дефолт кг); meta: `Посмотреть в Strong: Настройки → Units` |
| 4 | Аккордеон (details) | `Как выгрузить CSV из Strong` — открыт по умолчанию при первом входе: ① В Strong: ⚙️ Настройки → «Export Data». ② На почту из аккаунта Strong придёт письмо с CSV-файлом. ③ Скачайте файл на телефон («Файлы» → «Загрузки») и выберите его здесь |
| 5 | Кнопка prime, wide | `📄 Выбрать файл CSV` — открывает нативный file picker (`<input type="file" accept=".csv">`) |
| 6 | Meta-строки | `Файл разбирается прямо в телефоне — никуда не отправляется.` · `Поддерживается только выгрузка Strong (CSV).` |

### 4.2. Шаг 2 — парсинг (Э3)

Спиннер/прогресс на месте кнопки; отмена — «← Назад». Файл < ~200 КБ обрабатывается
мгновенно (промежуточный кадр не показывается); крупный — чанками с прогресс-полосой
и счётчиками строк. Фазы: `Читаем файл…` → `Разбираем подходы — 2 431 из 4 812` →
`Собираем тренировки — 64 из 128`. Meta: `Даже несколько лет истории — пара секунд.`

### 4.3. Шаг 3 — предпросмотр (Э4 свёрнут / Э5 развёрнут)

| # | Элемент | Содержание |
|---|---|---|
| 1 | Заголовок | `Проверьте перед импортом` |
| 2 | Сводка (glass) | крупно: `128 тренировок`; строки: `🗓 12.03.2021 — 18.11.2026` · `🏋 4 812 подходов` · `📚 52 упражнения` |
| 3 | Details | `5 упражнений не из каталога — станут «Своими»` → список: имя + число тренировок (`Bench Press (Barbell) — 18`) + meta `Вся статистика по ним будет работать` |
| 4 | Details (только если есть совпадения) | `⚠️ 3 даты совпадают с дневником` → список дат + meta `В эти дни останутся обе тренировки — импортированная и Ваша. Лишнюю можно удалить в Истории.` |
| 5 | Кнопка prime | `Импортировать 128 тренировок` |
| 6 | Кнопка sec | `Выбрать другой файл` |
| 7 | Meta | `После импорта его можно отменить одной кнопкой.` |

Файл, распознанный в 0 тренировок (строки есть — структуры нет) → ошибка «В файле нет
тренировок» (Э8-логика). Полного списка всех 128 тренировок в предпросмотре нет (§11.3).

### 4.4. Шаг 4 — запись и результат (Э6)

Запись: тот же прогресс-кадр, текст `Добавляем в дневник — 64 из 128`,
`Не закрывайте приложение.` Один `save()` по возможности; если кодер упрётся в размер
тела — партиями с несколькими `save()` (§9, п.4), прогресс отражает партии.

Результат:

| # | Элемент | Содержание |
|---|---|---|
| 1 | Заголовок | `✓ Готово — 128 тренировок в дневнике!` |
| 2 | Строки итогов | `✓ 4 812 подходов` · `✓ Период 12.03.2021 — 18.11.2026` · `📚 «Своих» упражнений: 5` · `🔥 Рекорды и калории пересчитались сами` |
| 3 | Details (если были пропуски) | `Не перенеслось: 3 строки` → до 10 строк `строка 214 — нет названия упражнения`; дальше — `и ещё N` |
| 4 | Кнопка prime | `Открыть историю` |
| 5 | Кнопка sec | `Отменить импорт` — удаляет все тренировки, добавленные этим импортом (список id в памяти), и возвращает к шагу 1 |
| 6 | Кнопка sec | `Готово` — закрывает флоу |

Хаптик success на результате (`tg.HapticFeedback`), как у рекорд-тостов.

### 4.5. Ошибки формата (Э7, Э8)

| Состояние | Текст |
|---|---|
| **Не Strong / кривой CSV** (нет узнаваемых заголовков) | `⚠️ Не похоже на выгрузку Strong` · `В файле нет колонок Strong — Date, Exercise Name и остальные. Убедитесь, что выбрали CSV из письма Export Data, и попробуйте ещё раз.` |
| **Пустой файл** (только заголовки / 0 байт данных) | `В файле нет тренировок` · `В этом CSV только заголовки — тренировок не нашлось. Возможно, экспорт был пустым.` |
| **Слишком большой** (>15 МБ) | `Файл слишком большой` · `Пока поддерживаем файлы до 15 МБ — обычно это больше 10 лет тренировок.` |
| **Ошибка чтения** (picker отменил/файл не читается) | молча: возврат к шагу 1 (отмена picker — норма, не ошибка) |

Кнопки у всех трёх показанных состояний: `Выбрать другой файл` (prime) + `← Назад`.

### 4.6. Состояния и edge cases

| Кейс | Поведение |
|---|---|
| Несколько тренировок Strong в один день | Переносятся обе (GymHelper поддерживает несколько тренировок дня) |
| Дубли даты с дневником | §В.5: обе остаются, плашка в предпросмотре |
| Имя упражнения пустое | Строка пропускается, причина в результате |
| `Reps` пустой/0, вес есть | Подход пропускается, причина в результате |
| Кардио-строка (Distance/Time без Reps) | Пропускается, причина: `кардио-подход (время/дистанция) не переносится` |
| Вес `0` | `""` (вес тела), как в ручном вводе |
| Активная незавершённая тренировка | Импорт не мешает: дописываются только завершённые |
| Ошибка `save()` (сеть/409) | Штатные тосты `doSave`; результат-экран не показывается, добавленное остаётся в памяти вкладки — повторное подтверждение повторит `save()`; 409 = «Данные были удалены — приложение обновлено» (существующая механика) |
| Парсинг при заблокированной вкладке | Чанковый разбор с yield (setTimeout/rAF) — UI живой |
| Сегмент фунты + вес с запятой-десятичной | Толерантный разбор чисел (`80,5` → 80.5) |
| 320px | Сводка и кнопки — одна колонка, проверка обязательна (конвенция UX-T17) |
| Светлая тема | Все экраны в обеих темах (конвенция проекта) |
| Повторный импорт того же файла | Дневник задвоится: защищать нечем и не нужно — перед повтором пользователь видел «Отменить импорт»; предупреждение не показываем (шум) |
| `localStorage`/навигация | Флагов не требует; «новизна» плашки пустой Истории определяется самой пустотой истории |

## 5. Бот: изменений НЕТ

Импортированные тренировки — обычные `Workout`; бот показывает их в «📜 История»,
«👀 Посмотреть», статистике и экспорте `/export` без единой правки `BotLogic`.
Новых ключей в `data/*.json` нет — паритет формата сохраняется автоматически.

## 6. Хранение и совместимость

- **GymData не расширяется.** Импорт создаёт стандартные `Workout`/`ExerciseEntry`/
  `SetEntry`. Старые файлы читаются как раньше; GymContractTest не меняется.
- **localStorage не расширяется** (в отличие от черновой рекомендации «авто-создание
  своих с пометкой источника» — §В.4): имена импортированных упражнений **не** добавляются
  в базу `gymCustomEx` — они и так считаются «Своими» через `ownCustomNames()`, а после
  удаления импорта база не замусоривается. Вопрос владельцу — §11.8.
- Undo («Отменить импорт») — по списку id в памяти вкладки; переживать перезагрузку
  страницы не требуется (кнопка живёт на экране результата).

## 9. Что НЕ делаем и почему

| Не делаем | Почему |
|---|---|
| Hevy / JEFIT / Fitnotes и прочие форматы | v1 — только Strong (границы тикета [ONB-E1]; парсер и предпросмотр строятся под один формат, остальные — следующие тикеты семейства) |
| Мерж импорта с существующими тренировками дня | Самая рискованная логика фичи (слияние подходов, конфликты правок); рекомендация «оба + плашка» закрывает случай честно (§В.5) |
| Словарь соответствий названий (Bench Press → «Жим штанги лёжа») | Крупная ручная работа с каталогом — семейство [EXR], этап 2 (§11.8); v1 честно работает через «Свои» |
| Перенос заметок Strong (`Notes`, `Workout Notes`), RPE | В GymHelper заметки — отдельная фича в In Design [UX-S17], питание ≠ заметки; RPE в модели нет |
| Кардио-метрики (Distance/Time) | В `SetEntry` нет полей дистанции/времени подхода |
| Серверный парсинг / загрузка файла на сервер | Приватность + ноль изменений API и Java; клиентский разбор достаточно быстр |
| Выбор диапазона дат («импортировать только 2025») | Усложняет предпросмотр; нужно единицам пользователей. Если запрос появится — этап 2 |
| Дедупликация по содержимому подходов (защита от повторного импорта) | Нет надёжного ключа совпадения; защита — «Отменить импорт» и плашка дублей |
| Пометка «из Strong» у «Своих» упражнений | Нет полей в схеме `gymCustomEx`; ценность сомнительна (§В.4, вопрос §11.8) |
| Онбординг-шаг импорта | §В.1: онбординг ред. 5 одобрен; аудитория импорта чаще мимо онбординга |
| Обратная конвертация (экспорт в формат Strong) | Есть свой `/export` CSV |

## 10. Открытые вопросы владельцу (ред. 1)

1. **Точка входа.** Рекомендую: основная — карточка «📦 Переезд из Strong» в ⚙️ Настройках;
   вторичная — плашка в пустой Истории. Онбординг — не трогаем (аргументы §В.1). Ок?
2. **Дубликаты дат.** Рекомендую «оба + жёлтая плашка в предпросмотре» (ничего не теряем
   молча, мерж — не делаем). Ок?
3. **Предпросмотр.** Рекомендую сводку + раскрытия (неизвестные упражнения, совпавшие
   даты) — полный список тренировок не показываем (128 карточек = шум, ценность мала).
   Ок?
4. **После импорта.** Рекомендую: экран результата внутри флоу (сводка + построчные
   пропуски + кнопки «Открыть историю» / «Отменить импорт» / «Готово»); тоста мало —
   информации много. Кнопка «Отменить импорт» нужна? (Рекомендую да — страховка.)
5. **Единицы кг/фунты.** Рекомендую сегмент на шаге выбора (дефолт кг) — у части
   пользователей Strong в фунтах, без конвертации веса приедут ×2.2. Ок?
6. **Мерж подряд одинаковых подходов** (60×8 ×3 → «60 кг · 3×8») — рекомендую да:
   карточки выглядят как ручной ввод, история компактнее. Если хочешь подход-в-строку —
   скажи.
7. **Названия тренировок из Strong** («Full Gym», «A · Pull») — переносим как `title`?
   Рекомендую да (сохраняет структуру программы). Альтернатива — всегда авто-название
   GymHelper.
8. **«Свои» после импорта.** Рекомендую v1 без изменений схемы: имена-неизвестные
   становятся «Своими» существующей механикой; без пометки источника и без добавления
   в базу `gymCustomEx`. Словарь переводов на русский каталог — отдельная идея семейства
   [EXR] на этап 2 (завести)?
